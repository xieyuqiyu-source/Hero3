## 战报快照、特性归属与分享修复

- 增援参战快照固定保存战斗开始时的实际出动兵力，结算援军损耗前深拷贝兵力和累计损失 map，避免战后写入反向污染主战报中的战前快照。
- 增援主战报和协防方独立战报补充逐队武将实际经验；玩家端聚合同一玩家的多批援军时，只累计最终展示武将对应批次的经验。
- 同一玩家对同一驻防目标的多批有效增援最多携带一名武将；已有携将援军时仍允许继续派遣不带武将的援军。
- 标准特性结构区分展示位置 `ownerSide` 与绝对角色 `ownerRole`，并从参战快照补齐触发武将名称；防守视角和协防视角不再把守方特性错误展示到攻击方。
- 玩家情报未揭示敌方武将时，同步移除敌方特性、增援武将经验和增援加成快照，旧版 `TraitTriggered / TraitOutcomes` 与标准详情都执行相同脱敏，仓储原始快照保持不变。
- 军情列表点击后等待完整详情接口返回再渲染，避免摘要数据短暂显示成详情；公开分享 token 直接读取分享接口，不再因登录状态先请求内部战报接口。
- 前端兼容旧黄巾防守战报错误的特性主侧标记，并避免重复显示“特性名称 · 特性名称”。
- 已同步根 README、玩家前端 README 和战报 OpenAPI schema，并补齐后端与前端回归测试。

## 双玩家前端域名与部署规则

- 用户确认生产环境必须同时部署两个玩家前端：React `web` 固定绑定 `https://hero3.ccoos.cn/`，Vue `web-wlsg` 固定绑定 `https://wlsg.ccoos.cn/`，禁止再把 `web-wlsg` 覆盖到 Hero3 Web 的发布目录。
- 两个域名共用同一套 Hero3 后端，`/api/` 与 `/healthz` 都反向代理到 `127.0.0.1:8081`；GM 后台继续保留在 `https://hero3.ccoos.cn/admin/`。
- `wlsg.ccoos.cn` 原静态目录和 `wlsg-save-api.service:18790` 退出生产链路；部署确认两个新站点健康且页面身份正确后，才停用旧服务。
- 旧 `mobilewlsg.ccoos.cn` 不再单独承载旧前端或 API，永久跳转到新的 `wlsg.ccoos.cn`，避免旧服务停用后留下不可用入口。
- 自动部署新增双前端独立构建、独立备份、独立安装和页面标题校验，并由仓库 `deploy/nginx/` 持续维护两个主域名及移动旧域名的 Nginx 配置。
- 数据库任务完成后优先重启 Hero3，再安装辅助服务与 Nginx；Nginx 安装、reload 后健康检查或页面身份校验失败时，会恢复旧静态目录和旧路由并确保 Hero3 重新运行，只有全部校验通过才停用旧 WLSG 服务。
