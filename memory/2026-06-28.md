# 2026-06-28 项目记忆

- 确认 PVP 行军时间不再固定 3 小时，而是以 3 小时作为速度 1 的基准，按出征队伍最慢兵种速度计算：`实际时间 = 3小时 / 最慢兵种速度`。
- PVP 出发、战后返程都按队伍速度计算；战后返程按幸存兵重新计算，慢兵阵亡后返程可变快。
- 召回返程按已经走出的距离返回，不再使用固定 3 小时或剩余到达时间。
- 修复 PVP 玩家目标页卡顿：倒计时拆为独立组件，避免整个目标列表和出征弹窗每秒重渲染。
- 修复 PVP 自动结算异常：防守方无兵时正常判定攻击方胜利并进入返程；历史空出征兵脏行军不再阻塞列表接口，会标记为异常失败并释放武将。
- 驿站 `relay_station` 正式接入核心建筑和建筑数值配置，提供 `marchSpeedBonus` 行军速度加成；默认每级 +1%，20 级 +20%。
- 驿站加成通过统一 Modifier 管线生效，不由 PVP 或增援模块硬编码读取建筑；PVP 出征/返程、增援出征/返程均读取 `marchSpeedBonus`。
- GM 后台建筑数值配置可调整建筑每级 modifier，包括驿站的 `marchSpeedBonus`；配置影响后续新发起的行军，不追溯已在路上的行军。
- 提交前验证通过：`go test ./internal/app/game ./internal/infrastructure/storage ./internal/transport/api`，以及前端 `npm run build` 曾在本轮修复后通过。

## 自动发布流程修正

- 用户确认既有发布模型应为：GitHub Actions 只负责 SSH 触发和监控服务器脚本，服务器自行从 GitHub 拉取 `main-core` 指定提交、构建 Go/Web/Admin、备份、覆盖部署、重启并健康检查。
- 已将 `.github/workflows/deploy.yml` 从“Actions 上传源码包到服务器”修正回“服务器 `/opt/hero3/source` 拉取指定提交构建部署”；保留 `main-core` push 自动触发和手动触发。
- 服务器拉取源码步骤保留部署锁，`git fetch`/`git clone` 超时从 120 秒放宽到 300 秒，以降低 GitHub 网络抖动导致发布失败的概率。
- 自动部署成功后会刷新服务器 `/opt/hero3/RELEASE`，用于后续确认线上实际运行的提交版本。
- 第二次自动发布曾因服务器访问 GitHub 出现 `GnuTLS recv error (-110)` 失败；已将服务器侧 `git fetch`/`git clone` 改为 HTTP/1.1 + 3 次重试，每次仍保留 300 秒超时。
- 已同步更新 `docs/运维部署/服务器部署文档.md`，明确 Actions 不上传源码包、不在 Actions 机器构建产物。

## PVP 行军、武将和信函体验修正

- PVP 出征支持选择是否携带武将；携带武将会占用该武将，出征、返程和战斗加成只读取随军武将，未携带时不吃武将加成。
- 武将出征或增援期间不再作为家中主将展示，也不能被其他模块重复调用；防守只使用真正留在城里的主将。
- PVP 攻击冷却已移除，仍保留保护与每日次数限制。
- 左侧军队菜单新增 PVP 行军提示：出征、增援、被攻击、被侦查；出征行内显示目标玩家和倒计时，并提供召回与闪电加速按钮。
- 召回仅允许出发后前 2 分钟；出征加速最多 2 次，每次按当前剩余时间减半。
- 行军倒计时归零后，前端会自动刷新行军、军队和武将状态，避免玩家必须手动刷新。
- PVP 战报已修正攻防双方武将归属、攻击/防守视角展示和防守方武将经验显示；防守方战报中经验显示到防守方栏位。
- PVP 战斗结算会给随军进攻武将和留城防守主将发放战斗经验；经验按击杀单位维护费计算，并兼容跨阵营兵种查找。
- 新账号初始化补发新手信函奖励方案已落地：创建账号/玩家时通过信函领取金币奖励，避免直接静默到账导致玩家无感。
- 玩家信函新增全服喊话能力：消耗 10 万城金发送全服信函，不走公告系统。
- 军情闪烁与 Tab 展示已补齐，进攻、防守、增援等战报不会遗漏入口。
- 提交发布前本地 Go 命令不可用，后端单测未能在当前机器重跑；前端/后台构建改用 Codex 自带 Node 环境执行。
