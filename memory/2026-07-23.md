# 2026-07-23 项目记忆

## 许褚特性更新

### 决策

- 虎痴冲阵仅在许褚主动进攻战斗前判定，默认 50% 概率使敌方全军步兵、骑兵防御降低 30%；概率和比例可由 GM 配置。
- 虎虎生威是永久被动，使许褚所率虎豹骑每兵固定增加 12 点攻击和 5 点移动；主动进攻、防守和增援持续生效，不进行概率判定，不进入战斗触发时间线。
- 旧破敌防御不再是当前特性。存量旧 ID 只允许在配置载入时迁移为虎虎生威，不得继续注册或执行旧破防逻辑。
- 两项可在主动进攻中同时生效：被动攻击先进入核心输入，虎痴命中后修改敌军防御，再用最终攻防计算真实兵损。

### 实现

- 正式配置、特性目录和配置迁移已切换到虎痴 `50% / -30%` 与虎虎生威虎豹骑 `+12 / +5`；当前 GM 显式配置值保留。
- 通用指定兵种固定攻击、移动 Modifier 同时接入 PVP 战斗、出征行军和增援速度；许褚没有新增专属核心分支。
- `web` 和 `web-wlsg` 同步当前元信息、将领特性列表和战报被动分栏；虎痴只按后端真实结果进入触发时间线。
- 新增许褚真实 PVP、配置迁移、被动属性、NPC、方向、概率和前端战报测试，并清理旧双破防断言。
- 新增 `docs/系统设计/许褚特性更新开发文档.md`，同步项目索引、文档目录、现有特性盘点、平衡设计和短期治理文档。

### 当前验收

- 真实 PVP 固定矩阵：无被动时攻击 `3000`、守军损失 `247`、行军 `2054` 秒；被动生效且虎痴未命中时攻击 `4200`、守军损失 `400`、行军 `1450` 秒；虎痴命中后防御战力 `8000 -> 6000`、守军损失 `602`。
- 虎痴命中战报准确记录步防 `-3`、骑防 `-2`；双方库存、经验、最终死伤和战报已对账。
- 许褚专项 Go `-race -count=3` 通过；`web` 236 项、`web-wlsg` 287 项测试和两个生产构建通过。
- Go 全量首次运行发现一条旧 `-3/-3` 测试文字，已按当前整数结果修正为 `-3/-2` 并定向连续 3 次通过；修正后的 `go test ./... -count=1` 全量通过。
- 本机 Chrome 使用同一许褚存档完成两端验收：`web` 准确显示虎痴 `50% / -30%` 与虎虎生威虎豹骑 `+12 / +5`，`web-wlsg` 正常进入许褚军事页；两端均无控制台警告、错误或横向溢出。
- 许褚改动将与工作区中已验收的夏侯渊、张辽、典韦改动合并为同一版本提交并推送到 `main-core`。

## 郭嘉特性更新

### 决策

- 神鬼之才是全天候永久被动，固定增加郭嘉 10 点内政和 10 点智谋；增加值进入最终四维与对应真实 Modifier，不进行概率判定，也不进入战斗触发时间线。
- 鬼才遗策在郭嘉主动进攻、守城或作为援军参战结束后，按其所属部队本场逐兵种真实阵亡复活 22%；默认必定触发，不限制胜负，复活比例和概率可由 GM 配置。
- 复活逐兵种执行向下取整，没有单场人数上限，但自然不能超过对应兵种本场真实阵亡；复活必须进入返程部队、主城守军、援军记录或轮回权威军队。
- 旧神鬼之才征兵资源减耗、旧鬼才遗策仅战败返兵、返兵上限和胜负条件全部废弃，只允许作为存量配置迁移输入。

### 实现

- 正式配置、特性目录和配置迁移已切换到永久内政/智谋与全方向战后复活；GM 当前有效自定义值保留。
- 永久属性复用通用 `passive_stat`，智谋和内政进入统一最终属性及真实效果；鬼才遗策复用统一战后事件并按真实阵亡逐兵种复活。
- 战报新增并统一展示 `actualLostUnits`、`revivedUnits`、`totalRevived`；参战快照保留两项拥有特性，触发时间线只记录实际发生的鬼才遗策。
- `web` 与 `web-wlsg` 已同步永久被动、战后阶段、真实阵亡、实际复活和最终存活文案，不在前端自行重算。
- Chrome 发现鬼才遗策仍显示无效的通用最大影响比例、最大影响数量；已从该特性的 GM schema 移除，并用专项测试锁定只允许复活比例和触发概率。
- 新增 `docs/系统设计/郭嘉特性更新开发文档.md`，同步项目索引、现有特性盘点、平衡设计和短期治理文档。

### 验收事实

- 永久属性样本：基础智谋 3、内政 4 变为最终智谋 13、内政 14；对应真实征兵/行军加成为 26%，生产/容量加成为 28%，神鬼之才不进入触发时间线。
- PVP 真实战败样本：郭嘉带 100 名魏步兵真实阵亡 100，鬼才遗策复活 22，返程和战报最终存活均为 22；双方主战报的拥有者、阶段和逐兵种结果一致。
- PVP、NPC、黄巾、轮回、扫荡和真实增援均覆盖获胜、战败或平局的适用入口；经验继续按真实阵亡计算，权威兵力与两套战报对账。
- Go 全量测试与郭嘉专项 `-race -count=3` 通过；`web` 236 项测试与生产构建、`web-wlsg` 287 项测试与生产构建均通过。
- Chrome 已确认最新 GM 面板参数准确，旧返兵字段和无效通用上限均不存在，三端页面均无横向溢出。

## 刘备特性更新

### 决策

- 仁德天下是全天候永久被动，固定增加刘备 10 点内政和 12 点统率；系统字段分别为 `politics`、`command`，每点按 2% 转换为对应真实 Modifier。
- 仁德天下不进行概率判定，不进入战斗触发时间线。增加值必须进入最终四维、属性和 Buff。
- 仁主守护适用于主动进攻、主城防守和正式援军，在战斗结束后默认以 60% 概率按所属部队本场真实阵亡逐兵种复活 35%；概率和比例可由 GM 配置。
- 仁主守护不限制胜负、不设人数上限。35% 天然不会超过本场真实阵亡，统一战后结算仍负责累计复活封顶。
- 复活只增加最终存活，不回减真实阵亡和敌方击杀经验；概率未命中时不修改兵力、不生成战报触发项。
- 旧仁德 50% 复活、10000 上限，以及旧仁主守护 10% 返还、10000 上限全部废止，只允许作为存量配置迁移输入。

### 实现

- 正式配置、特性目录和配置迁移已切换到仁德天下 `politicsBonus=10`、`commandBonus=12`，仁主守护 `effectRate=0.35`、`triggerChance=0.6`。
- 删除旧独立 `rende.go` 复活执行器；仁德复用通用永久属性装配，仁主守护复用统一 `AfterBattle` 复活事件，不修改稳定战斗核心。
- GM schema 每项只暴露两个当前有效字段，清除旧返还、复活人数上限和通用最大影响字段，同时保留当前新格式自定义值。
- PVP、NPC、黄巾、轮回和援军测试已改为当前单一复活结果；参战快照保留仁德拥有信息，触发时间线只记录实际命中的仁主守护。
- `web` 与 `web-wlsg` 同步当前名称、阶段、永久内政/统率展示、逐兵种复活和无上限大额损失样本。
- 新增 `docs/系统设计/刘备特性更新开发文档.md`，同步项目索引、现有特性盘点、平衡设计和短期治理文档。

### 验收事实

- 永久属性专项验证基础内政 4、统率 3 变为最终内政 14、统率 15，对应生产/容量 28%、防御 30%，仁德天下不进入触发时间线。
- PVP 100 人真实阵亡固定命中时复活 35，概率 0 时复活 0；多兵种各阵亡 30000 时各复活 10500，总复活 21000，证明不存在旧 10000 人数上限。
- 进攻、防守、正式援军、NPC、黄巾和轮回的真实兵力、经验、复活、最终存活和战报均按当前单一仁主守护结果对账。
- Go 全量与刘备专项 `-race -count=3` 通过；`web` 236 项、`web-wlsg` 287 项测试和两个生产构建通过。
- Chrome 确认 GM 只显示四个当前字段，React 正确展示仁德永久内政/统率与仁主 60%/35%，Vue 可进入刘备存档；三端无控制台告警和横向溢出。
