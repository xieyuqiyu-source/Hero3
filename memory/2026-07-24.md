# 2026-07-24 项目记忆

## 诸葛亮特性更新

### 决策

- 奇门遁甲适用于进攻、防守和增援战斗前，默认使敌方 25% 兵力仅本场无法参战；这些兵不属于真实阵亡，战后完整保留。
- 奇门遁甲正式参数为 `effectRate=0.25`、`triggerChance=1`，比例和概率均可由 GM 配置。
- 卧龙奇谋适用于进攻、防守和增援，在任何战斗触发型特性执行前默认以 60% 概率判定。
- 卧龙奇谋命中后封禁敌方所有参战将领的战斗触发型特性，包括主将和全部真实参战援军将领。
- 卧龙奇谋不封禁永久属性、永久兵种加成、留城效果和已经完成的行军效果。
- 双方都有诸葛亮时，双方卧龙奇谋都不判定、不触发、不封禁；两份结果分别提示“特性已失效，双方均有诸葛亮”。奇门遁甲照常独立执行。

### 实现

- 核心事件管线新增 `battle_trait_control` 阶段，先确定整场触发型特性封禁，再进入原有战前、战斗结算后、战斗结束后和掠夺结算。
- PVP 把封禁状态贯穿主将、援军和全部战斗后续阶段，不修改稳定攻防公式。
- 旧卧龙“战斗结算后拦截 1 项”逻辑及 `disableTraitCount` 参数已废止；黄盖苦肉计继续保留原单项压制机制。
- 奇门旧 `maxAffectedRate`、`maxAffectedCount` 字段已清理。
- GM schema 中奇门只暴露困敌比例和概率，卧龙只暴露概率；旧配置载入时自动迁移到当前字段。
- 战报新增封禁将领数、实际封禁特性数、失效状态和失效原因；`web` 与 `web-wlsg` 同步当前名称和战前阶段。
- 新增 `docs/系统设计/诸葛亮特性更新开发文档.md`，同步项目索引、现有盘点、平衡设计和短期治理文档。

### 当前验收

- 核心和应用层已覆盖 0% 未命中、100% 命中、被动保留、援军诸葛封禁进攻方全部触发特性、GM 旧字段迁移和参数 schema。
- 真实双诸葛 PVP 连续验证双方战力 `750/750`、两项奇门各压制 25 兵、两项卧龙分别显示失效且不封禁奇门。
- `go test ./... -count=1` 全仓通过；诸葛亮相关核心与应用测试使用 `-race -count=3` 通过，关键配置及 PVP 场景另以 `-count=5` 重复通过。
- `web` 236 项、`web-wlsg` 287 项全量测试通过；两个玩家端和 GM 后台生产构建通过。
- Chrome 实机检查确认 GM 中奇门只显示 25% 困敌比例和 100% 默认概率，卧龙只显示 60% 概率，并明确说明封禁所有参战将领的战斗触发型特性且不影响被动。
- Chrome 实机完成 `web` 注册、存档、将领详情及 `web-wlsg` 登录、同存档加载冒烟；双端战报字段和双方诸葛失效文案由各自全量展示测试覆盖。
- `git diff --check` 通过；诸葛亮规则文档、项目索引和当天项目记忆均已同步。
