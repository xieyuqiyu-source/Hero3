# 2026-06-30 项目记忆

## NPC 扫荡死锁排查与修复

- 用户反馈 NPC 扫荡时出现 `Error 1213 (40001): Deadlock found when trying to get lock; try restarting transaction`，前端表现为“扫荡完成：成功 3 场，失败 1 场”。
- 定位为 NPC 城池扫荡逐场调用 `/api/v1/map/npc-cities/attack`，其中某一场攻击在 MySQL 资产事务写入玩家状态、资源、兵力、武将经验、NPC 快照等数据时遇到 InnoDB 死锁。
- 判断原因：近期战报、资产权威表、武将经验和奖励流水接入后，单场 NPC 攻击事务触达表和索引增多；扫荡连续快速攻击时更容易暴露数据库并发锁冲突。
- 修复方案：在 `Service.AttackNpc` 的核心 `UpdateCombatState` 事务外增加可恢复数据库冲突短重试，识别 `deadlock`、`Error 1213`、`40001`、`lock wait timeout`、`Error 1205`，最多重试 3 次。
- 重试前会清空本次尝试的临时战报、奖励、俘虏驻防等变量，确保只重试未提交的核心事务，避免重复扣兵、重复发奖或重复攻击。
- 验证通过：`go test ./internal/app/game -run 'TestAttackNpc|TestStorageConflict' -count=1`，以及 `go test ./internal/app/game ./internal/transport/api ./cmd/dbtool`。
