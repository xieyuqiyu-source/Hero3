## NPC 扫荡死锁排查与修复

- 用户反馈 NPC 扫荡时出现 `Error 1213 (40001): Deadlock found when trying to get lock; try restarting transaction`，前端表现为“扫荡完成：成功 3 场，失败 1 场”。
- 定位为 NPC 城池扫荡逐场调用 `/api/v1/map/npc-cities/attack`，其中某一场攻击在 MySQL 资产事务写入玩家状态、资源、兵力、武将经验、NPC 快照等数据时遇到 InnoDB 死锁。
- 判断原因：近期战报、资产权威表、武将经验和奖励流水接入后，单场 NPC 攻击事务触达表和索引增多；扫荡连续快速攻击时更容易暴露数据库并发锁冲突。
- 修复方案：在 `Service.AttackNpc` 的核心 `UpdateCombatState` 事务外增加可恢复数据库冲突短重试，识别 `deadlock`、`Error 1213`、`40001`、`lock wait timeout`、`Error 1205`，最多重试 3 次。
- 重试前会清空本次尝试的临时战报、奖励、俘虏驻防等变量，确保只重试未提交的核心事务，避免重复扣兵、重复发奖或重复攻击。
- 验证通过：`go test ./internal/app/game -run 'TestAttackNpc|TestStorageConflict' -count=1`，以及 `go test ./internal/app/game ./internal/transport/api ./cmd/dbtool`。
- 发布提交 `a1ad02f` 触发 Actions `Deploy Hero3 #64`，失败点仍在服务器 `Build and deploy on server`；本地复验通过 `go build ./cmd/server`、`go test ./internal/app/game ./internal/transport/api ./cmd/dbtool`、`pnpm --dir web build`、`pnpm --dir admin build`，准备追加重试发布提交。

## 经验包使用死锁

- 用户截图反馈一次性使用 999 个“将领经验包”时报 `Error 1213 (40001): Deadlock found when trying to get lock; try restarting transaction`。
- 线上日志显示同一时间大量 `/api/v1/map/npc-cities/attack` 在 NPC 扫荡事务内遇到死锁并重试，期间也有 `/api/v1/items/use` 请求；MySQL 进程列表可见同一玩家多个 `SELECT ... FOR UPDATE` 和 `DELETE FROM player_inventory` 并发。
- 判断原因：NPC 攻击之前只有数据库死锁重试，但没有按玩家进入 `playerLocks` 串行；道具使用有玩家锁但缺少数据库死锁重试，因此在高频扫荡和使用经验包同时发生时，错误会直接透给前端。
- 修复：`UseItem` 的 `UpdateItemState` 主事务增加和 NPC 攻击一致的可恢复死锁短重试，重试前清空本次临时效果、资产快照和道具数量，避免失败尝试污染最终返回。
- 修复：`AttackNpc` 进入玩家资产事务前按 `playerId` 加 `playerLocks`，让同一玩家的 NPC 攻击、扫荡和道具使用串行进入核心资产写入，减少同玩家并发事务互锁。
- 验证通过：`go test ./internal/app/game -run 'TestUseItem|TestGrantItem|TestAttackNpc|TestStorageConflict' -count=1`、`go test ./internal/app/game -count=1`、`git diff --check`。
