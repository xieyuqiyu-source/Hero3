# 2026-06-27 记忆

## 增援系统第一版开发

- 用户要求按 `docs/系统设计/增援系统开发文档.md` 开发增援系统，若中间有冲突点结束后说明。
- 已确认规则冲突/取舍：
  - 增援是玩法模块，不应写入接收方长期兵力。
  - 派出兵力通过派出方长期兵力扣出，剩余兵力返程完成后返还派出方。
  - 携带武将通过 `player_general_assignments` 占用，`module_id = reinforcement`，返程完成后释放。
  - 当前没有完整 PVP 防守战斗系统，因此本轮提供 `BuildDefenseReinforcementUnits` 和 `ApplyReinforcementBattleResult` 接入点，不强行开发 PVP。
  - 当前信函系统没有统一的模块幂等通知入口，因此本轮保留 `mail_state_json` 幂等字段，不自动发送增援生命周期邮件，避免重复结算刷屏。
- 后端已新增：
  - `Reinforcement` 领域模型、请求/响应、状态常量。
  - `ReinforcementRepository`。
  - 内存仓储实现。
  - MySQL `player_reinforcements` 表和 `mysql_reinforcements.go`。
  - `service_reinforcement.go`，支持发起、列表、详情、召回、遣返、到达结算、返程完成、防守援军构建、战斗损耗应用。
  - HTTP handlers 和路由：`/api/v1/reinforcements`、`/sent`、`/received`、`/{reinforcementId}`、`/recall`、`/expel`。
- 玩法模块注册表已登记 `reinforcement`。
- 前端已新增：
  - 增援类型和 API 方法。
  - `/reinforcements` 页面。
  - 桌面和移动侧边栏“增援”入口。
  - 页面支持我派出的/我收到的、发起增援、召回、遣返。
- OpenAPI 已新增 `paths/reinforcement.yaml` 和 `schemas/reinforcement.yaml`，打包文档已更新。
- 文档已同步：
  - `docs/系统设计/增援系统开发文档.md` 增加当前落地状态。
  - `docs/数据库/数据库设计.md` 增加 `player_reinforcements` 表说明。
  - `go/README.md` 更新玩法模块说明。
- 测试覆盖：
  - 发起增援扣兵和武将占用。
  - 同一接收方最多 5 个来源，且同来源可追加多批。
  - 行军速度倍率影响行军时间。
  - 到达后可构建防守援军。
  - 战斗损耗全灭后返程，返程完成幂等且不返还已死兵力。
