# 2026-07-06 记忆

## 战报系统大改造

- 按 `docs/系统设计/战报系统大改造开发文档.md` 推进战报重修，保留统一战报入口，不允许玩法绕过核心战报能力。
- 后端 `BattleReport` 和 `BattleReportDetail` 补齐 `winnerSide`、`ownerSide`、`ownerOutcome`，由 `report_standard.go` 集中推导；旧 `defender_defeat` 仅作为历史兼容读取，不再作为新 PVP 防守战报写入值。
- PVP 侦查攻击方战报改为 `viewType=scout`、`ownerSide=scout`，侦查 extra 补 `scoutSent/scoutLost/scoutReturned/revealResources/revealUnits` 等上下文。
- 协防战报补 `detail.extra.reinforcement`，包含被协防玩家和城池、攻击来源、事件 ID、协防方出动/损失/剩余/武将经验。
- 黄巾防守和黄巾协防战报补 `detail.extra.yellowTurban`，包含来袭 ID、黄巾来源城、风险等级、当前口粮、承载上限和压力。
- 扫荡战报补 `detail.extra.sweep.detailMode=lightweight`，前端只按轻量目标摘要渲染，不扩大完整明细写入体积。
- 玩家端军情列表调整为全部、进攻、防守、协防、侦查、扫荡；侦查和扫荡按 `battleType` 筛选，列表结果优先显示 `ownerOutcome`。
- 玩家端战报详情页拆到 `report-detail/` 组件目录，优先使用 `detail.primarySide / secondarySide / rewards / traits / visibility / extra` 渲染；保留历史战报本地兜底结构。
- GM 后台新增“战报排查”页面，接入已有 `/admin/battle-events`、事件报告和参与方接口，只读查看同事件所有视角战报和原始 extra。
- 玩家侧新增 `GET /api/v1/report-events/{reportId}`，只返回当前玩家可见的同事件报告和参与方快照，避免泄露其他玩家视角；该路径避开既有分享路径 `/reports/shared/{token}` 的 ServeMux 冲突。
- 轮回绝境战报补 `detail.extra.dungeon.rewardMode=preview`，明确当前战报奖励是预览而非最终发放流水。
- OpenAPI 同步战报新字段、`yellow_turban` 来源、`ownerOutcome` 查询参数和 sweep/scout/reinforcement/yellowTurban/dungeon extra schema。
- 验证通过：`go test ./...`、玩家前端 `npm run build`、GM 后台 `npm run build`、`python3 scripts/openapi_bundle.py`。

## 战报详情布局按参考图调整

- 用户要求战报 UI 风格可沿用当前实现，但布局必须按参考图：上方攻击方，交战分隔，下方防守方，并继续向下排列多个增援/协防方。
- 兵种矩阵默认展示所有兵种，不再折叠 0 数量兵种；协防/增援快照只有实际兵力时，前端按阵营兵种配置补齐 0 行。
- 每个参战方区块内部按“身份/武将信息、战前效果、兵种矩阵、掠夺资源、建筑战损、战损反馈、宝物掉落”排列；不渲染参考图中的热门推荐。
- 验证通过：玩家前端 `npm run build`。

## 战报详情布局微调

- 官职、军衔当前统一占位为 `-`，只兼容读取后续可能补上的真实字段，不再用阵营、城池或玩家名冒充。
- 防守方无将领时，武将/官职/军衔区域合并为单行 `-` 占位；战力与生命状态行也统一显示 `-`。
- 原“本场战斗按当前规则结算”行改为特性触发行，触发特性仅做文字高亮，不再在底部单独渲染特性面板。
- 参与方左侧徽标改显示阵营，标题栏右侧显示玩家名、NPC 名或增援来源名。
- 验证通过：玩家前端 `npm run build`。

## 战报详情阵营与胜败视觉微调

- 左侧阵营徽标撑满格子，使用楷体和更大字号；魏、蜀、吴、未知阵营分别使用不同色系区分。
- 参与方标题栏右侧名称改为紧挨攻击方/防守方/增援方标题并高亮，不再右对齐。
- 右上角胜败印改为楷体大字，并按胜、败、平使用不同颜色；增援方按防守侧胜败计算。
- 验证通过：玩家前端 `npm run build`。

## 战报顶部标题微调

- 顶部战报标题优先按标准详情结构化渲染为“进攻方名称 动作 防守方名称”，整体居中并放大。
- 攻防双方名称按阵营色高亮区分；缺少标准双方数据时才回退显示原始 `detail.title`。
- 验证通过：玩家前端 `npm run build`。

## 战报增援方信息与特性修正

- 增援战报快照补 `fromPlayerName`，玩家端增援方标题优先显示增援来源名，旧数据缺名时再回退到获得驻防或玩家 ID。
- 阵营徽标不再直接显示 `wei/shu/wu` 代码，统一转成魏、蜀、吴，并继续按阵营色区分。
- 参与方特性栏改为读取当前方块自己的将领特性，增援方使用增援武将快照里的 `traits`；无将领或将领无特性时显示 `-`。
- 特性文本包含将领名、特性名、触发时机、描述和参数，避免只显示触发摘要。
- 验证通过：Go `go test ./...`、玩家前端 `npm run build`。

## 战报将领特性旧数据兜底

- 普通 PVP 武将快照 `PvpGeneralSnapshot` 新增 `traits`，标准战报转换会把攻防双方武将特性写入详情，后续本人武将特性不再丢失。
- 玩家端对旧战报做兜底：参战方武将缺少 `traits` 时，优先从当前存档武将状态补；仍缺时按静态武将特性表补中文特性名和描述。
- 特性标题强制使用前端特性注册表中文名，不再信任快照里的英文 ID 或旧英文 name。
- 增援方旧战报的玩家 ID 会优先用账号存档列表和当前存档状态反查昵称，反查不到才显示 ID。
- 验证通过：Go `go test ./...`、玩家前端 `npm run build`。
