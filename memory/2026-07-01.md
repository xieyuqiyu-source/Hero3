# 2026-07-01 记忆

- 线上玩家 `xiaomimi` 反馈 NPC 扫荡偶发 `Error 1213 Deadlock found when trying to get lock`。排查 `hero3.service` 日志，确认集中在同一存档高频 NPC 攻击/扫荡时出现，符合手机和电脑同时操作同一存档导致事务抢锁的表现。
- 架构处理共识：对同一 `player_id` 的 NPC 攻击/扫荡做串行保护；如果同一存档已有 NPC 操作正在执行，新的 NPC 操作不排队等待，直接返回友好错误 `操作太快，请稍后再试`，HTTP 状态为 `429 Too Many Requests`，减少数据库错误直接暴露给玩家。
- 实现调整：`AttackNpc` 和 `SweepNpc` 在公开入口尝试获取玩家锁，内部 `attackNpc` 不再重复拿锁，避免批量扫荡期间被另一端同存档 NPC 操作插队。
- 测试补充：新增同一存档扫荡执行中再次 NPC 攻击会返回 `ErrOperationTooFast` 的测试，确保不会进入第二个存储事务。
- 前端体验优化：一键扫荡弹窗和军情战报详情的宝物掉落按物品标识和品质聚合展示，避免同一物品掉落多次时弹窗过长。
- 验证：后端通过 `go test ./internal/app/game ./internal/transport/api`；前端通过 `npm run build`。
- 存档删除保护：删除存档改为 1 小时冷静期，首次删除只写入 `deleteRequestedAt/deleteScheduledAt`，存档列表显示倒计时并提供恢复按钮；到期后刷新存档列表触发真正硬删除。前端云同步弹窗和账户页都展示倒计时/恢复，删除入口加两次确认。
- 新增接口：`DELETE /api/v1/players/{playerId}` 负责申请删除或到期硬删除；`POST /api/v1/players/{playerId}/restore-delete` 负责取消待删除状态。
- 验证：延迟删除版本通过 `go test ./internal/app/game ./internal/transport/api` 和 `npm run build`；额外跑 storage 集成包时有 3 个既有 MySQL 更新时间断言失败，未作为本次阻塞项。
