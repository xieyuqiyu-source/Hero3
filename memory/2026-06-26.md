# 2026-06-26 记忆

## 驻防/增援系统

- 当前阶段完成玩家之间互相增援基础闭环，不支持对 NPC 城池增援。
- `GameState` 新增 `garrisonArmy`，用于存放驻防军队；主军队 `army` 和驻防军队不得混用。
- 非增援渠道获得兵种时：
  - 本阵营兵种进入 `army`。
  - 非本阵营兵种进入 `garrisonArmy`。
- 玩家主动增援时，发起方扣除对应兵力；抵达目标玩家后，无论本阵营或非本阵营兵种，全部进入目标玩家 `garrisonArmy`。
- 增援接口生成 `reinforce` 类型军情/战报，并分别给发起方和目标方保存记录。
- 新增玩家互攻基础接口，防守方 `army` 与 `garrisonArmy` 共同参与防守计算。
- PVP 防守结算时内部使用带来源的战斗单位 ID 区分主军队和驻防军队；战损按来源分别扣回 `army` 或 `garrisonArmy`，避免同兵种粗暴扣错池子。
- 钓鱼库存兑换规则已更新：非本阵营兵种不再拒绝，兑换后进入驻防军队。

## 公告系统

- 公告系统按纯公告实现，不支持附件、不支持奖励领取、不支持玩家回复。
- 公告和信函系统保持独立：
  - 后端使用 `announcements` 与 `announcement_reads` 独立表。
  - 内存仓储使用独立公告 map 和已读 map。
  - 玩家端公告不进入 `mail` 页面，不产生信函记录。
- 公告支持 `system`、`maintenance`、`event`、`update` 类型。
- 公告支持 `draft`、`published`、`archived` 状态。
- 玩家只看到 `published` 且处于 `startsAt` / `endsAt` 展示窗口内的公告。
- 公告排序规则为置顶优先、优先级高优先、展示/创建时间新优先。
- 玩家端新增 `/notice` 页面和侧边栏公告入口，未读数走独立公告接口。
- GM 后台新增独立“公告管理”页面，支持列表、新建、编辑、发布、下架和软删除。
- OpenAPI 新增公告 paths 和 schemas，并挂载到入口文件。
