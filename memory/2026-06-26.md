# Hero3 Memory - 2026-06-26

## 核心地基补强：建筑生命周期

- 用户确认核心地基已完成后，继续追问建筑长期状态是否应算入地基。
- 共识：建筑是玩家长期资产，建筑状态变化应进入核心地基，而不是后续玩法临时补丁。
- 已新增 `internal/core/building`，定义建筑标准状态和通用变更类型。
- 建筑标准状态包括：`normal`、`constructing`、`upgrading`、`locked`、`damaged`、`destroyed`、`repairing`、`disabled`、`protected`、`occupied`。
- 已新增应用层统一入口 `MutateBuilding(playerID, mutation)`，建筑摧毁、损坏、修复、锁定、占领等长期状态变化应通过该入口或后续 Effect Pipeline 调用。
- 现有升级流程接入建筑状态：开始升级为 `upgrading`，完成升级恢复 `normal`。
- `destroyed`、`disabled` 建筑不再提供资源产量、容量和建筑 Modifier。
- 建筑状态变化会进入核心资产事件快照，通过 `building.upgraded` 事件的 `statusChanges` 载荷发布。
- 已更新核心地基文档、总体架构文档和 Go README。
- 本轮验证目标：`go test ./...`、`git diff --check`。

## Effect Pipeline 第一版

- 本轮进入最后一块：Effect Pipeline 设计与接入。
- 共识保持不变：玩法模块、武将特性、道具效果、建筑效果不能各自直接改长期资产，应提交标准效果，由统一管线校验并执行。
- 已新增 `internal/core/effect`，定义稳定效果契约，不直接读写玩家存档。
- 当前标准效果类型包括：`reward`、`building_mutation`、`modifier`。
- 已新增 `effect_pipeline.go`，应用层执行器 `ExecuteEffectsOnState` 和服务级事务入口 `Service.ExecuteEffects`。
- `reward` 效果内部复用 `ApplyRewardsToStateWithContext`。
- `building_mutation` 效果内部复用建筑生命周期校验和 `applyBuildingMutation`。
- `modifier` 效果会转换为标准 Buff 奖励，再进入 Modifier 管线。
- `MutateBuilding` 已改为提交 `building_mutation` 效果，由 `Service.ExecuteEffects` 执行。
- `item_effects.go` 已把道具效果转换为标准 `reward` 效果，武将经验、资源、兵力产出不再由道具系统直接写长期资产。
- `ClaimMailAttachments` 已把信函附件转换为标准 `reward` 效果，通过 Effect Pipeline 发放。
- `RedeemMiniGameReward` 和 `RedeemAllFactionMiniGameRewards` 已把万象幻境兑换产出转换为标准 `reward` 效果，通过 Effect Pipeline 发放。
- 已新增 `effect_pipeline_test.go` 和 `internal/core/effect/effect_test.go`，覆盖奖励效果、建筑变更效果、Modifier 效果、服务级资产事件和核心效果 helper。
- 文档已补充“Effect Pipeline”：后续武将特性、活动、副本如果要影响长期资产，应优先提交标准 Effect；如果需要新长期资产容器，先讨论核心是否不完整。
- 本轮验证目标：`go test ./...`、`git diff --check`。
