- 排查 `xiaomimi`、`洛美人` 等存档一键扫荡偶发“服务器异常”，确认线上主要表现为 `POST /api/v1/map/npc-cities/sweep` 偶发 `502`，Nginx 日志为 `upstream prematurely closed connection while reading response header from upstream`。
- 洛美人最近一次北京时间 `2026-07-03 09:56:45` 前端报错，但战报 `br_5b39e2e4b3df1935` 已保存，实际为“扫荡 10 城，成功 10 场”，说明异常发生在响应写回阶段，不是结算失败。

## 自动部署方式调整

- 用户确认采用“方案二”：核心原则是服务器本机构建部署，GitHub Actions 不在 runner 上安装 Go/Node，也不构建 release 产物。
- 初版实现让服务器在 `/opt/hero3/source` 直接拉取 `main-core` 指定 `GITHUB_SHA`；实测服务器到 GitHub 的 HTTPS fetch 多次卡住，因此当前实现调整为 GitHub Actions checkout 当前提交、打包完整源码仓库快照并通过 SSH 上传，服务器解包到 `/opt/hero3/source` 后本机构建。
- 源码包包含最近 100 个提交的 `.git` 历史，供每日更新公告继续读取 git log；Actions checkout 设置 `persist-credentials: false`，避免把 GitHub token 写入服务器源码目录。
- 手动触发生产部署时只允许 `main-core`。
- 部署脚本保留 `flock` 单实例部署、旧后端和前端静态资源备份、systemd timer 安装、`hero3.service` 重启、Nginx reload 和本地/公网健康检查。
- 服务器 Go 已升级到 `/usr/local/go` 的 `go1.26.4 linux/amd64`，`/usr/local/bin/go` 在 SSH 部署环境中优先；部署脚本仍保留 `GOTOOLCHAIN=auto`。
- `docs/运维部署/服务器部署文档.md` 已同步为单一方案二口径，删除旧的 release 包构建、服务器拉 GitHub、静态资源按目录变更跳过等干扰信息。
