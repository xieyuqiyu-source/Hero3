## 将领特性生效链路复查

- 用户复查后指出“将领特性是不是没生效”。确认不是完全没生效，但存在部分链路只完成配置/展示/注册、没有完整进入结算结果或战报的缺口。
- 已修复 PVP 防守方战前与战中事件：防守武将特性现在会通过核心事件管线参与 `before_battle` 与 `after_combat_resolve`，且按触发方区分“自己/敌方”，防守方追击、反伤、压制等效果会作用到进攻方。
- 已修复掠夺收益类特性：进攻方加成和防守方防掠夺都会通过 `plunder_resolve` 核心事件修改最终掠夺资源，并把触发结果合并进双方战报。
- 已修复“压制敌方特性”真实生效：`disable_traits` 现在在核心事件分发器里记录被压制阵营，后续同一事件中的敌方特性会被核心管线跳过，不再只是战报文案。
- 已补齐内政类真实生效链路：`productionBonusRate` 会进入将领 Modifier 影响资源产量；`guardPerMinute` 会在资源结算间隔内产出配置兵种，默认回退为本阵营特殊兵。
- 新增核心测试覆盖防守方追击方向与压制跳过敌方特性，避免后续再次出现“看得到配置但不改结果”的回归。
- 本次复查后再次验证通过：`cd go && go test ./... -count=1`、`cd admin && npm run build`、`cd web && npm run build`、`python3 scripts/openapi_bundle.py`、`git diff --check`。
