# 核心接口想象图

你之前说的“正方形核心，四个方向都有接口”是合适的。

## 输入接口

模块可以向核心提交：

- 消耗资源。
- 消耗兵力。
- 使用道具。
- 选择武将。
- 领取奖励。
- 触发事件。

## 输出接口

核心可以向模块提供：

- 玩家资源。
- 玩家兵力。
- 玩家建筑。
- 玩家武将。
- 玩家道具。
- 当前加成。
- 战斗结果。
- 奖励发放结果。

## 回写接口

模块执行完玩法后，把结果回写核心：

- 扣除兵力。
- 增加奖励。
- 增加道具。
- 更新武将。
- 记录战报。
- 触发事件。

## 关键原则

模块不能绕过核心直接乱改玩家关键状态。
核心也不能塞满某个玩法的专用逻辑。
