# 内容注册表

内容注册表负责让核心认识游戏里的基础内容。

## 资源类型注册表

负责资源类型，例如：

- 木材。
- 石料。
- 铁矿。
- 粮食。
- 未来可能的新资源。

新增资源时，不应该到处写死字段，而应该先注册资源类型，再让数据库和前端识别它。

## 建筑注册表

负责建筑类型和升级配置。

例如：

- 主城。
- 资源田。
- 建造司。
- 未来模块新增建筑。

如果模块新增建筑，核心应该通过建筑 ID 和配置识别，而不是为某个建筑写特殊分支。

## 兵种注册表

负责兵种配置。

例如：

- 步兵。
- 骑兵。
- 弓兵。
- 超级兵。
- 活动兵。

核心只需要识别兵种 ID、数量和战斗属性。

## 武将注册表

负责武将基础配置。

支持多武将的前提是：玩家持有的是武将 ID 列表，而不是核心写死某一个武将。

## 道具注册表

负责道具定义和使用效果。

例如“使用后增加一个新武将”的物品，本质是：

道具使用 -> 奖励系统 -> 武将奖励 -> 玩家武将列表更新。
