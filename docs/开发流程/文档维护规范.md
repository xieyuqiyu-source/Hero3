# <span style="color:#16a34a">Hero3 文档维护规范</span>

最后更新：2026-06-25
文档状态：active

## <span style="color:#16a34a">1. 维护目标</span>

文档是长期维护物，不是一次性交付物。  
代码变更时，相关文档必须同步更新。

每份 Markdown 文档标题下方应标记文档状态：

- `文档状态：active`：当前有效，可作为开发参考。
- `文档状态：planning`：规划草案，只作思考参考。
- `文档状态：historical`：历史记录，只作回看。
- `文档状态：deprecated`：已过期，默认不参考。

## <span style="color:#16a34a">2. 什么时候必须改文档</span>

- 新增接口
- 修改接口参数或响应
- 新增玩法模块
- 修改存档结构
- 修改数据库表或索引
- 修改鉴权规则
- 修改发版或回滚流程
- 修改数值配置或平衡规则

## <span style="color:#16a34a">3. 文档同步顺序</span>

推荐顺序：

1. 先改设计文档。
2. 再改 OpenAPI 或数据库说明。
3. 再改代码。
4. 最后补测试和回归记录。

## <span style="color:#16a34a">4. 目录放置规则</span>

- 产品目标放 `docs/产品/`
- 架构放 `docs/架构/`
- 领域模型放 `docs/领域模型/`
- 数据库放 `docs/数据库/`
- 安全权限放 `docs/安全与权限/`
- 测试放 `docs/测试/`
- 发布回滚放 `docs/发布与回滚/`
- 开发过程放 `docs/开发流程/`
- 接口放 `docs/接口文档/`

## <span style="color:#16a34a">5. 建议的最小维护集</span>

每个大功能至少维护这四类内容：

- 设计说明
- 接口契约
- 数据结构
- 测试记录

## <span style="color:#16a34a">6. 版本习惯</span>

- 文档标题要写最后更新日期。
- 文档标题下方要写文档状态。
- 先小步补齐，再持续修订。
- 避免把文档写成一次性大作文。
- 以“能被后续开发接着改”为标准。

## <span style="color:#16a34a">7. 可读性规范</span>

规划类、路线图类、状态类文档可以使用少量 HTML 彩色标签提升可读性。

建议颜色：

| 类型 | 颜色 |
|---|---|
| 功能点 | <span style="color:#2563eb;font-weight:700">蓝色</span> |
| 副本/活动 | <span style="color:#7c3aed;font-weight:700">紫色</span> |
| 据点/战争 | <span style="color:#c2410c;font-weight:700">橙色</span> |
| NPC/世界事件 | <span style="color:#16a34a;font-weight:700">绿色</span> |
| 待定/风险 | <span style="color:#64748b;font-weight:700">灰色</span> |

注意：

- 颜色只辅助阅读，不能替代文字标签。
- 不要整段大面积染色。
- 业务文档优先保证清晰，颜色只用于分类、状态和重点。
