# <span style="color:#2563eb">Hero3 未来开发规划</span>

最后更新：2026-06-25
文档状态：planning

## <span style="color:#2563eb">1. 文档目的</span>

本文档用于记录 Hero3 后续要逐步补充的功能点、玩法模块和整体开发计划。  
内容会随着开发不断修订，当前版本先记录方向，不作为最终数值和平衡方案。

为了提升阅读区分度，本文档使用彩色标签标记模块类型和开发状态。  
如果某些 Markdown 查看器不显示颜色，以标签文字为准。

| 标签 | 含义 |

## <span style="color:#2563eb">3. 功能点规划</span>

### 3.1 <span style="color:#2563eb">功能点</span>：兵种缩略图

目标：

- 为全部兵种补齐缩略图。
- 玩家端用于征兵、军队、战报、派兵、奖励展示。
- GM 后台用于兵种配置、奖励配置、调试面板展示。

要求：

- 每个兵种有稳定资源 key。
- 图片命名和兵种配置保持一致。
- 前端不要硬编码图片路径，优先通过兵种配置或统一资源映射读取。

### 3.2 <span style="color:#2563eb">功能点</span>：武将缩略图

目标：

- 为全部武将补齐缩略图。
- 玩家端用于登录选将、军事页、战报、特性展示。
- 后台用于将领配置和运营查看。

要求：

- 每个武将有头像、缩略图和可选立绘。
- 图片资源和将领 `id` 对齐。
- 后续支持稀有度、阵营、技能标签展示。

### 3.3 <span style="color:#2563eb">功能点</span>：建造司扩展资源田

建造司作为资源建筑扩展入口，后续应承担“增加资源田数量”的功能。

规则草案：

| 建造司等级 | 新增资源田数量 | 累计新增 |
|---|---:|---:|
| 1 | +1 | 1 |
| 5 | +1 | 2 |
| 10 | +1 | 3 |
| 15 | +1 | 4 |
| 20 | +1 | 5 |
| 25 | 待定 | 5 |

当前规则说明：

- 最多新增 5 个资源田。
- 新资源田由建造司等级解锁。
- 建造司只能使用金币升级。
- 是否允许玩家选择新增资源田类型，后续再定。

待确认问题：

- 新增资源田是固定顺序，还是由玩家选择木/石/铁/粮。
- 新资源田是否和初始资源田使用同一套升级消耗。
- 建造司本身是否占建筑位。
- 建造司金币升级是否需要冷却时间。

## <span style="color:#2563eb">4. 副本与活动模块规划</span>

副本定位：副本是周期性活动和特殊挑战模块，不等同于普通 NPC 城池。  
副本可以有独立入口、独立结算、独立奖励和独立排行榜。

### 4.1 <span style="color:#7c3aed">副本</span>：万王争霸

方向：

- 多玩家竞争型活动副本。
- 可按赛季或周期开放。
- 重点突出排名、积分、贡献和结算奖励。

待补充：

- 参战条件
- 匹配或分组规则
- 积分来源
- 奖励结构
- 是否允许跨阵营竞争

### 4.2 <span style="color:#7c3aed">副本</span>：天下名将

方向：

- 围绕名将挑战、招募、碎片、传记或专属装备展开。
- 可以作为武将系统扩展的重要入口。

待补充：

- 名将挑战规则
- 掉落内容
- 武将获取方式
- 每日/每周次数限制
- 与已有将领系统的关系

### 4.3 <span style="color:#7c3aed">副本</span>：轮回绝境

方向：

- 高难度连续挑战副本。
- 强调多轮战斗、资源消耗、阵容选择和极限奖励。

待补充：

- 轮数规则
- 失败重置规则
- 是否消耗真实兵力
- 是否允许复活或购买增益
- 排行榜和保底奖励

## <span style="color:#2563eb">5. 据点玩法规划</span>

据点定位：据点是可占领、可争夺、可提供加成的地图战略目标。  
和副本不同，据点更偏长期归属和全局加成。

### 5.1 <span style="color:#c2410c">据点</span>：沙巴克

方向：

- 大型核心据点。
- 可设计为联盟/阵营争夺目标。
- 占领后提供全局加成或特殊权益。

可能加成：

- 资源产量加成
- 征兵速度加成
- 行军速度加成
- 每日奖励
- 特殊商店权限

待补充：

- 占领周期
- 宣战规则
- 防守规则
- 归属结算
- 加成范围是个人、联盟还是阵营

### 5.2 <span style="color:#c2410c">据点</span>：沉冤池

方向：

- 全服公共高难度据点。
- 可承载战损贡献、击杀奖励和参与奖励。
- 可与现有 MVP 规划中的沉冤池设计继续合并。

可能机制：

- 玩家攻打后累计战损贡献。
- 达到贡献门槛获得个人奖励。
- 最终击杀者获得额外奖励。
- 据点池子越大，奖励品质越高。

待补充：

- 刷新周期
- 难度成长
- 贡献计算
- 击杀归属
- 奖励池配置

## <span style="color:#2563eb">6. NPC 反攻机制规划</span>

NPC 后续不应只作为静态被打目标，还需要具备动态反应。  
黄巾起义可以作为第一套 NPC 反攻机制。

### 6.1 <span style="color:#16a34a">NPC</span>：黄巾起义

方向：

- 玩家长期攻击 NPC 或全服进度达到条件后，触发黄巾反攻。
- NPC 会主动攻击玩家城池、据点或资源点。
- 反攻既是压力系统，也是活动系统。

可能触发条件：

- 玩家连续攻打 NPC 达到次数。
- 某地区 NPC 城池被清空。
- 全服击杀黄巾军达到阈值。
- 周期性活动开启。

可能玩法：

- 黄巾军反攻玩家主城。
- 黄巾军围攻公共据点。
- 玩家防守成功获得奖励。
- 防守失败损失部分资源或进入保护状态。

待补充：

- 反攻目标选择规则
- 反攻行军时间
- 玩家预警机制
- 防守失败惩罚
- 防守成功奖励
- 是否允许盟友增援

## <span style="color:#2563eb">7. 整体开发计划</span>

### 7.1 <span style="color:#2563eb">阶段一</span>：基础表现补齐

目标：

- 补齐兵种缩略图。
- 补齐武将缩略图。
- 梳理资源映射和图片加载方式。
- 避免后续 UI 大量硬编码资源路径。

### 7.2 <span style="color:#2563eb">阶段二</span>：建造司与资源田扩展

目标：

- 实现建造司建筑。
- 建造司使用金币升级。
- 建造司按等级解锁新资源田。
- 前端支持展示新增资源田。
- 后端支持存档结构扩展和资源田上限计算。

### 7.3 <span style="color:#7c3aed">阶段三</span>：副本活动框架

目标：

- 先建立通用副本/活动模块框架。
- 支持活动配置、开启时间、参与记录、奖励结算。
- 再逐步接入万王争霸、天下名将、轮回绝境。

### 7.4 <span style="color:#c2410c">阶段四</span>：据点框架

目标：

- 建立全服据点数据结构。
- 支持占领、归属、加成、刷新和结算。
- 先做沉冤池或沙巴克其中一个 MVP。

### 7.5 <span style="color:#16a34a">阶段五</span>：NPC 动态反攻

目标：

- NPC 从静态目标升级为动态势力。
- 实现黄巾起义第一版。
- 支持预警、防守、奖励、失败惩罚。

## <span style="color:#2563eb">8. 后续补充规则</span>

本规划文档后续持续补充：

- 新想法先写入本文档。
- 进入开发前拆到具体系统设计文档。
- 确定接口后同步 OpenAPI。
- 涉及存档或数据库时同步数据库设计。
- 涉及奖励和金币时同步配置与平衡文档。
