# <span style="color:#f59e0b">天机轮转老虎机系统设计</span>

最后更新：2026-07-01

## <span style="color:#8b5cf6">定位</span>

天机轮转是万象幻境下的第三个小游戏模块，玩法形态是老虎机。

它不进入建筑、资源、战斗主循环，也不绕过核心资产系统。玩家使用已有兵种作为押注，后端完成结算，胜利奖励进入小游戏库存，玩家后续手动兑换。

稳定定位：

- 展示名称：天机轮转
- 玩法类型：老虎机
- 所属入口：玩家端 `地图 -> 万象幻境`
- 后端 `gameType`：`slot`
- 资产规则：押注先扣兵，中奖奖励进可兑换库存
- 结算权威：后端结算，前端只播放后端返回结果
- 数据归属：复用 `minigame_records`
- 当前目标版本：第二版复杂规则

说明：

- 早期简化规则只作为背景，不作为当前开发目标。
- 新开发代理必须实现“第二版复杂规则”。
- 第二版仍然只有 3 个轮子，但每个轮子显示 3 格，形成 `3 列 × 3 行` 的可视窗口。
- 第二版必须有真实滚动动画，最终停靠结果必须和后端返回的 3x3 网格一致。

## <span style="color:#8b5cf6">核心原则</span>

1. 不允许前端上报中奖结果。
2. 不允许前端决定随机结果。
3. 不允许未扣押注就写中奖库存。
4. 不新增独立库存表，复用小游戏记录库存体系。
5. 所有长期资产变更必须走后端事务。
6. 输赢都写记录，方便 GM 后续排查。
7. 中奖库存只在玩家主动兑换时进入军队或驻防。

## <span style="color:#8b5cf6">第二版复杂规则（当前开发目标）</span>

第二版不是简单的“三个一样才中奖”。它采用现实老虎机更接近的结构：3 个轮子、3 行可视窗口、多条赔付线、Wild、Scatter、免费旋转和小型奖励局。

### 可视窗口

屏幕上显示 3 个竖向轮子，每个轮子最终停下后显示 3 个图案：

```text
左轮    中轮    右轮
上格    上格    上格
中格    中格    中格
下格    下格    下格
```

后端返回结构应是一个 3x3 网格：

```json
[
  ["bronze_charm", "silver_charm", "tiger_tally"],
  ["wild", "gold_charm", "gold_charm"],
  ["scatter", "scatter", "scatter"]
]
```

数组约定：

- 第一层为行，顺序是 `top`、`middle`、`bottom`。
- 第二层为列，顺序是 `left`、`center`、`right`。

### 赔付线

第二版固定开启 5 条赔付线，不做玩家选择线路数量，降低前端复杂度。

| 线 ID | 名称 | 坐标 |
| --- | --- | --- |
| `middle` | 中横线 | 中左、中中、中右 |
| `top` | 上横线 | 上左、上中、上右 |
| `bottom` | 下横线 | 下左、下中、下右 |
| `diagonal_down` | 左上到右下 | 上左、中中、下右 |
| `diagonal_up` | 左下到右上 | 下左、中中、上右 |

坐标示意：

```text
top:            X X X
middle:         X X X
bottom:         X X X
diagonal_down:  X
                  X
                    X
diagonal_up:        X
                  X
                X
```

### 押注方式

第二版押注使用“单次押注”。

```text
totalBet = lineBet
```

玩家界面展示：

- 单次押注：玩家选择或输入。
- 可中奖线：系统固定结算 5 条线。
- 本局扣除：与单次押注相同。

扣兵数量按单次押注扣除。

示例：

```text
单次押注 10,000
固定 5 条线
实际扣兵 10,000
```

中奖计算按每条线独立计算：

```text
lineWin = lineBet * multiplier
totalWin = 所有中奖线 lineWin 之和 + 满天星奖励 + Scatter 奖励 + Bonus 奖励 + 免费旋转奖励
```

### 第二版押注规则

| 项 | 值 |
| --- | ---: |
| 单次最小押注 | 1,000 |
| 额外固定上限 | 无 |
| 单次押注上限 | 不能超过当前拥有的押注兵力 |

最终校验：

```text
lineBet >= 1,000
totalBet = lineBet
totalBet <= currentUnitAmount
```

不再使用单次固定上限或当前兵力比例上限。玩家可以自由输入单次押注，只要本局押注能被当前兵力支付即可。

### 图案类型

第二版包含普通赔付图案和特殊图案。

| 图案 ID | 显示名 | 类型 | 稀有度 | 说明 |
| --- | --- | --- | --- | --- |
| `bronze_charm` | 玄铜符 | 普通 | common | 低级图案 |
| `silver_charm` | 白银符 | 普通 | rare | 中低级图案 |
| `gold_charm` | 赤金符 | 普通 | rare | 中级图案 |
| `jade_seal` | 玉玺 | 普通 | epic | 高级图案 |
| `tiger_tally` | 虎符 | 普通 | epic | 高级图案 |
| `heaven_order` | 天命令 | 普通 | legendary | 顶级图案 |
| `wild` | 天机令 | Wild | epic | 大小王，可替代普通图案并补齐星陨/宝匣触发 |
| `scatter` | 星陨 | Scatter | epic | 任意位置 3 个触发免费旋转 |
| `bonus` | 宝匣 | Bonus | rare | 任意位置 3 个触发奖励局 |

### 普通赔付规则

每条赔付线只看 3 个格子。

普通图案中奖条件：

- 同一条线上 3 个普通图案相同。
- `wild` 是大小王，可以替代普通图案，并可补齐 Scatter / Bonus 的 3 个触发条件。
- `wild / wild / 普通图案` 按该普通图案赔付。
- `wild / 普通图案 / wild` 按该普通图案赔付。
- `普通图案 / wild / wild` 按该普通图案赔付。
- `wild / wild / wild` 按 `天命令` 的 3 连倍率赔付。

不中奖示例：

- `玄铜符 / 玄铜符 / 白银符`
- `scatter / bonus / wild`
- `bonus / scatter / wild`

特殊图案补齐规则：

- `scatter / wild / wild` 会按 3 个星陨触发免费旋转。
- `bonus / wild / wild` 会按 3 个宝匣触发奖励局。
- `wild / wild / wild` 优先按普通顶级图案 `天命令` 三连赔付，不凭空触发星陨或宝匣。

### 第二版倍率表

倍率按“单次押注”计算。

| 图案 | 三连倍率 |
| --- | ---: |
| 玄铜符 | ×3 |
| 白银符 | ×6 |
| 赤金符 | ×12 |
| 玉玺 | ×30 |
| 虎符 | ×80 |
| 天命令 | ×250 |
| 天机令三连 | ×250 |

说明：

- 第二版因为有 5 条线和特殊机制，普通三连倍率必须低于早期简化方案。
- 奖励仍按 gross 奖励写入库存。
- 押注已扣除，玩家实际净收益要减去本局单次押注。

### Scatter 免费旋转

Scatter 图案为 `星陨`。

触发条件：

- 3 个 `scatter` 出现在任意位置。
- `scatter + wild` 合计凑满 3 个也触发，但至少需要 1 个真实 `scatter`。
- 不要求在赔付线上。

触发奖励：

- 获得 5 次免费旋转。
- 免费旋转不再扣兵。
- 免费旋转沿用触发时的 `lineBet`、押注兵种、赔付线。
- 免费旋转中的中奖奖励继续进入天机库存。
- 免费旋转中再次出现 3 个 Scatter，追加 3 次免费旋转。

限制：

- 单次后端结算最多展开 20 次免费旋转。
- 达到上限后不再追加，避免极端情况下返回过大。

### Bonus 奖励局

Bonus 图案为 `宝匣`。

触发条件：

- 3 个 `bonus` 出现在任意位置。
- `bonus + wild` 合计凑满 3 个也触发，但至少需要 1 个真实 `bonus`。

第二版 Bonus 奖励局不做玩家选择，后端直接随机一个奖励倍率。

奖励池：

| 奖励倍率 | 权重 |
| ---: | ---: |
| ×5 | 50 |
| ×10 | 30 |
| ×20 | 15 |
| ×50 | 5 |

奖励计算：

```text
bonusWin = lineBet * bonusMultiplier
```

Bonus 奖励会计入本局总奖励，并写入同一条 `minigame_records` 记录。

后续如果要做“玩家点宝箱”互动，可以第二阶段再扩展，不进入当前实现。

### 满天星奖励

满天星是不看赔付线的全屏收集奖励。

触发条件：

- 任意位置同类普通图案数量 + `wild` 数量达到 5 个及以上。
- 至少需要 1 个真实普通图案，纯 `wild` 不凭空生成满天星。
- 同局只取收益最高的一组满天星，避免同一批 `wild` 被多个图案重复结算。

数量倍率：

| 数量 | 满天星数量系数 |
| ---: | ---: |
| 5 | ×2 |
| 6 | ×4 |
| 7 | ×8 |
| 8 | ×15 |
| 9 | ×30 |

奖励计算：

```text
allPayWin = lineBet * 普通图案三连倍率 * 满天星数量系数
```

示例：

- 4 个 `gold_charm` + 1 个 `wild` = 赤金符满天星 5，倍率为 `12 * 2 = 24`。
- 9 个 `gold_charm` = 赤金符满天星 9，倍率为 `12 * 30 = 360`。

### 单局总结果

后端一次 `resolve` 可能包含：

- 主旋转结果。
- 主旋转赔付线中奖。
- 主旋转满天星奖励。
- Scatter 触发的免费旋转列表。
- 免费旋转中的赔付线中奖。
- Bonus 奖励。
- 最终总奖励。

最终只写一条 `minigame_records`：

- `bet_amount = totalBet`
- `reward_amount = totalWin`
- `remaining_amount = totalWin`
- `result_name` 汇总展示，例如：
  - `赤金符三连 ×12`
  - `星陨免费旋转 + 虎符三连`
  - `宝匣奖励 ×20`
  - `未中奖`

详细转轮结果不塞进 `result_name`。如果需要完整回放，建议把结果摘要写入后续新增 JSON 字段；第一阶段可以只返回给前端，不持久化完整回放。

### 第二版整体体验

玩家看到的是：

1. 选择兵种和单次押注。
2. 系统显示固定 5 条线和本局扣除。
3. 点击启动后，3 个轮子快速滚动。
4. 左轮先停，中轮后停，右轮最后停。
5. 停止后高亮中奖线。
6. 如果触发免费旋转，界面显示剩余免费次数并继续自动滚动。
7. 如果触发 Bonus，弹出短动画展示宝匣奖励。
8. 最终结果弹窗展示总奖励和库存入口。

## <span style="color:#8b5cf6">玩家流程</span>

1. 玩家进入 `万象幻境`。
2. 点击 `天机轮转`。
3. 选择押注兵种。
4. 选择押注数量。
5. 点击 `启动轮转`。
6. 前端请求后端结算接口。
7. 后端校验兵种与数量，扣除押注兵力。
8. 后端随机生成 3x3 转轮窗口。
9. 后端计算赔付线、Wild、Scatter、Bonus 和免费旋转。
10. 后端写入 `minigame_records`。
11. 后端返回最新军队、最终转轮窗口、中奖线、免费旋转和记录。
12. 前端播放转轮动画，最终停在后端返回的窗口。
13. 如果中奖，玩家可在 `天机库存` 中兑换奖励。

## <span style="color:#8b5cf6">押注规则</span>

### 允许押注的兵种

第二版只允许押注玩家本阵营的可战斗兵种。

校验方式：

- 必须存在于当前玩家阵营的兵种配置。
- 必须是玩家当前军队里已有的兵种。
- 不能是运输、商队、侦察或其他非战斗兵种。
- 复用后端 `validateAndConsumeArmy` 或同等核心校验逻辑。

### 押注数量

第二版采用“单次押注”规则，固定开启 5 条赔付线。

| 项 | 值 |
| --- | ---: |
| 单次最小押注 | 1,000 |
| 额外固定上限 | 无 |
| 单次押注上限 | 不能超过当前拥有的押注兵力 |

本局扣除：

```text
totalBet = lineBet
```

有效押注范围：

```text
lineBet >= 1,000
totalBet <= currentUnitAmount
```

如果当前兵种数量不足以支付 `lineBet`，该兵种不能以该金额启动天机轮转。

### 扣兵时机

点击启动后，后端在结算事务内立即扣除押注兵力。

规则：

- 输了：押注兵力不返还。
- 赢了：押注兵力也不返还，但发放本局累计中奖数量的可兑换库存。
- 前端必须使用后端返回的 `army` 更新玩家当前军队。

## <span style="color:#8b5cf6">转轮规则</span>

第二版使用 3 轮、3 行、5 条固定赔付线。

每轮最终停下后显示 3 个图案，三个轮子组成 3x3 窗口。后端按配置权重生成完整窗口，再计算横线、斜线、满天星、Wild、Scatter、Bonus 和免费旋转。

普通线奖励只计算 3 格连线结果；两个相同不中奖。满天星按全屏同类数量触发。Scatter 和 Bonus 按“任意位置 3 个”触发，不要求位于同一条赔付线。

## <span style="color:#8b5cf6">图案与倍率</span>

第二版配置如下：

| 图案 ID | 显示名 | 类型 | 稀有度 | 单格权重 | 连线倍率 | 说明 |
| --- | --- | --- | --- | ---: | ---: | --- |
| `bronze_charm` | 玄铜符 | 普通 | 普通 | 30 | ×3 | 小奖 |
| `silver_charm` | 白银符 | 普通 | 稀有 | 22 | ×6 | 稳定奖 |
| `gold_charm` | 赤金符 | 普通 | 稀有 | 16 | ×12 | 中等奖 |
| `jade_seal` | 玉玺 | 普通 | 史诗 | 10 | ×30 | 大奖 |
| `tiger_tally` | 虎符 | 普通 | 史诗 | 6 | ×80 | 特大奖 |
| `heaven_order` | 天命令 | 普通 | 传说 | 2 | ×250 | 头奖 |
| `wild` | 天机令 | Wild | 史诗 | 5 | ×250 | 大小王，补齐普通/星陨/宝匣 |
| `scatter` | 星陨 | Scatter | 史诗 | 4 | - | 任意 3 个触发免费旋转 |
| `bonus` | 宝匣 | Bonus | 稀有 | 5 | - | 任意 3 个触发奖励局 |

总权重为 100。

说明：

- 普通图案按 5 条赔付线逐条计算。
- Wild 可以替代普通图案，也可以补齐满天星、Scatter 和 Bonus 的触发条件。
- Scatter 和 Bonus 不按普通线倍率赔付，但可被 Wild 补齐触发各自机制。
- 具体理论返奖率需要按 3x3、多线、满天星、Wild、Scatter、Bonus 和免费旋转联合模拟后再定，不在文档中手算固定值。

## <span style="color:#8b5cf6">中奖奖励</span>

奖励兵种第二版固定为押注兵种。

示例：

- 玩家选择 `骁骑营`，单次押注 `10,000`
- 本局扣除为 `10,000`
- 中横线结果为 `赤金符 / 赤金符 / 赤金符`
- 赤金符连线倍率为 ×12
- 该线奖励为 `10,000 × 12 = 120,000`
- 如果同局还有其他中奖线、满天星、Scatter 免费旋转或 Bonus 奖励，继续累加到本局总奖励

输局记录也要写入 `minigame_records`，但：

- `reward_unit = ''`
- `reward_amount = 0`
- `remaining_amount = 0`

中奖记录：

- `reward_unit = 押注兵种中文名`
- `reward_amount = 本局累计中奖数量`
- `remaining_amount = reward_amount`

## <span style="color:#8b5cf6">数据模型</span>

复用 `minigame_records`。

字段使用约定：

| 字段 | 天机轮转写入规则 |
| --- | --- |
| `game_type` | 固定为 `slot` |
| `result_name` | 例如 `赤金符三连 ×12`、`星陨免费旋转 + 虎符三连`、`未中奖` |
| `rarity` | 根据中奖图案写入 `common` / `rare` / `epic` / `legendary`，输局写 `common` |
| `reward_unit` | 中奖时为押注兵种中文名，输局为空 |
| `reward_amount` | 中奖数量，输局为 0 |
| `remaining_amount` | 可兑换数量，中奖时等于 `reward_amount`，输局为 0 |
| `bet_unit` | 押注兵种中文名 |
| `bet_amount` | 本局扣除数量，即 `lineBet` |
| `created_at` | 后端结算时间 |

第二版不新增表。

如果后续要做排行榜、每日限额、保底、累计奖池，再新增专用模块状态表。

| 单次押注超过当前兵力 | 422 | `押注兵力不足` |
| 同一存档操作过快 | 429 | `操作太快，请稍后再试` |

### 禁止旧上报接口

`POST /api/v1/minigame/record` 不能接受 `gameType = slot`。

原因：

- 天机轮转必须后端结算。
- 不允许前端伪造图案、倍率或中奖记录。

## <span style="color:#8b5cf6">后端实现要求</span>

建议新增文件：

- `go/internal/app/game/service_slot.go`
- `go/internal/transport/api/handlers_slot.go` 或继续放入 `handlers_minigame.go`
- 如需要配置化，新增 `go/config/slot.json` 和 `slot_config.go`

核心服务方法建议：

```go
func (s *Service) ResolveSlotRound(playerID string, betUnitType string, lineBet int) (SlotRoundResult, error)
```

实现步骤：

1. 清理并校验 `playerID`、`betUnitType`、`lineBet`。
2. 获取玩家级互斥锁，避免同存档连点并发结算。
3. 使用 `UpdateMiniGamePlayerState` 或等价玩家资产事务。
4. 事务内读取权威军队。
5. 计算 `totalBet = lineBet`。
6. 校验单次押注下限，并确认当前兵力足以支付本局押注。
7. 使用核心出兵校验扣除单次押注兵力。
8. 使用后端随机数生成 3x3 主转轮窗口。
9. 计算 5 条赔付线、满天星、Wild 替代、Scatter、Bonus。
10. 如触发免费旋转，在同一次结算内展开免费旋转，最多 20 次。
11. 计算总奖励 `totalWin`。
12. 生成 `MiniGameRecord` 并插入记录列表。
13. 设置 `state.ServerTime`。
14. 事务提交后返回 `army`、`record`、`grid`、`winningLines`、`freeSpins`、`bonusRewards` 和结果信息。

随机数要求：

- 第二版可以使用 `crypto/rand`。
- 不允许使用前端随机。
- 不允许请求中传入图案或随机种子。
- 后端必须返回完整最终网格，前端动画只负责视觉过程。

### 前端结算流程

1. 玩家点击启动。
2. 前端禁用按钮，显示 `结算中...`。
3. 调用 `gameApi.resolveSlotRound`。
4. 收到后端结果后，开始播放转轮动画。
5. 动画最终停在后端返回的 `grid`。
6. 调用 `patchState({ army, serverTime })`。

- 自己随机最终图案。
- 自己判断是否中奖。
- 自己计算奖励并上报。
- 直接调用 `/minigame/record` 写 `slot` 记录。

### 滚动动画要求

第二版必须有明显的 3 轮滚动效果，不能只闪一下结果。

布局要求：

- 画面中间是 3 个竖向轮子。
- 每个轮子有 3 个可视格。
- 三个轮子组成 3x3 窗口。
- 每个格子使用统一尺寸，避免滚动中布局跳动。
- 手机端保持 3x3 结构，但整体缩小，不横向溢出。

动画流程：

1. 请求后端前，按钮进入 `结算中...`。
2. 收到后端结果后，轮子进入高速滚动。
3. 左轮先停，中轮后停，右轮最后停。
4. 停轮间隔建议：
   - 左轮：1.2 秒
   - 中轮：1.7 秒
   - 右轮：2.3 秒
5. 停轮前 300ms 做减速效果。
6. 停下时轻微回弹一次。
7. 最终 3x3 图案必须和后端 `grid` 完全一致。

视觉表现：

- 滚动中可以循环显示随机图案，但只能作为过程动画。
- 最终停靠结果不能由前端随机决定。
- 中奖线停稳后高亮，对应 `winningLines.positions`。
- Scatter 触发时，所有 `scatter` 格子发光。
- Bonus 触发时，`bonus` 格子弹出短促光效。
- 免费旋转时显示剩余免费次数，并自动继续滚动。

交互限制：

- 滚动期间禁用再次启动。
- 滚动期间可以打开库存，但不能再次结算。
- 如果接口失败，不播放最终结果，只提示错误并恢复按钮。
- 如果动画中途组件卸载，需要清理定时器。

实现建议：

- 不需要引入大型动画库，CSS transition + requestAnimationFrame 足够。
- 每个轮子可以渲染一列较长的图案 strip，通过 `transform: translateY(...)` 滚动。
- 停靠时把 strip 的最后 3 格替换或对齐为后端返回的该列结果。
- 动画状态与结算状态分开：`resolving` 表示接口进行中，`spinning` 表示动画播放中。

## <span style="color:#8b5cf6">上线注意事项</span>

第二版不需要数据迁移。

原因：

- `minigame_records.game_type` 是字符串，支持新玩法类型。
- 新玩法没有历史记录需要回填。
- 复用现有库存兑换体系。

上线前必须确认：

- 新接口已部署。
- 前端已改为调用后端结算。
- `gameType=slot` 已禁止走旧上报接口。
- 线上 `minigame_records.reward_amount` 是 `INT`，所以单局最大奖励不能超过 2,147,483,647。
- 第二版不设置额外押注上限，实际可押注数量受当前兵力约束。
- 由于押注不设额外上限，极端奖励可能随玩家兵力上升而扩大，后端必须保留 `reward_amount` 上限保护。
- 后端仍应在写库前做 `reward_amount` 上限保护，超过 `2,147,000,000` 时直接拒绝或截断为配置上限；建议第二版实现为拒绝并记录错误日志。
