# <span style="color:#f59e0b">Hero3 物品配置开发文档</span>

最后更新：2026-06-29

## <span style="color:#f59e0b">1. 文档定位</span>

本文档定义 Hero3 物品配置系统的第一版设计，用于指导后续背包、道具、玩法掉落、奖励池、Admin 配置和物品流水开发。

物品系统属于游戏核心资产的一部分，但具体物品效果、掉落来源和玩法产出应通过配置、奖励和 Effect Pipeline 接入，不允许玩法模块硬编码发放具体物品。

第一版目标：

- 标准化物品配置字段。
- 明确物品品质、颜色和使用确认规则。
- 明确物品效果必须走 Effect Pipeline。
- 明确掉落配置通过物品 ID 或奖励池引用。
- 支持背包容量、堆叠上限拆分和物品流水。
- 为 Admin 后台物品管理预留结构。

## <span style="color:#f59e0b">2. 和钓鱼品质的关系</span>

当前钓鱼系统已有 4 档稀有度：

```text
common      普通   灰色
rare        稀有   蓝色
epic        史诗   紫色
legendary   传说   金色
```

物品系统可以在钓鱼基础上再往上加一档，形成 5 档品质：

```text
common      普通   灰色
rare        稀有   蓝色
epic        史诗   紫色
legendary   传说   金色
mythic      神话   红金 / 彩色
```

说明：

- 物品品质字段统一使用 `quality`。
- 颜色和光效由前端根据 `quality` 统一映射。
- 不同系统可以有自己的表现，但品质枚举应尽量统一。
- 史诗及以上物品使用时需要二次确认。

第一版推荐颜色：

```text
common      普通   slate / gray
rare        稀有   blue
epic        史诗   purple
legendary   传说   amber / gold
mythic      神话   rose-gold / red-gold
```

## <span style="color:#f59e0b">3. 物品配置总原则</span>

物品配置只回答三件事：

```text
这个物品是什么
这个物品能不能使用
这个物品使用后触发什么效果
```

玩法掉落不写在物品本体里。

正确关系：

```text
items.json        定义物品
drop_pools.json   定义掉落池
玩法配置          引用物品 ID 或掉落池 ID
Effect Pipeline   统一执行效果
```

允许后续继续扩展字段。新增字段必须遵守：

- 不破坏旧配置读取。
- 有默认值。
- 能被 Admin 展示或编辑。
- 不让玩法绕过 Reward / Effect Pipeline。

## <span style="color:#f59e0b">4. 物品基础字段</span>

标准结构：

```json
{
  "id": "resource_pack_small",
  "name": "小资源包",
  "description": "使用后获得少量资源。",
  "category": "resource_pack",
  "quality": "common",
  "icon": "resource_pack",
  "usable": true,
  "stackable": true,
  "maxStack": 999,
  "bindType": "bound",
  "useTarget": "self",
  "confirmOnUse": "auto",
  "effects": [],
  "metadata": {}
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `id` | 物品唯一 ID，稳定不改 |
| `name` | 中文名称 |
| `description` | 中文描述 |
| `category` | 物品分类 |
| `quality` | 品质 |
| `icon` | 图标 key |
| `usable` | 是否可使用 |
| `stackable` | 是否可堆叠 |
| `maxStack` | 单格最大堆叠 |
| `bindType` | 绑定规则 |
| `useTarget` | 使用目标 |
| `confirmOnUse` | 使用确认规则 |
| `effects` | 使用效果 |
| `metadata` | 扩展字段 |

## <span style="color:#f59e0b">5. 物品分类</span>

第一版推荐分类：

```text
resource_pack    资源包
general_exp      武将经验
recruit_ticket   征募券
buff_item        增益道具
pvp_item         PVP 道具
ticket           门票 / 入场券
material         材料
chest            宝箱
token            功能凭证
currency_pack    货币包
event_item       活动物品
equipment        装备
equipment_set    装备套装标识，套装系统使用
```

当前已有物品建议归类：

```text
general_exp_small / medium / large  -> general_exp
resource_pack_small / medium / large -> resource_pack
recruit_ticket_small                 -> recruit_ticket
pvp_truce_8h                         -> pvp_item
general_change_card                  -> token
```

暂时只预留、不配置：

```text
fragment         碎片
```

装备说明：

- 装备属于物品体系的正式分类。
- 装备可以先作为不可使用或特殊使用物品进入背包。
- 装备穿戴、属性生效、卸下、强化、洗练等不直接塞进第一版物品使用逻辑。
- 装备套装系统应作为独立模块设计，通过标准装备字段和 Effect / Modifier 管线接入核心。
- 套装效果不应由普通物品使用流程触发，而应由装备穿戴状态计算触发。

### <span style="color:#f59e0b">5.1 装备和套装系统理解</span>

装备是物品的一类，但装备系统不是普通消耗品系统。

物品系统负责：

```text
装备定义
装备品质
装备图标
装备是否可堆叠
装备是否绑定
装备在背包中的存放
装备获得和消耗流水
```

装备系统负责：

```text
装备穿戴
装备卸下
装备槽位
装备属性
装备强化
装备洗练
装备锁定
装备分解
```

套装系统负责：

```text
套装 ID
套装件数
套装激活条件
套装属性加成
套装特殊效果
套装展示
```

边界规则：

- 装备可以作为 `equipment` 类型物品进入背包。
- 套装可以通过 `equipment_set` 或装备配置中的 `setId` 字段表达。
- 普通 `UseItem` 不负责装备穿戴。
- 装备穿戴应有独立接口，例如 `POST /api/v1/equipment/equip`。
- 套装效果根据当前已穿戴装备动态计算。
- 套装加成必须进入 Modifier 管线，不应直接改玩家长期属性。
- 装备获得、分解、强化消耗等资产变化仍应走 Reward / Effect / 物品流水。
- 第一版物品配置只为装备和套装预留字段，不实现完整装备系统。

装备配置示例：

```json
{
  "id": "weapon_qinggang_sword",
  "name": "青釭剑",
  "description": "名剑，适合武将装备。",
  "category": "equipment",
  "quality": "legendary",
  "icon": "weapon_sword_gold",
  "usable": false,
  "stackable": false,
  "maxStack": 1,
  "bindType": "bound",
  "useTarget": "equipment_slot",
  "equipment": {
    "slot": "weapon",
    "setId": "set_tiger_general",
    "attributes": {
      "attack": 120,
      "marchSpeed": 0.02
    }
  },
  "effects": [],
  "metadata": {}
}
```

套装配置后续应放在独立配置中，例如：

```json
{
  "set_tiger_general": {
    "id": "set_tiger_general",
    "name": "虎将套装",
    "pieces": {
      "2": [
        { "type": "modifier", "key": "attackBonus", "value": 0.05 }
      ],
      "4": [
        { "type": "modifier", "key": "marchSpeedBonus", "value": 0.08 }
      ]
    }
  }
}
```

## <span style="color:#f59e0b">6. 使用确认规则</span>

`confirmOnUse` 可选：

```text
auto    自动判断
always  永远确认
never   不确认
```

第一版规则：

- 默认 `confirmOnUse = auto`。
- `quality = epic / legendary / mythic` 时需要二次确认。
- `quality = common / rare` 不需要二次确认。
- `confirmOnUse = always` 时无论品质都确认。
- `confirmOnUse = never` 时无论品质都不确认，但不建议给高品质物品使用。

用户确认规则：

```text
史诗以上确认。
```

## <span style="color:#f59e0b">7. 背包容量和堆叠</span>

背包容量：

```text
9999 格
```

堆叠规则：

- 单格数量不能超过物品 `maxStack`。
- `stackable = false` 时 `maxStack = 1`。
- 获得物品时，优先补满已有同物品堆叠。
- 超出单格上限时拆成多个堆叠。
- 背包剩余格子不足时，奖励发放必须失败或进入待领取状态，不能吞物品。

示例：

```text
物品 maxStack = 999
玩家获得 2500 个
应拆为 999 + 999 + 502 三格
```

## <span style="color:#f59e0b">8. Effect Pipeline 接入</span>

物品效果必须走 Effect Pipeline。

第一版支持效果：

```text
resources          资源
item               发物品
general_exp        当前武将经验
unit_by_faction    按阵营发兵
random_unit_by_faction_category  随机本阵营基础分类兵种
all_units_by_faction_category    发放本阵营全部基础分类兵种
buff               Buff / 加成
pvp_protection     PVP 免战
currency           城金 / 金币
random_reward      随机奖励池
choice_reward      自选奖励，后续
unlock             解锁类，后续
```

资源包示例：

```json
{
  "type": "resources",
  "resources": {
    "wood": 1000,
    "stone": 1000,
    "iron": 1000,
    "food": 1000
  }
}
```

按阵营发兵示例：

```json
{
  "type": "unit_by_faction",
  "amount": 50,
  "unitByFaction": {
    "wei": "qingZhouArmy",
    "shu": "greedyWolf",
    "wu": "shadowGuard"
  }
}
```

随机基础分类兵种示例：

```json
{
  "type": "random_unit_by_faction_category",
  "category": "infantry",
  "amount": 5000
}
```

随机全部特殊作战兵示例：

```json
{
  "type": "random_unit_by_faction_category",
  "category": "special",
  "pool": "all",
  "amount": 10000
}
```

全部基础分类兵种示例：

```json
{
  "type": "all_units_by_faction_category",
  "category": "cavalry",
  "amount": 15000
}
```

默认基础分类兵种只取对应分类中最低解锁等级的作战兵，排除侦察、商人和运输等功能兵。`pool = all` 时会使用该分类全部非功能作战兵，当前用于特殊征召令的特殊兵种二选一。

免战令示例：

```json
{
  "type": "pvp_protection",
  "protectionType": "manual",
  "durationSeconds": 28800
}
```

## <span style="color:#f59e0b">9. 掉落和奖励引用</span>

玩法掉落应引用物品或掉落池。

不推荐：

```text
副本代码里硬编码发 resource_pack_small
```

推荐：

```text
副本配置引用 dropPoolId
掉落池配置引用 itemId
奖励系统按配置发放
```

掉落池示例：

```json
{
  "dungeon_001_normal": {
    "rolls": 1,
    "items": [
      { "type": "item", "id": "resource_pack_small", "amount": 1, "weight": 6000 },
      { "type": "item", "id": "general_exp_small", "amount": 1, "weight": 3000 },
      { "type": "item", "id": "recruit_ticket_small", "amount": 1, "weight": 1000 }
    ]
  }
}
```

独立槽位示例：

```json
{
  "npc_large_exp_pack": {
    "id": "npc_large_exp_pack",
    "slots": [
      {
        "items": [
          { "type": "item", "id": "general_exp_medium", "amount": 1, "weight": 10000 }
        ]
      },
      {
        "items": [
          { "type": "item", "id": "general_exp_large", "amount": 1, "weight": 500 },
          { "type": "none", "id": "none", "weight": 9500 }
        ]
      }
    ]
  }
}
```

说明：

- `rolls + items` 表示从同一个权重表中抽取指定次数。
- `slots` 表示多个独立掉落槽位，每个槽位各抽一次；槽位里也可以配置 `rolls`。
- `none` 表示该槽位落空，用于配置概率掉落。例如 `500 + 9500` 等于 5% 掉落。
- 掉落物品的名称、品质和高亮颜色来自 `items.json` 中对应物品配置。
- GM 后台“物品配置”页提供掉落池表单编辑区，可新建掉落池、维护独立槽位、选择物品或空掉落、填写数量和权重，并保留高级 JSON 用于排查和批量修改。
- NPC 城池后台可在每个层级填写 `dropPoolId`，保存时后端会校验该掉落池存在。

玩法配置示例：

```json
{
  "dungeon_001": {
    "clearRewards": [
      { "type": "item", "id": "resource_pack_small", "amount": 1 }
    ],
    "dropPoolId": "dungeon_001_normal"
  }
}
```

## <span style="color:#f59e0b">10. 物品流水</span>

必须补物品流水。

用途：

- 查询物品来源。
- 排查发放、消耗、掉落异常。
- 支持 GM 回溯。
- 支持未来交易审计。

字段建议：

```text
id
player_id
item_id
change_amount
before_amount
after_amount
reason
ref_type
ref_id
metadata_json
created_at
```

原因枚举：

```text
admin_grant
mail_claim
item_use
drop_reward
dungeon_reward
pvp_reward
stronghold_reward
npc_reward
repair
```

## <span style="color:#f59e0b">11. 配置校验</span>

物品系统必须提供配置校验能力。校验可以由后端启动时执行，也可以由 Admin 保存配置时执行，后续还可以提供 dbtool 或配置检查命令。

### <span style="color:#f59e0b">11.1 物品配置校验</span>

必须校验：

- `id` 非空且全局唯一。
- `id` 只能包含小写英文、数字和下划线。
- `name` 非空。
- `category` 必须是合法分类。
- `quality` 必须是合法品质。
- `maxStack` 必须大于 0。
- `stackable = false` 时 `maxStack` 必须为 1。
- `usable = false` 时不应配置普通使用效果；装备、材料、凭证等特殊类型除外。
- `usable = true` 时必须至少有一个合法 `effect`。
- 史诗及以上品质默认需要二次确认，除非明确配置 `confirmOnUse = never`，但该情况需要 Admin 明确提示风险。
- `effects` 中引用的资源、兵种、Buff、物品、货币类型必须存在。
- `unit_by_faction` 必须覆盖魏、蜀、吴三个阵营，或明确声明只对部分阵营可用。
- `pvp_protection` 必须配置合法保护类型和正数持续时间。
- `random_reward` 必须引用存在的掉落池。

### <span style="color:#f59e0b">11.2 掉落池校验</span>

掉落池必须校验：

- `id` 非空且全局唯一。
- 未配置 `slots` 时，`rolls` 必须大于 0，`items` 不能为空。
- 配置 `slots` 时，每个槽位的 `items` 不能为空；槽位 `rolls` 不填时默认 1 次。
- 每个掉落项的 `weight` 必须大于 0。
- 掉落项引用的 `itemId` 必须存在。
- 非 `none` 掉落项数量 `amount` 必须大于 0。
- `none` 只用于空掉落占位，不发放物品。
- 同一个掉落池内允许重复物品，但必须明确是否合并展示。
- 掉落池总权重必须大于 0。
- 掉落池不能循环引用自身或形成循环引用链。

### <span style="color:#f59e0b">11.3 Admin 保存校验</span>

Admin 新建或编辑物品时，必须在保存前校验：

- ID 格式。
- ID 唯一。
- 分类和品质合法。
- 效果配置合法。
- 掉落池引用合法。
- 史诗以上物品使用确认规则。

校验失败时，前端应展示明确中文错误，不允许保存半成品配置。

## <span style="color:#f59e0b">12. Admin 后台</span>

第一版 Admin 能力：

- 查看物品配置。
- 新建/编辑物品配置。
- 校验配置合法性。
- GM 给玩家发物品。
- 查看玩家背包。
- 查看物品流水。

### <span style="color:#f59e0b">12.1 GM 新增物品流程</span>

第一版 GM 可以通过后台添加物品，但物品 ID 必须是稳定可读配置 ID，不使用随机 ID。

推荐流程：

```text
1. 选择物品分类
2. 选择物品品质
3. 系统根据分类自动补全 ID 前缀
4. GM 填写物品名称
5. GM 填写或调整 ID 后缀
6. 系统预览完整 itemId
7. GM 填写描述、图标、堆叠、使用目标和效果
8. 保存时校验
9. 保存后 itemId 锁定，不允许随意修改
```

示例：

```text
分类：资源包 resource_pack
品质：普通 common
名称：小资源包
系统前缀：resource_pack_
GM 填写后缀：small
最终 ID：resource_pack_small
```

再例如：

```text
分类：PVP 道具 pvp_item
品质：稀有 rare
名称：8 小时免战令
系统前缀：pvp_
GM 填写后缀：truce_8h
最终 ID：pvp_truce_8h
```

ID 规则：

```text
只能使用小写英文、数字和下划线
必须全局唯一
保存后不可改
被掉落池、邮件、活动、副本或玩家背包引用后不可硬删除
```

分类到 ID 前缀建议：

```text
resource_pack  -> resource_pack_
general_exp    -> general_exp_
recruit_ticket -> recruit_ticket_
buff_item      -> buff_
pvp_item       -> pvp_
ticket         -> ticket_
material       -> material_
chest          -> chest_
token          -> token_
currency_pack  -> currency_pack_
event_item     -> event_
equipment      -> equipment_
```

系统自动补全前缀，但 GM 可以填写后缀。这样既方便创建，也保证后续掉落池、邮件、活动和代码引用稳定。

配置编辑第一版可以先支持常用字段：

```text
id
name
description
category
quality
usable
stackable
maxStack
useTarget
confirmOnUse
effects
```

复杂 `metadata` 和高级效果可先提供 JSON 编辑。

## <span style="color:#f59e0b">13. 第一版不做</span>

暂不做：

- 玩家交易。
- 拍卖行。
- 装备穿戴。
- 物品强化。
- 装备套装系统。
- 自选礼包完整交互。
- 限时过期物品。
- 跨服物品。

这些后续可以继续扩展，但不能破坏当前标准配置结构。

## <span style="color:#f59e0b">14. 第一版验收标准</span>

- 物品配置支持 5 档品质。
- 前端按品质显示颜色。
- 史诗以上物品使用时二次确认。
- 普通和稀有物品使用时不二次确认。
- 背包以格子形式展示。
- 背包容量上限为 9999。
- 堆叠上限真实生效。
- 超过堆叠上限时自动拆分。
- 使用物品走 Effect Pipeline。
- 掉落配置通过物品 ID 或掉落池引用。
- Admin 可以查看、新建、编辑、校验和发放物品。
- Admin 编辑物品配置时必须保存前校验，已被引用的物品 ID 不允许修改。
- 物品获得和消耗写入物品流水。
- Admin 可以查看物品流水，并按玩家、物品 ID、来源和时间范围筛选。
- 物品配置保存前必须校验。
- 后端启动或配置加载时必须校验物品配置。
- 掉落池引用的物品 ID 必须存在。
- 掉落池权重、次数和数量必须合法。
- 配置校验失败时必须返回明确中文错误。

## <span style="color:#f59e0b">15. 当前落地状态</span>

截至 2026-06-29，本轮已落地第一版物品配置系统主体能力：

- `items.json` 已升级为 `category`、`quality`、`confirmOnUse` 标准字段，并保留旧 `type`、`rarity` 读取兼容。
- 后端启动和 Admin 保存物品配置时会执行中文错误配置校验。
- 物品品质支持 `common`、`rare`、`epic`、`legendary`、`mythic` 五档。
- 玩家端背包使用 `inventorySlots` 格子展示，兼容 `inventory` 聚合数量。
- 背包容量按 9999 格限制，获得物品会按 `maxStack` 自动拆分堆叠。
- 物品使用仍走 Effect Pipeline，物品发物品、资源、兵力、武将经验、货币、Buff 和 PVP 免战均通过标准入口处理。
- 新增 `drop_pools.json` 掉落池配置和校验入口，玩法后续应引用掉落池或物品 ID。
- 新增 `item_ledger` 物品流水，记录获得、消耗、来源、前后数量和时间。
- Admin 后台配置页已提供物品配置 JSON 校验/保存、分类 + 品质 + ID 前缀/后缀的表单式新增/编辑、玩家背包格子查询和物品流水筛选。
- Admin 表单新增物品时按分类自动补全 ID 前缀；编辑已有物品时锁定 ID，后端保存也禁止删除已有物品 ID。

仍需后续单独设计或接入的范围：

- 装备穿戴、装备强化、套装系统仍未实现，保持独立模块边界。
- 复杂自选礼包交互、限时物品、交易和拍卖行仍不在第一版范围。
