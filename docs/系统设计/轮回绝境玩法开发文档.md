# <span style="color:#7c3aed">Hero3 轮回绝境玩法开发文档</span>

最后更新：2026-06-29

## <span style="color:#7c3aed">1. 文档定位</span>

本文档定义 Hero3 副本玩法「轮回绝境」的最终设计，用于指导后续后端、前端、数据库、GM 后台、战报、奖励和物品掉落接入开发。

轮回绝境是一个玩家主动开启、限时完成、真实消耗兵力、18 波攻防交替的副本玩法。

它不是普通 NPC 城池，也不是 PVP。它是独立玩法模块，必须通过标准核心能力接入：

```text
战斗计算       复用核心战斗能力或副本专用战斗规则入口
兵力扣减       通过军事/玩家资产标准入口
奖励发放       走 Reward / Effect Pipeline
物品掉落       引用 itemId 或 dropPoolId
战报           走标准战报系统
玩法状态       使用副本自身状态表或通用玩法模块表承载
GM 配置        可配置层级、波次、时间、加成、奖励和掉落池
```

## <span style="color:#7c3aed">2. 玩法一句话</span>

玩家选择一个轮回层级，开启 2 小时限时挑战，在 18 波进攻、防守交替的轮回中根据每波随机提示搭配兵种，承受真实战损，完成全部波次后获得累计奖励。

## <span style="color:#7c3aed">3. 核心规则</span>

基础规则：

```text
玩家主动开启
默认持续 2 小时，GM 可配置
一共 18 波
奇数波为进攻波
偶数波为防守波
2 小时内通过 18 波即通关
超时未通关则结束
防守波失败则结束
真实消耗玩家兵力
每波通过后奖励进入累计奖励池
副本结束后发放已累计奖励
```

不参与内容：

```text
武将暂不参与
装备暂不参与
套装暂不参与
PVP 保护期不参与
普通 PVP 掠夺不参与
```

## <span style="color:#7c3aed">4. 轮回层级</span>

玩家开启轮回绝境前选择轮回层级。层级决定本次 18 波的整体兵力规模和奖励上限。

不是每波有自己的等级，而是本次副本实例有一个固定层级。

层级建议：

| 层级 | 每波兵力规模 | 说明 |
| --- | ---: | --- |
| 1 级 | 1 万左右 | 入门轮回 |
| 2 级 | 10 万左右 | 初级轮回 |
| 3 级 | 100 万左右 | 中级轮回 |
| 4 级 | 1000 万左右 | 高级轮回 |
| 5 级 | 1 亿左右 | 绝境轮回 |
| 6 级 | 10 亿左右 | 无间轮回 |
| 7 级 | 100 亿左右 | 归墟轮回 |

示例：

```text
玩家开启 3 级轮回绝境
本次 18 波每波敌方总量都围绕 100 万规模
每波敌方阵营、兵种搭配和加成都不同
玩家每波可投入任意数量的真实可用兵力
```

GM 可配置：

```text
level
name
wavePowerBase
playerTroopCap（旧客户端兼容字段，不再参与出兵校验）
enemyTroopBase
durationSeconds
rewardExpCap
enabled
```

## <span style="color:#7c3aed">5. 波次结构</span>

轮回绝境固定 18 波。

波次类型：

```text
奇数波：进攻波
偶数波：防守波
```

每波生成：

```text
波次编号
波次类型
敌方阵营
敌方兵种搭配
敌方兵力规模
敌方加成
己方加成
本波奖励池
本波出兵上限
```

每波敌方阵营可以不同。

示例：

```text
第 1 波：进攻波，敌方魏阵营，敌方青州军较多，己方贪狼营攻击 +40%，敌方虎豹骑防御 +30%
第 2 波：防守波，敌方吴阵营，敌方影卫较多，己方青州军防御 +35%，敌方神风攻击 +25%
```

## <span style="color:#7c3aed">6. 每波随机加成</span>

第一版每波生成 2 个主要加成：

```text
己方 1 个加成
敌方 1 个加成
```

进攻波：

```text
己方随机某个兵种攻击加成
敌方随机某个兵种防御加成
```

防守波：

```text
己方随机某个兵种防御加成
敌方随机某个兵种攻击加成
```

示例：

```text
进攻波：
己方贪狼营攻击 +40%
敌方虎豹骑防御 +30%

防守波：
己方青州军防御 +35%
敌方神风攻击 +25%
```

加成必须在波次开始前明确展示给玩家。

后续预留：

```text
一波多个己方加成
一波多个敌方加成
全兵种加成
阵营加成
分类加成
特殊事件加成
```

## <span style="color:#7c3aed">7. 进攻波规则</span>

进攻波由玩家主动派兵攻击敌方。

规则：

```text
玩家可分多次进攻
每次进攻真实扣除战损
敌方剩余兵力保留
打光敌方本波兵力后通过本波
通过后进入下一波
2 小时内未打光则可能超时结束
```

玩家每次出兵：

```text
选择兵种和数量
总投入不能超过本波出兵上限
不能超过玩家当前真实兵力
确认真实损耗提示
点击进攻
结算战斗
生成本轮战报或追加到本波战报
```

进攻波允许玩家先少量试探，再根据战报和剩余情况继续投入更多兵力。

## <span style="color:#7c3aed">8. 防守波规则</span>

防守波由敌方发起进攻，玩家配置防守兵力。

规则：

```text
玩家查看本波提示
玩家配置防守兵力
玩家点击防御就绪
系统进入 3 秒倒计时
倒计时结束后敌方进攻
结算战斗
守住则通过本波
守不住则本次轮回结束
```

防守波第一版一次性结算，不支持失败后补防。

防守失败：

```text
当前失败波奖励不进入累计奖励池
前面已经通过的波次奖励照常发放
本次轮回结束
```

## <span style="color:#7c3aed">9. 中途离开和继续</span>

轮回绝境开启后，2 小时倒计时持续运行。

玩家可以：

```text
离开副本页面
去打资源
去征兵
整理兵力
回到副本继续当前波次
```

限制：

```text
不能超过本次开启的结束时间
超时后不能继续挑战
同一玩家同一时间只能有一个进行中的轮回绝境实例
```

这个设计允许玩家发现某波缺少适合兵种后，出去补资源、征兵，再回来继续。

## <span style="color:#7c3aed">10. 真实损耗</span>

轮回绝境使用真实兵力损耗。

规则：

```text
玩家每次出兵从真实兵力中扣除或锁定
战斗结束后按战损扣除阵亡兵力
幸存兵力返还或解除锁定
防守波阵亡兵力真实扣除
敌方损耗只影响本次副本实例
```

必须提示：

```text
本玩法为真实兵力损耗
阵亡兵力不会返还
请确认后继续
```

第一版至少在开启副本和每次大量出兵时提供确认提示。

## <span style="color:#7c3aed">11. 战斗规则</span>

轮回绝境战斗规则可以与普通官方战斗规则不同。

第一版原则：

- 只围绕兵力、攻击、防御、步防、骑防、随机波次加成计算。
- 武将不参与。
- 装备不参与。
- 阵营和兵种配置参与。
- 每波加成直接影响指定兵种在本波的攻击或防御表现。

战斗输入：

```text
我方出战兵种与数量
敌方兵种与数量
波次类型
己方加成
敌方加成
兵种基础攻击
兵种基础防御
兵种步防
兵种骑防
```

战斗输出：

```text
我方损耗
敌方损耗
我方剩余
敌方剩余
是否通过本轮/本波
```

具体公式可以在开发阶段继续微调，但必须满足：

- 加成对玩家配兵选择有明显影响。
- 不允许玩家超过该层级本波上限出兵。
- 战损可解释。
- 战报能展示本波加成和损耗。

## <span style="color:#7c3aed">12. 奖励池规则</span>

每波都有奖励池。

波次开始前，前端展示本波可能获得的奖励池。

通过本波后：

```text
本波奖励进入本次轮回累计奖励池
不立即发放到背包
```

副本结束时：

```text
通关、失败或超时后
统一发放已累计奖励
```

防守波失败：

```text
发放前面已通过波次累计奖励
不发放当前失败波奖励
```

进攻波超时：

```text
发放已通过波次累计奖励
未通过波次奖励不发放
```

奖励发放必须走 Reward / Effect Pipeline。

## <span style="color:#7c3aed">13. 经验卡奖励设计</span>

轮回绝境主要奖励为将领经验卡。

当前规则按用户确认：

```text
小将领经验卡：1000 经验
中将领经验卡：50000 经验
大将领经验卡：200000 经验
```

注意：现有 `go/config/items.json` 中经验卡数值可能仍是旧值，最终以物品配置为准。轮回绝境只引用物品 ID，不直接决定物品效果。

建议 itemId：

```text
general_exp_small
general_exp_medium
general_exp_large
```

层级顶格经验预算：

```text
本层级每波兵力规模 × 最高口粮 × 经验换算倍率
```

示例：

```text
3 级轮回：每波约 100 万兵
最高口粮兵：6 口粮
顶格经验预算：100 万 × 6 = 600 万经验
大将领经验卡：20 万经验
单波顶格约 30 张大将领经验卡
```

这里的 30 张是理论顶格，不代表每波必给。实际每波奖励由 GM 配置的波次系数、随机倍率、固定奖励和掉落池决定。

## <span style="color:#7c3aed">14. 波次奖励配置</span>

每波奖励由配置决定。

推荐配置字段：

```text
waveIndex
rewardPreview
expBudgetRate
expRandomMin
expRandomMax
fixedRewards
dropPoolId
```

经验预算公式：

```text
本波经验预算 = 层级顶格经验预算 × expBudgetRate × 随机倍率
```

随机倍率：

```text
expRandomMin ~ expRandomMax
```

示例：

```json
{
  "waveIndex": 7,
  "expBudgetRate": 0.08,
  "expRandomMin": 0.8,
  "expRandomMax": 1.2,
  "fixedRewards": [
    { "type": "item", "id": "general_exp_medium", "amount": 2 }
  ],
  "dropPoolId": "reincarnation_level_3_wave_7"
}
```

掉落池示例：

```json
{
  "id": "reincarnation_level_3_wave_7",
  "rolls": 1,
  "items": [
    { "type": "item", "id": "resource_pack_medium", "amount": 1, "weight": 5000 },
    { "type": "item", "id": "general_exp_small", "amount": 5, "weight": 3000 },
    { "type": "item", "id": "general_exp_medium", "amount": 1, "weight": 1000 }
  ]
}
```

物品内容由物品配置决定，轮回绝境只引用 ID。

## <span style="color:#7c3aed">15. 累计奖励</span>

本次轮回实例必须保存累计奖励。

状态字段建议：

```text
pending_rewards_json
cleared_wave_rewards_json
reward_claim_status
reward_granted_at
```

规则：

- 每通过一波，把该波奖励合并进 `pending_rewards_json`。
- 副本结束时发放 `pending_rewards_json`。
- 发放成功后标记已发放。
- 重复结算不能重复发奖励。

## <span style="color:#7c3aed">16. 战报规则</span>

轮回绝境接入标准战报系统。

战报来源：

```text
sourceType = dungeon
```

进攻波：

```text
viewType = attack
battleType = dungeon_reincarnation_attack
primarySide = 玩家出战兵力
secondarySide = 本波敌军
extra.dungeon.dungeonId = reincarnation_abyss
extra.dungeon.waveIndex = 当前波次
extra.dungeon.level = 轮回层级
```

防守波：

```text
viewType = defense
battleType = dungeon_reincarnation_defense
primarySide = 本波敌军
secondarySide = 玩家防守兵力
extra.dungeon.dungeonId = reincarnation_abyss
extra.dungeon.waveIndex = 当前波次
extra.dungeon.level = 轮回层级
```

战报必须展示：

- 本波类型。
- 本波层级。
- 本波敌方阵营。
- 本波己方加成。
- 本波敌方加成。
- 我方出兵。
- 我方损耗。
- 敌方损耗。
- 本波是否通过。

## <span style="color:#7c3aed">18. GM 配置</span>

GM 后台需要支持：

- 配置轮回层级。
- 配置默认持续时间。
- 配置是否开启某个层级。
- 配置 18 波波次类型。
- 配置敌方阵营随机池。
- 配置敌方兵种搭配随机池。
- 配置己方加成随机池。
- 配置敌方加成随机池。
- 配置每波奖励预览。
- 配置每波固定奖励。
- 配置每波 dropPoolId。
- 配置经验预算系数。
- 查看玩家进行中的轮回实例。
- 强制结算异常实例。
- 补发或修复累计奖励。

## <span style="color:#7c3aed">20. 接口设计</span>

玩家接口：

```text
GET  /api/v1/dungeons/reincarnation/config
GET  /api/v1/dungeons/reincarnation/run
POST /api/v1/dungeons/reincarnation/start
POST /api/v1/dungeons/reincarnation/waves/{waveId}/attack
POST /api/v1/dungeons/reincarnation/waves/{waveId}/defense-ready
POST /api/v1/dungeons/reincarnation/waves/{waveId}/bonus-reset
POST /api/v1/dungeons/reincarnation/settle
GET  /api/v1/dungeons/reincarnation/reports
```

当前波次未产生战斗记录前，玩家可以通过 `bonus-reset` 消耗配置项 `bonusResetGoldCost` 对己方和敌方随机加成重新抽取；扣费走账户金币流水 `reincarnation_bonus_reset`。

GM 接口：

```text
GET  /api/v1/admin/dungeons/reincarnation/config
PUT  /api/v1/admin/dungeons/reincarnation/config
GET  /api/v1/admin/dungeons/reincarnation/runs
GET  /api/v1/admin/dungeons/reincarnation/runs/{runId}
POST /api/v1/admin/dungeons/reincarnation/runs/{runId}/force-settle
POST /api/v1/admin/dungeons/reincarnation/runs/{runId}/repair-reward
```

## <span style="color:#7c3aed">21. 幂等和事务</span>

必须保证：

- 同一玩家不能同时开启多个进行中轮回绝境。
- 进攻波同一次 attack 请求不能重复扣兵。
- 防守波 defense-ready 不能重复结算。
- 波次通过奖励不能重复加入累计奖励池。
- 副本结束奖励不能重复发放。
- 真实兵力扣减、敌方剩余写回、战报、奖励状态必须在事务中保持一致。

建议：

```text
每次战斗生成 battleId
请求可以携带 clientActionId
数据库唯一约束防重复
结算时锁 run、wave、玩家兵力资产
```

## <span style="color:#7c3aed">22. 第一版不做</span>

暂不做：

- 武将参与。
- 装备参与。
- 套装参与。
- 排行榜。
- 扫荡。
- 自动挑战。
- 多玩家协助。
- 复活。
- 购买额外时间。
- 跨服轮回。

## <span style="color:#7c3aed">23. 验收标准</span>

达到以下条件才算第一版完成：

- 玩家可以选择轮回层级并开启轮回绝境。
- 默认 2 小时倒计时可运行，且 GM 可配置。
- 一次轮回固定 18 波。
- 奇数波进攻、偶数波防守。
- 同一层级下每波围绕该层级兵力规模生成。
- 每波敌方阵营可以随机。
- 每波敌方兵种搭配不同。
- 每波显示己方加成和敌方加成。
- 进攻波允许多次进攻直到打光敌方。
- 防守波点击防御就绪后 3 秒倒计时并结算。
