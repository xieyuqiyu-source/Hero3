# 夏侯渊特性更新开发文档

## 1. 现行设计

### 疾行奔袭

- 类型：永久被动。
- 对象：夏侯渊实际率领的骁骑营 `qiQiYing`。
- 效果：每个骁骑营固定攻击 `+18`、移动 `+5`。
- 场景：主动进攻、守城、增援、NPC、黄巾和轮回中持续生效。
- 战报：不得写入特性触发时间线；参战将领快照和独立“被动生效”区域展示 `+18/+5`，战力使用攻击加成后的权威值。
- 行军：先对骁骑营基础移动 `14` 增加 `5`，混编部队再按所有参战兵种中的最慢移动计算时间。

### 盾阵防御

- 类型：战斗前概率特性。
- 方向：仅防守或增援，主动进攻无效。
- 默认概率：`60%`，由 GM 的 `triggerChance` 配置。
- 默认效果：所率全军步防、骑防增加 `30%`，由 GM 的 `defenseBonusRate` 配置。
- 结算：命中后先修改本方实际防御，再交给现有战斗核心重新计算战力、兵损、经验和剩余兵力。
- 战报：只在真实命中时记录设计概率、设计比例和逐兵种实际整数变化；未命中不补造结果。

## 2. 组合顺序

1. 构建夏侯渊所率军队时应用疾行奔袭的骁骑营固定属性。
2. 进入防守或增援战斗前，独立判定盾阵防御。
3. 盾阵命中时，以已经包含永久被动的军队快照增加防御。
4. 使用最终攻防和战前兵力进入原有战斗核心。

疾行奔袭没有概率判定，也不占用战斗触发顺序；盾阵防御不会在主动进攻中执行。

## 3. GM 与旧配置迁移

- 疾行奔袭公开 `unitAttackFlat`、`unitSpeedFlat` 两个固定值，不公开无意义的触发概率。
- 盾阵防御公开 `triggerChance`、`defenseBonusRate`。
- 旧 `speedBonusRate`、`minMarchSeconds` 和被动 `triggerChance` 会被删除，并迁移为攻击 `18`、移动 `5`、目标骁骑营。
- 旧盾阵“必定增加 35%”迁移为默认“60% 概率增加 30%”；已有明确新概率的 GM 自定义比例不被强制覆盖。

## 4. 验收矩阵

- 疾行奔袭：骁骑营攻击 `24 -> 42`，其他兵种不变；纯骁骑营行军使用移动 `14 -> 19`，混编仍受最慢兵种限制。
- 主动进攻：疾行奔袭改变真实战力、兵损和行军时间；盾阵不触发。
- 防守与增援：盾阵分别覆盖命中和未命中；命中后战报、战力、兵损和权威剩余兵力一致。
- 战报：疾行奔袭只出现在被动区域和拥有快照；盾阵只出现在真实命中的触发区域。
- 配置：正式 JSON、注册表默认值、GM schema 和旧配置归一化一致。
- 工程：后端全量测试、概率/方向专项测试、`web` 与 `web-wlsg` 测试和构建、Chrome 页面检查、`git diff --check` 全部通过。
