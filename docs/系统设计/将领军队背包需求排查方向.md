# 将领军队背包需求排查方向

最后更新：2026-06-30

## 1. 文档用途

本文档用于交给 AI 或开发者对当前 Hero3 项目进行一次需求排查和代码 Review。

本次不要求直接开发，而是要求先确认以下需求在现有系统中的实现状态、缺口、风险和推荐改造方式。

Review 时请优先阅读：

- 根目录 `AGENTS.md`
- 根目录 `PROJECT_RULES.md`
- 最近的 `memory/` 记录
- 将领、军队、驻防、物品、背包、装备相关代码
- 当前前端对应页面和接口

Hero3 当前架构原则是模块化单体，玩法和系统必须通过标准接口接入核心。涉及玩家长期资产的改动，例如金币、物品、兵力、将领属性、经验、装备，都不能只在前端处理，必须由后端校验和落库。

## 2. Review 总目标

请按以下目标排查：

1. 判断每条需求属于前端显示、后端规则、数据库字段、配置系统还是接口问题。
2. 判断当前代码是否已经部分实现。
3. 找出已有实现中的 Bug、规则漏洞或体验问题。
4. 标明哪些需求可以直接改，哪些需求必须先补规则或字段。
5. 给出推荐开发顺序。
6. 给出需要补充的测试点。

Review 输出不要只写“能做/不能做”，需要给出对应文件、接口、数据结构和风险说明。

## 3. 待排查需求清单

### 3.1 军队与战斗状态显示

需求 1：驻防部队改成原来的绿色，兵种按顺序锁定位置。

排查方向：

- 当前左侧菜单或军队展示组件在哪里。
- 驻防部队使用的颜色样式在哪里定义。
- 是否存在旧版绿色颜色值或旧样式。
- 兵种顺序是否已经固定为：步兵、骑兵、攻城、特殊。
- 接口返回顺序变化时，前端是否会导致展示位置跳动。
- 驻防部队和普通部队是否共用同一组件，修改颜色是否会影响其他军队卡片。

预期结论：

- 驻防部队应恢复绿色视觉。
- 兵种位置必须固定，不跟接口顺序变化。
- 如果当前已有固定排序逻辑，只需确认未被驻防数据绕过。

需求 2：出征 / 被攻击倒计时颜色改成红色，并放在最上面。

排查方向：

- 当前出征倒计时组件在哪里。
- 当前被攻击倒计时组件在哪里。
- 两类倒计时是否同源数据。
- 前端是否已有状态优先级排序。
- 被攻击、出征、驻防、普通军队的展示顺序是否稳定。
- 倒计时结束后的刷新逻辑是否正确。

预期展示优先级：

1. 被攻击倒计时，红色，最高优先级。
2. 出征或行军倒计时，红色或橙红色。
3. 驻防部队，绿色。
4. 普通部队信息。

风险点：

- 不应只改颜色，还要检查排序。
- 倒计时结束后不能残留在顶部。
- 被攻击状态不能被普通出征状态覆盖。

## 4. 将领系统排查

### 4.1 洗点错误

需求 3：将领洗点老是跳错误，需要优化。

排查方向：

- 洗点按钮调用哪个前端方法。
- 洗点请求调用哪个接口。
- 后端洗点接口在哪里。
- 当前错误是接口返回错误、前端解析错误、状态刷新错误，还是规则校验失败。
- 洗点是否需要消耗金币、道具或其他资源。
- 洗点后是否正确重置四维属性。
- 洗点后可分配属性点是否正确回算。
- 洗点失败时是否给出明确错误原因。

重点检查：

- 前端请求参数是否缺少 generalId、cityId 或 playerId。
- 后端是否校验玩家拥有该将领。
- 后端是否校验资源足够。
- 后端是否存在属性点为负数、等级经验异常、未初始化字段等问题。
- 洗点后前端是否使用旧数据导致二次点击错误。

Review 需要输出：

- 当前真实报错来源。
- 可复现路径。
- 涉及文件和接口。
- 推荐修复方式。

### 4.2 洗点后显示属性点数量

需求 4：洗完属性点要显示出来数量。

排查方向：

- 将领详情页是否显示可分配属性点。
- 后端将领详情接口是否返回可分配属性点。
- 洗点接口返回值是否包含最新将领状态。
- 洗点成功后前端是否刷新将领详情。

预期效果：

- 洗点后立即显示可分配属性点数量。
- 四维属性显示最新值。
- 玩家能清楚知道还有多少点可以分配。

### 4.3 批量加属性点

需求 5：将领需要增加批量加属性点按钮。

排查方向：

- 当前加属性点是单点立即保存，还是本地分配后统一保存。
- 后端是否支持一次提交多个属性变化。
- 是否存在属性点分配接口。
- 当前四维字段名称和校验规则是什么。

推荐交互：

- 每项属性提供 `+1`、`+5`、`+10`、`最大`。
- 有可分配属性点不足时按钮禁用。
- 优先采用本地预分配，点击确认后一次保存。
- 保存前显示本次消耗点数。

后端必须校验：

- 玩家拥有该将领。
- 分配点数不能小于 0。
- 分配总点数不能超过可分配点数。
- 四维属性不能低于基础值。
- 并发提交不能超发属性点。

### 4.4 洗点和换将费用显示

需求 6：洗点和换将的金币费用要显示出来。

排查方向：

- 洗点费用当前是否存在配置。
- 换将费用当前是否存在配置。
- 前端是否写死费用。
- 后端接口是否返回当前费用。
- 金币字段和扣费服务在哪里。

推荐方式：

- 费用由后端配置或配置表返回。
- 前端展示接口返回的费用，不写死。
- 操作确认弹窗显示消耗金币。
- 金币不足时按钮置灰或提示。

### 4.5 换将时间限制

需求 7：换将要限制时间，不能随意更换；现在疑似免费且点一下就换。

排查方向：

- 当前换将入口在哪里。
- 当前换将接口在哪里。
- 当前换将是否扣金币。
- 当前换将是否有冷却字段。
- 当前换将是否只是前端切换显示，还是后端已经更换绑定关系。
- 将领绑定的是城市、槽位、玩家还是阵容。

推荐规则：

- 换将需要消耗金币。
- 换将后进入冷却时间。
- 冷却时间由配置决定，例如 24 小时。
- 冷却中不能更换，或后续预留金币加速。
- 后端必须校验冷却，前端只负责展示。

可能需要字段：

- `last_general_change_at`
- `next_general_change_available_at`
- `general_change_cooldown_until`

Review 需要判断字段应放在：

- 玩家维度
- 城池维度
- 将领槽位维度

优先建议按将领槽位或城池维度设计，避免玩家在不同城市换将互相影响。

### 4.6 经验条数字与百分比

需求 8：将领经验条增加实际进度和数字百分比。

排查方向：

- 当前将领是否有经验条。
- 当前接口是否返回当前经验。
- 当前接口是否返回升下一级所需经验。
- 当前前端是否能计算百分比。
- 满级时经验条如何显示。

预期显示：

```text
12500 / 20000
62.5%
```

满级显示：

```text
已满级
```

### 4.7 四维属性文字介绍

需求 9：将领四维：武力、智谋、内政、统帅缺少文字介绍。

排查方向：

- 当前四维属性在哪里展示。
- 是否已有 tooltip 组件。
- 属性实际影响是否已有后端规则或文档。
- 文案是否会误导玩家。

建议文案必须基于真实规则。

临时文案可采用：

- 武力：影响战斗攻击相关能力。
- 智谋：影响策略、技能或特殊加成相关能力。
- 内政：影响资源、建设或治理相关能力。
- 统帅：影响带兵、部队规模或战斗统率相关能力。

如果当前规则未真正接入这些属性，应在 Review 中指出，不要写成已经生效。

### 4.8 将领等级上限与经验曲线

需求 10：将领等级开放多少；如果 100 级满级可以保持，如果要 200-500 级，每级经验需要下调。

排查方向：

- 当前将领等级上限在哪里配置。
- 当前经验曲线在哪里配置。
- 当前升级所需经验是否写死。
- 经验卡数值和经验曲线是否匹配。
- 将领等级是否影响属性点、战斗、内政或其他能力。

Review 判断：

- 当前是否实际是 100 级满级。
- 若开放 200-500 级，需要改哪些配置和逻辑。
- 是否会造成已有玩家将领强度膨胀。

建议：

- 第一阶段保持 100 级。
- 经验曲线必须配置化。
- 未完成完整数值设计前，不建议直接开放 200-500 级。

## 5. 装备、物品、背包排查

### 5.1 经验包批量使用

需求 11：装备吃经验包等，要增加批量使用按钮。

排查方向：

- 当前经验包使用入口在哪里。
- 是将领吃经验包，还是装备吃经验包，还是两者都有。
- 当前使用物品接口是否支持数量参数。
- 当前是否一次只能使用 1 个。
- 使用多个物品时是否逐个调用接口。
- 使用后经验、等级、背包数量是否刷新。

推荐交互：

- 使用 1 个。
- 使用 5 个。
- 使用 10 个。
- 使用全部。
- 自定义数量。

后端要求：

- 批量使用必须一个事务处理。
- 不能超过玩家拥有数量。
- 不能超过使用目标可接收上限。
- 史诗及以上物品使用仍需二次确认。
- 使用后必须写物品流水。

### 5.2 同类物品自动合并

需求 12：同个东西要自动合并，超过 999 是否不合并需要确认。

排查方向：

- 当前背包数据结构是按 itemId 汇总，还是按格子/堆叠记录。
- 当前是否支持 stackable。
- 当前是否支持 maxStack。
- 当前新增物品时是否自动合并。
- 超过上限时是否拆分为多格。
- 前端是否按格子展示，还是按物品汇总展示。

项目既有规则：

- 背包容量限制为 9999。
- 物品堆叠上限必须生效。
- 超过单格堆叠上限时拆分为多个格子或多条堆叠记录。
- 不建议全局写死 999，应由物品配置的 `maxStack` 决定。

Review 需要指出：

- 当前代码是否已经支持 maxStack。
- 如果没有，应补在哪一层。
- 背包容量是按格子算，还是按 itemId 种类算。

### 5.3 物品和装备图片

需求 13：后期要增加图片。

排查方向：

- 物品配置是否已有 icon 字段。
- 装备配置是否已有 icon 或 image 字段。
- 前端是否有默认图标兜底。
- 静态资源目录是否已有物品素材规范。

建议：

- 第一版使用 icon 字段。
- 无图片时使用默认占位图标。
- 后期素材补齐后不改业务逻辑，只改配置。

## 6. 优先级建议

### 6.1 第一优先级

这些会影响规则漏洞、报错或核心体验，应优先排查：

1. 洗点报错真实原因。
2. 换将是否免费、是否无冷却。
3. 洗点和换将费用是否由后端校验。
4. 洗点后属性点是否正确回算和刷新。
5. 出征 / 被攻击倒计时是否置顶且红色。

### 6.2 第二优先级

这些主要是体验增强：

1. 批量加属性点。
2. 将领经验条数字和百分比。
3. 四维属性说明。
4. 驻防绿色和兵种固定排序。
5. 经验包批量使用。

### 6.3 第三优先级

这些涉及系统完善或后续素材：

1. 物品自动合并和 maxStack。
2. 装备和物品图片。
3. 将领等级上限和经验曲线重做。

## 7. Review 输出格式要求

请按以下格式输出 Review 结果：

```text
一、总体结论
- 当前哪些需求已经实现。
- 当前哪些需求部分实现。
- 当前哪些需求尚未实现。
- 最大风险是什么。

二、逐条需求排查
1. 需求名称
   - 当前实现状态：
   - 涉及文件：
   - 涉及接口：
   - 涉及数据库字段：
   - 问题：
   - 推荐处理：
   - 测试点：

三、需要先补规则的点
- 例如换将冷却是玩家维度、城市维度还是槽位维度。
- 例如将领等级上限是否保持 100。
- 例如 maxStack 是否按物品配置。

四、推荐开发顺序
- 按低风险到高风险，或按影响体验排序。

五、需要用户确认的问题
- 只列必须确认的问题，不列可以由开发判断的问题。
```

## 8. 关键判断标准

Review 时请坚持以下判断：

- 颜色、布局、文字说明属于前端优化。
- 金币费用、冷却时间、属性点、经验、物品数量属于后端规则，不能只前端限制。
- 玩家长期资产变化必须有后端校验、事务和流水。
- 任务、战斗、物品、将领等系统已有标准核心能力时，应优先复用，不要新增旁路逻辑。
- 如果需求和核心边界冲突，需要明确指出冲突点。
