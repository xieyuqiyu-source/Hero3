# 许褚特性更新开发文档

最后更新：2026-07-23

## 1. 当前设计

| 特性 | 类型 | 当前规则 |
| --- | --- | --- |
| 虎痴冲阵 `huchi_chongzhen` | 主动战前特性 | 仅许褚作为主动进攻主将时，在战斗前按 50% 默认概率触发；命中后使敌方全军步兵防御、骑兵防御降低 30%，再用修改后的攻防重新计算战力与真实兵损。概率和降低比例均可由 GM 配置。 |
| 虎虎生威 `huhu_shengwei` | 永久兵种被动 | 许褚所率虎豹骑每兵固定增加 12 点攻击、5 点移动。主动进攻、防守和增援均持续生效，不进行概率判定，不作为一次战斗触发写入时间线。 |

两项特性可以在同一场主动进攻中同时生效：虎虎生威先通过将领 Modifier 进入虎豹骑最终属性，虎痴冲阵再在战斗前修改敌军防御。防守或增援时只有虎虎生威生效，虎痴冲阵不得判定。

## 2. 数值与战报

- 虎虎生威的攻击加成必须进入核心攻击战力与最终兵损；移动加成必须进入 PVP 出征和增援的真实到达时间。
- 虎痴冲阵命中后，战报记录设计概率、设计降低比例，以及逐兵种实际步防、骑防变化。整数属性按当前核心的四舍五入口径处理。
- 虎痴未命中或方向不合法时，不修改数值，也不生成伪触发结果。
- 虎虎生威只显示在参战将领拥有快照的“被动生效”区域，展示虎豹骑攻击 `+12`、移动 `+5`；触发时间线不得出现该 ID。
- 战报最终兵力、阵亡、存活、经验、战力和权威库存必须来自同一次后端结算，两个玩家前端不得自行推算或补造结果。

## 3. GM 配置与迁移

GM 可配置字段：

| 特性 | 字段 | 默认值 |
| --- | --- | --- |
| 虎痴冲阵 | `triggerChance` | `0.5` |
| 虎痴冲阵 | `enemyDefenseReductionRate` | `0.3` |
| 虎虎生威 | `unitAttackFlat` | `12` |
| 虎虎生威 | `unitSpeedFlat` | `5` |

旧“破敌防御”已从当前特性目录、正式配置和两个玩家前端清除。载入存量配置时，旧 ID 仅作为兼容输入迁移成虎虎生威；迁移后强制目标兵种为 `huBaoQi`，并移除旧概率、破防、场景和方向字段。当前 GM 已明确配置的新数值应保留，不被默认值覆盖。

## 4. 实现边界

- 不修改稳定战斗核心校验；虎痴冲阵复用标准战前敌军防御修正能力。
- 虎虎生威复用通用指定兵种固定攻击、固定移动 Modifier，不能写成许褚专属分支。
- PVP、NPC、轮回和增援继续使用各自现有适配层；不存在行军过程的玩法只应用攻击被动，不伪造移动触发。
- `web` 与 `web-wlsg` 必须同步维护名称、阶段、方向、概率、数值和战报展示。

## 5. 自动验收结果

真实 PVP 使用 100 名虎豹骑对 1000 名蜀步兵，得到以下固定矩阵：

| 场景 | 攻击战力 | 防御战力 | 守军损失 | 进攻行军 |
| --- | ---: | ---: | ---: | ---: |
| 两项均关闭或虎虎生威关闭、虎痴未命中 | 3000 | 8000 | 247 | 2054 秒 |
| 虎虎生威生效、虎痴未命中 | 4200 | 8000 | 400 | 1450 秒 |
| 虎虎生威生效、虎痴命中 | 4200 | 6000 | 602 | 1450 秒 |

虎痴命中战报的实际防御变化为步防 `-3`、骑防 `-2`。三组场景均校验双方最终库存、真实阵亡、许褚经验和双方战报；虎虎生威额外验证虎豹骑攻击 `30 -> 42`、速度 `12 -> 17`、非目标骁骑营不变、增援最慢速度真实读取 `17`。

专项测试覆盖默认配置、GM 自定义值保留、旧配置迁移、命中、未命中、错误方向、PVP、NPC、轮回、增援、战报归属和两个玩家前端展示。最终执行结果以本次项目记忆和当前 CI 为准。

本次验收已通过许褚专项 Go `-race -count=3`、`go test ./... -count=1`、`web` 236 项测试、`web-wlsg` 287 项测试和两个生产构建。本机 Chrome 使用同一许褚存档检查两端页面，React 端展示当前完整参数，Vue 端正常进入许褚军事页；两端均无控制台警告、错误或横向溢出。

## 6. 后续修改验收清单

1. 同步修改后端、`web` 和 `web-wlsg`，不得只修单端。
2. 检查 GM 参数 schema、默认值、存量迁移和自定义值保留。
3. 分别验证主动命中、主动未命中、防守、增援和非虎豹骑边界。
4. 对账战力、实际防御变化、兵损、存活、经验、权威库存和行军时间。
5. 两端战报必须区分“本场触发”和“永久被动”。
6. 运行 Go 专项竞态、Go 全量、两端全量测试和生产构建，并使用本机 Chrome 验收两端页面。
