# <span style="color:#2563eb">Hero3 公告系统开发文档</span>

最后更新：2026-06-27

## <span style="color:#2563eb">1. 文档定位</span>

本文档定义 Hero3 公告系统的最终功能范围、模块边界、数据库设计、接口设计、前端展示和验收标准。

公告系统是运营通知模块，不是奖励模块，不是信函模块，也不是聊天系统。

本系统最终目标是提供一个轻量、稳定、可运营的公告中心：

- GM 可以创建、编辑、定时发布、撤回和归档公告。
- 玩家可以查看公告列表、公告详情、历史公告。
- 玩家端支持红点、置顶、强弹窗和已读状态。
- 公告可以按玩家范围投放。
- 公告不负责发放奖励。
- 补偿、奖励、附件统一走信函系统。
- 数据统计只预留，不在本次功能中开发。

## <span style="color:#2563eb">2. 模块边界</span>

公告系统属于运营模块，通过标准 HTTP 接口服务玩家端和 GM 后台。

公告系统负责：

- 公告内容管理。
- 公告发布状态。
- 公告展示策略。
- 公告可见范围。
- 玩家阅读状态。
- 玩家弹窗状态。
- 历史公告查询。

公告系统不负责：

- 奖励发放。
- 奖励领取。
- 奖励附件。
- 信函投递。
- 操作审计。
- 多语言和多版本。
- 服务器和渠道投放。
- 实时数据统计。

如果公告内容涉及维护补偿或活动奖励，应由信函系统发送对应信函。公告正文只说明“奖励已通过信函发放”或“请前往信函查看”。

## <span style="color:#2563eb">3. 和信函系统的关系</span>

公告和信函必须保持清晰边界。

| 模块 | 作用 | 是否承载奖励 |
|------|------|--------------|
| 公告 | 面向全体或指定范围公开展示通知 | 否 |
| 信函 | 给指定玩家投递消息、补偿、奖励和附件 | 是 |
| 战报 | 战斗、侦查、增援等结果记录 | 否 |

补偿流程建议：

```text
GM 发布补偿公告
GM 或系统通过信函发放补偿
玩家在公告中心看到补偿说明
玩家在信函中领取补偿附件
```

公告系统不调用 Reward，不调用 Effect Pipeline，不写玩家资源、道具、货币、兵力、武将和 Buff。

## <span style="color:#2563eb">4. 最终功能范围</span>

### <span style="color:#2563eb">4.1 玩家侧功能</span>

玩家侧需要支持：

- 查看公告列表。
- 查看公告详情。
- 查看历史公告。
- 标记公告已读。
- 记录公告已弹出。
- 关闭弹窗并记录忽略状态。
- 显示公告未读红点。
- 按公告类型筛选。
- 按置顶和优先级排序。

玩家侧不支持：

- 从公告领取奖励。
- 从公告领取附件。
- 对公告评论。
- 对公告点赞。
- 转发公告。

### <span style="color:#2563eb">4.2 GM 后台功能</span>

GM 后台需要支持：

- 公告列表。
- 新建公告。
- 编辑公告。
- 保存草稿。
- 立即发布。
- 定时发布。
- 定时下线。
- 撤回公告。
- 归档公告。
- 删除草稿。
- 设置公告类型。
- 设置置顶。
- 设置优先级。
- 设置强弹窗。
- 设置展示模式。
- 设置有效期。
- 设置投放范围。
- 查看历史公告。

GM 后台不支持：

- 公告奖励配置。
- 公告领取记录。
- 操作审计。
- 多语言内容编辑。
- 数据统计面板。
- 按服务器或渠道投放。

## <span style="color:#2563eb">5. 公告类型</span>

建议公告类型：

```text
system        系统公告
maintenance   维护公告
update        更新公告
activity      活动公告
compensation  补偿说明
emergency     紧急公告
```

说明：

- `compensation` 只是补偿说明，不表示公告本身可以领取补偿。
- 真实补偿由信函系统发放。
- `emergency` 可用于停服、故障、临时维护等高优先级通知。

## <span style="color:#2563eb">6. 公告状态</span>

建议公告状态：

```text
draft       草稿
scheduled   定时发布
published   已发布
withdrawn   已撤回
archived    已归档
```

状态说明：

- `draft`：仅 GM 可见，玩家不可见。
- `scheduled`：已设置发布时间，未到时间前玩家不可见。
- `published`：玩家可见，但仍受投放范围和有效期限制。
- `withdrawn`：已撤回，玩家不可见，GM 可查看。
- `archived`：历史公告，玩家可在历史公告中查看，是否显示取决于后台配置和时间范围。

删除规则：

- 草稿可以物理删除。
- 已发布公告不建议物理删除，应撤回或归档。
- 历史公告通过 `archived` 状态保留。

## <span style="color:#2563eb">7. 展示模式</span>

建议展示模式：

```text
center_only  只在公告中心展示
popup        进入游戏后弹窗展示
banner       横幅预留
```

第一期可以实现：

- `center_only`
- `popup`

`banner` 只保留字段，不开发前端横幅。

强弹窗规则：

- `force_popup = true` 的公告进入弹窗队列。
- 弹窗只展示当前玩家可见、未弹出或未忽略的公告。
- 多个弹窗按 `priority`、`pinned`、`published_at` 排序。
- 玩家关闭后记录 `dismissed_at`。

## <span style="color:#2563eb">8. 投放范围</span>

公告系统支持指定范围投放。

需要支持：

```text
all               全体玩家
player_ids        指定玩家
account_ids       指定账号
factions          指定阵营
level_range       指定玩家等级段
created_at_range  指定玩家创建时间段
```

不需要支持：

```text
server_ids
channels
language
client_version
```

投放判断原则：

- 没有投放规则时，默认不可见或默认全体，需要在实现前明确配置；建议默认全体必须显式写 `all`。
- 多条投放规则之间建议采用“任意命中即可见”。
- 未来如果需要复杂规则，再增加 `match_mode`，当前不做。

## <span style="color:#2563eb">9. 数据库设计</span>

### <span style="color:#2563eb">9.1 公告主体表</span>

表名：`announcements`

用途：保存公告正文、状态、展示策略和有效期。

```text
id              VARCHAR(64) PRIMARY KEY
title           VARCHAR(160) NOT NULL
summary         VARCHAR(255) NOT NULL DEFAULT ''
content         TEXT NOT NULL
type            VARCHAR(32) NOT NULL
status          VARCHAR(32) NOT NULL
display_mode    VARCHAR(32) NOT NULL DEFAULT 'center_only'
pinned          BOOLEAN NOT NULL DEFAULT FALSE
priority        INT NOT NULL DEFAULT 0
force_popup     BOOLEAN NOT NULL DEFAULT FALSE
starts_at       DATETIME(6) NULL
ends_at         DATETIME(6) NULL
published_at    DATETIME(6) NULL
withdrawn_at    DATETIME(6) NULL
archived_at     DATETIME(6) NULL
created_at      DATETIME(6) NOT NULL
updated_at      DATETIME(6) NOT NULL
```

推荐索引：

```text
idx_announcements_visible(status, starts_at, ends_at, pinned, priority, published_at)
idx_announcements_admin(updated_at)
idx_announcements_type(type, status, published_at)
```

字段说明：

- `summary`：公告列表摘要，避免列表接口返回完整正文。
- `content`：公告详情正文。
- `display_mode`：展示模式。
- `force_popup`：是否进入弹窗队列。
- `starts_at`：公告可见开始时间。
- `ends_at`：公告可见结束时间。
- `published_at`：实际发布时间。
- `archived_at`：归档时间，历史公告使用。

### <span style="color:#2563eb">9.2 投放规则表</span>

表名：`announcement_targets`

用途：保存公告可见范围。

```text
announcement_id     VARCHAR(64) NOT NULL
target_type         VARCHAR(32) NOT NULL
target_value_json   JSON NULL
created_at          DATETIME(6) NOT NULL
updated_at          DATETIME(6) NOT NULL
PRIMARY KEY (announcement_id, target_type)
```

推荐索引：

```text
idx_announcement_targets_type(target_type)
```

示例：

```text
target_type = all
target_value_json = null

target_type = factions
target_value_json = ["wei", "shu"]

target_type = player_ids
target_value_json = ["player_xxx", "player_yyy"]

target_type = level_range
target_value_json = {"min": 10, "max": 30}
```

### <span style="color:#2563eb">9.3 玩家阅读状态表</span>

表名：`announcement_reads`

用途：保存玩家对公告的阅读、弹出和忽略状态。

```text
announcement_id   VARCHAR(64) NOT NULL
player_id         VARCHAR(64) NOT NULL
account_id        VARCHAR(64) NOT NULL DEFAULT ''
is_read           BOOLEAN NOT NULL DEFAULT FALSE
read_at           DATETIME(6) NULL
is_popup_shown    BOOLEAN NOT NULL DEFAULT FALSE
popup_shown_at    DATETIME(6) NULL
is_dismissed      BOOLEAN NOT NULL DEFAULT FALSE
dismissed_at      DATETIME(6) NULL
created_at        DATETIME(6) NOT NULL
updated_at        DATETIME(6) NOT NULL
PRIMARY KEY (announcement_id, player_id)
```

推荐索引：

```text
idx_announcement_reads_player(player_id, updated_at)
idx_announcement_reads_account(account_id, updated_at)
```

说明：

- 点开公告详情后可标记 `is_read`。
- 弹窗真正展示后标记 `is_popup_shown`。
- 玩家关闭弹窗后标记 `is_dismissed`。
- 这些状态必须幂等，重复请求不能报错或重复产生副作用。

### <span style="color:#2563eb">9.4 统计预留</span>

统计本次不开发。

未来如需统计，可以新增：

```text
announcement_metrics
```

预留指标：

```text
announcement_id
read_count
popup_count
dismiss_count
updated_at
```

当前不要在登录时逐条写曝光记录，避免 2000 人同时登录时产生写入风暴。


```text

go/internal/transport/api/handlers_admin_announcement.go
```

```text

```

## <span style="color:#2563eb">11. 后端接口设计</span>

### <span style="color:#2563eb">11.1 玩家接口</span>

获取可见公告列表：

```text
GET /api/v1/announcements
```

查询参数：

```text
type
includeArchived
page
pageSize
```

返回列表只包含摘要：

```text
id
title
summary
type
status
displayMode
pinned
priority
forcePopup
publishedAt
endsAt
isRead
isPopupShown
isDismissed
```

获取公告详情：

```text
GET /api/v1/announcements/{announcementId}
```

返回：

```text
id
title
summary
content
type
displayMode
pinned
priority
forcePopup
publishedAt
startsAt
endsAt
isRead
```

标记已读：

```text
POST /api/v1/announcements/{announcementId}/read
```

记录弹窗已展示：

```text
POST /api/v1/announcements/{announcementId}/popup-shown
```

记录弹窗已关闭：

```text
POST /api/v1/announcements/{announcementId}/dismiss
```

获取弹窗队列：

```text
GET /api/v1/announcements/popups
```

说明：

- 弹窗队列只返回摘要，不返回完整正文。
- 玩家点击弹窗后再拉详情。
- 已关闭的强弹公告不应重复弹出，除非后续公告内容更新并明确重置弹窗状态；当前不做重置。

### <span style="color:#2563eb">11.2 GM 接口</span>

GM 公告列表：

```text
GET /api/v1/admin/announcements
```

新建公告：

```text
POST /api/v1/admin/announcements
```

编辑公告：

```text
PUT /api/v1/admin/announcements/{announcementId}
```

发布公告：

```text
POST /api/v1/admin/announcements/{announcementId}/publish
```

定时发布：

```text
POST /api/v1/admin/announcements/{announcementId}/schedule
```

撤回公告：

```text
POST /api/v1/admin/announcements/{announcementId}/withdraw
```

归档公告：

```text
POST /api/v1/admin/announcements/{announcementId}/archive
```

删除草稿：

```text
DELETE /api/v1/admin/announcements/{announcementId}
```

GM 接口说明：

- 只有草稿允许物理删除。
- 已发布公告必须撤回或归档。
- 编辑已发布公告时，应更新 `updated_at`，但不需要做操作审计。
- GM 后台可以查看已撤回和已归档公告。

## <span style="color:#2563eb">12. 可见性判断</span>

玩家能看到公告需要同时满足：

```text
status = published 或 status = archived 且 includeArchived = true
当前时间 >= starts_at 或 starts_at 为空
当前时间 <= ends_at 或 ends_at 为空
玩家命中 announcement_targets
```

投放命中规则：

- `all`：所有玩家命中。
- `player_ids`：当前玩家 ID 在列表中。
- `account_ids`：当前账号 ID 在列表中。
- `factions`：当前玩家阵营在列表中。
- `level_range`：当前玩家等级在范围内。
- `created_at_range`：当前玩家创建时间在范围内。

如果需要玩家等级，但当前玩家摘要里没有稳定等级字段，应先确认等级来源。不要为了公告系统临时从不稳定字段里推断等级。

## <span style="color:#2563eb">13. 前端页面设计</span>

### <span style="color:#2563eb">13.1 玩家端入口</span>

建议入口：

```text
左侧菜单：公告
```

如果已有消息或新闻菜单，也可以作为其子项：

```text
消息
公告
信函
战报
```

菜单红点：

- 有未读可见公告时显示红点。
- 红点不需要精确数量，先做是否未读即可。

### <span style="color:#2563eb">13.2 公告中心</span>

公告中心包含：

```text
全部
系统
维护
更新
活动
补偿
紧急
历史
```

公告卡片展示：

- 标题。
- 摘要。
- 类型。
- 置顶标识。
- 未读标识。
- 发布时间。
- 有效期。

公告详情展示：

- 标题。
- 类型。
- 正文，支持受限 HTML 富文本排版；玩家端只渲染白名单标签，普通纯文本公告继续按换行展示。
- 发布时间。
- 有效期。

每日自动更新公告：

- 玩家公告源固定为 `announcements/daily/YYYY-MM-DD.md`。
- `memory/YYYY-MM-DD.md` 只记录开发记忆和技术决策，不作为玩家公告正文来源。
- 自动任务只用 git 提交范围判断是否存在新版本，用公告源文件决定发什么内容。
- 如果当天公告源文件不存在，或没有 `## 玩家公告` 下的列表条目，则不发布每日公告。

### <span style="color:#2563eb">13.3 弹窗队列</span>

玩家登录或进入游戏主界面后：

1. 请求弹窗队列。
2. 按优先级展示第一条。
3. 展示后调用 `popup-shown`。
4. 玩家关闭后调用 `dismiss`。
5. 玩家点击详情后进入公告详情，并调用 `read`。

弹窗正文可以直接展示摘要，详情按钮再打开完整公告。

## <span style="color:#2563eb">15. 并发和性能要求</span>

公告系统是读多写少系统。

2000 人同时登录时，风险主要来自：

- 同时拉公告列表。
- 同时拉弹窗队列。
- 同时写弹窗展示状态。
- 同时写已读状态。

设计要求：

- 登录后只拉公告摘要，不拉完整正文。
- 不在登录时写曝光记录。
- `popup-shown`、`dismiss`、`read` 必须幂等。
- 公告详情按需加载。
- 历史公告分页加载。
- 列表默认分页，默认 20 条，最大 50 条。

推荐查询顺序：

```text
先查可见公告摘要
再批量查询当前玩家 announcement_reads
在应用层合并 isRead/isPopupShown/isDismissed
```

不要为每条公告单独查询一次阅读状态。

## <span style="color:#2563eb">16. 测试验收</span>

后端测试必须覆盖：

- GM 创建公告。
- GM 编辑公告。
- GM 发布公告。
- GM 定时发布公告。
- GM 撤回公告。
- GM 归档公告。
- 只有草稿可以删除。
- 玩家只能看到已发布且有效期内的公告。
- 玩家可以看到历史公告。
- 投放范围按玩家、账号、阵营、等级、创建时间生效。
- 公告列表不返回完整正文。
- 公告详情返回正文。
- 标记已读幂等。
- 记录弹窗展示幂等。
- 记录弹窗关闭幂等。
- 弹窗队列按置顶、优先级、发布时间排序。

前端验证必须覆盖：

- 菜单红点显示。
- 公告列表按类型筛选。
- 历史公告可查看。
- 公告详情打开后标记已读。
- 强弹窗登录后展示。
- 关闭强弹窗后不重复弹出。
- GM 可以保存草稿、发布、撤回、归档。

## <span style="color:#2563eb">17. 不做内容</span>

本公告系统最终版明确不做：

- 公告奖励领取。
- 公告附件。
- 奖励领取限制。
- 多语言。
- 多版本。
- 服务器投放。
- 渠道投放。
- 操作审计。
- 实时统计。
- 玩家评论。
- 玩家点赞。
- 公告聊天。

数据统计只保留未来扩展空间，不在本次开发。

## <span style="color:#2563eb">18. 最终交付标准</span>

公告系统完成时，应达到：

```text
GM 可以创建、编辑、发布、定时发布、撤回和归档公告
玩家可以查看公告列表、详情和历史公告
公告支持类型、置顶、优先级、有效期、强弹窗
公告支持全体、指定玩家、指定账号、指定阵营、等级段、创建时间段投放
玩家侧支持未读红点、已读、已弹出、已关闭状态
公告列表只返回摘要，详情按需加载正文
公告不发奖励，不领取附件
补偿和奖励统一走信函系统
统计和审计不开发，仅保留后续空间
2000 人同时登录时不会因为公告产生大量写入风暴
```
