# 典韦特性更新开发文档

最后更新：2026-07-23

## 1. 当前设计

| 特性 | 类型 | 当前规则 |
| --- | --- | --- |
| 护主血战 `huzhu_xuezhan` | 防守战前特性 | 典韦作为守城主将或增援将领时，战斗前必定使所率禁卫甲士固定增加 20 点步兵防御和 20 点骑兵防御，再用修改后的防御重新计算战力与真实兵损；主动进攻无效。固定值和触发概率可由 GM 配置。 |
| 死战到底 `sizhandaodi` | 进攻战前特性 | 仅典韦主动进攻时，在战斗前按 60% 默认概率触发；命中后使所率步兵攻击增加 35%，再用修改后的攻击重新计算战力与真实兵损。概率和比例可由 GM 配置。 |

两项特性方向互斥：主动进攻只判定死战到底，守城或增援只判定护主血战。不得在错误方向判定概率、修改属性或生成战报触发项。

## 2. 数值与战报

- 护主血战只修改 `jinWeiSoldier`，必须同时写入 `infantryDefenseModifiedUnits` 和 `cavalryDefenseModifiedUnits`，其它兵种不变。
- 死战到底只修改步兵攻击，命中战报记录设计概率、设计比例和逐兵种实际攻击变化。
- 两项效果都在战斗前进入核心攻防输入；战力、阵亡、存活、经验和权威库存必须来自修改后的同一次后端结算。
- 合法未命中或方向不合法时，不修改数值，也不根据将领拥有快照补造触发项。
- 已废弃的战败返兵不得再出现在当前配置、特性目录、战后结算或两个玩家前端中。

## 3. GM 配置与迁移

| 特性 | 字段 | 默认值 |
| --- | --- | --- |
| 护主血战 | `triggerChance` | `1` |
| 护主血战 | `generalDefenseFlat` | `20` |
| 死战到底 | `triggerChance` | `0.6` |
| 死战到底 | `attackBonusRate` | `0.35` |

旧 `huzhu_sizhan` 只允许作为存量配置迁移输入：载入后转换为 `huzhu_xuezhan`，强制目标兵种为禁卫甲士、方向为防守/增援，并移除旧 `requiredOutcome`、返兵比例和返兵上限。当前 GM 已明确配置的新概率和数值保留，不被默认值覆盖。

## 4. 实现边界

- 不修改稳定战斗核心公式；两项特性复用通用战前单位攻击或固定防御修正。
- PVP、NPC、黄巾、轮回和增援继续使用统一特性事件与各自既有适配层。
- 战报以后端真实触发时间线为准，前端只负责中文格式化，不自行推算特性是否命中。
- `web` 与 `web-wlsg` 必须同步维护名称、阶段、方向、概率、数值和战报结果字段。

## 5. 固定验收矩阵

### 5.1 主动进攻

100 名魏步兵进攻 1000 名守军：

| 场景 | 攻击战力 | 防御战力 | 进攻方损失 | 防守方损失 |
| --- | ---: | ---: | ---: | ---: |
| 死战到底未命中 | 1000 | 10000 | 96 | 36 |
| 死战到底命中 | 1400 | 10000 | 94 | 57 |

命中时单兵攻击实际 `+4`；护主血战不得进入时间线。NPC 同项矩阵固定为攻击战力 `1000 -> 1400`，敌军损失 `74 -> 120`，进攻方均全损。

### 5.2 守城与增援

200 名来袭步兵进攻 100 名禁卫甲士：

| 场景 | 防御战力 | 来袭方损失 | 禁卫甲士损失 |
| --- | ---: | ---: | ---: |
| 护主血战关闭 | 1300 | 108 | 100 |
| 护主血战生效 | 3300 | 200 | 49 |

黄巾场景包含魏国公共防御加成，护主生效后的防御战力为 `3399`，来袭方损失 `200`、禁卫甲士损失 `47`。真实增援矩阵固定验证防御战力 `1010 -> 3010`、步防 `+20`、骑防 `+20`、三方战报归属和援军权威剩余兵力；死战到底不得进入防守或增援时间线。

## 6. 自动与页面验收

- 已覆盖默认配置、GM 自定义值保留、旧配置迁移、命中、未命中、错误方向、非目标兵种、PVP、NPC、黄巾、轮回、增援、战报归属、经验和权威库存。
- 典韦专项 Go `-race -count=3`、Go 全量、`web` 236 项、`web-wlsg` 287 项测试和两套生产构建均通过。
- 本机 Chrome 使用同一典韦存档验收：React 将领页准确展示护主 `100% / 双防 +20` 与死战 `60% / 攻击 +35%`；Vue 正常进入典韦军事页。两端均无控制台警告、错误或横向溢出。
