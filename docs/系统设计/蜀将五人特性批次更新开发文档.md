## 3. 赵云资源保护

- 只接入当前已经真实搬运资源的掠夺结算，不虚构普通进攻的资源转移。
- 赵云作为守城主将时贡献基础保护率 20%。
- 赵云作为援军时，按真实参战顺序依次贡献 20%、10%、5%……。
- 主将与援军贡献相加，均以本场原始可掠夺资源为基数计算；理论累计上限为 60%。
- 战报保存单次贡献比例、累计保护比例、逐资源保护数量和掠夺值变化。

示例：守城主将赵云加两名赵云援军时，累计保护率为 `20% + 20% + 10% = 50%`；继续增加援军时按前一名援军贡献减半。

## 4. GM 配置

- 概率型特性必须暴露 `triggerChance`，并允许 0% 和 100% 用于验收。
- 固定或永久被动不暴露伪概率字段。
- 比例和固定值只暴露当前实现真正消费的参数。
- 旧字段在配置载入时迁移或删除，不能继续影响运行时。
- 两项特性独立判定，满足条件时允许同时触发。

## 5. 战报

- 战前真实伤亡显示逐兵种伤亡和总真实伤亡。
- 逃跑显示逐兵种本场不参战、逃跑和战后返回数量，不计入阵亡与经验。
- 攻防修正显示设计比例或固定值，以及逐兵种实际整数变化。
- 龙胆救援同时发生麒麟卫防御和资源保护时，必须合并为同一归属特性的完整结果，不能被后阶段覆盖。
- 永久四维和永久兵种被动只进入参战将领最终属性、Buff 和拥有特性快照，不进入“本场触发”时间线。
- `web` 与 `web-wlsg` 只展示后端权威结果，不在前端重新计算兵损或资源。

## 6. 自动验收

- 覆盖概率命中、合法未命中、错误方向、错误兵种、主将、援军和轮回副本。
- 覆盖真实伤亡与逃跑按全军总量精确取整，避免逐兵种分别取整造成少扣。
- 覆盖战前变化后重新计算攻击、防御、核心兵损、经验、返程兵力和权威库存。
- 覆盖赵云主将与多援军资源保护递减叠加，及三方战报归属。
- 覆盖黄忠、魏延被动不进入触发时间线。
- Go 全仓测试、两个前端全量测试与生产构建、`git diff --check` 必须通过。
