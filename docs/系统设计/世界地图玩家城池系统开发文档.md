# <span style="color:#16a34a">世界地图玩家城池系统开发文档</span>

最后更新：2026-07-02

## <span style="color:#16a34a">1. 文档定位</span>

本文档用于开发 Hero3 第一版世界地图系统。

第一版只做玩家城池地图，不做 NPC、据点、资源点、副本入口、黄巾起义、活动目标、迁城、空地建城和联盟领土。

目标是把当前 PVP 玩家目标列表升级为真正的世界地图：

```text
玩家有权威坐标 -> 地图按格子展示玩家城池 -> 点选城池 -> 查看等级和状态 -> 执行侦查/攻击/掠夺/增援
```

本系统是地图基础能力，不是单独 PVP 玩法。PVP 和增援只是世界地图上的操作之一。

## <span style="color:#16a34a">2. 第一版范围</span>

### <span style="color:#16a34a">2.1 必须实现</span>

- 只保留一个 `世界地图` 视图，不做地图分类。
- 地图只显示玩家城池。
- 玩家创建后分配随机世界坐标。
- 第一版直接建立权威坐标表。
- 老玩家从旧伪随机坐标迁移到权威表。
- 地图以自己的城池为默认中心。
- 地图支持拖拽移动。
- 地图每个格子对应一个世界坐标。
- 支持输入 X/Y 坐标查找。
- 支持筛选：
  - 自己
  - 同盟
  - 其他玩家
- 不同国家用不同颜色显示。
- 点选玩家城池后显示城池信息。
- 城池信息只显示等级和状态，不显示兵力。
- 操作按钮沿用现有能力：
  - 侦查
  - 攻击
  - 掠夺
  - 增援
- PVP 和增援行军时间按地图距离和部队最低速度计算。

### <span style="color:#16a34a">2.2 第一版不做</span>

- NPC 城池点位。
- 据点点位。
- 资源点点位。
- 副本入口点位。
- 活动目标点位。
- 黄巾起义点位。
- 空地建城。
- 迁城。
- 坐标收藏。
- 联盟领土。
- 战争迷雾。
- 地图行军动画。
- 地图装饰资源。
- 多世界分服。
- 跨服地图。

以上内容只预留结构，不进入第一版。

## <span style="color:#16a34a">3. 核心规则</span>

### <span style="color:#16a34a">3.1 地图大小</span>

第一版地图为：

```text
100 x 100
```

坐标范围：

```text
x: 0 - 99
y: 0 - 99
```

说明：

- 100x100 共 10000 个格子。
- 每个玩家城池占用一个格子。
- 同一个世界内不能有两个玩家占同一个坐标。
- 当有效玩家接近 8000 时，需要考虑扩容地图或开启新世界。

第一版固定：

```text
world_id = world_1
```

### <span style="color:#16a34a">3.2 玩家坐标</span>

玩家必须拥有权威坐标。

规则：

- 新玩家创建时随机分配空坐标。
- 老玩家迁移时优先保留旧伪随机坐标。
- 坐标写入权威表后，后续地图只读权威表。
- 不再实时用 `playerId` 计算展示坐标。
- 第一版不允许玩家主动迁城。

### <span style="color:#16a34a">3.3 默认视野</span>

玩家打开世界地图时，默认以自己的城池为中心。

默认视野建议：

```text
centerX = self.x
centerY = self.y
radius = 10
```

前端可以根据屏幕尺寸调整实际展示格子数量，但后端查询需要支持 `centerX`、`centerY`、`radius`。

当中心点贴近世界边界时，前端视野窗口应整体补齐到合法坐标范围内，例如中心在 `(0,0)` 且半径为 `10` 时，画面显示 `x: 0-20`、`y: 0-20`，不保留负坐标造成的空白格。

### <span style="color:#16a34a">3.4 格子关系</span>

地图必须是格子地图。

规则：

- 一个格子对应一个坐标。
- 玩家城池只能显示在一个具体格子中。
- 点击有城池的格子，选中玩家城池。
- 点击空格，显示空地信息。
- 空地第一版没有操作。

### <span style="color:#16a34a">3.5 图例筛选</span>

第一版图例筛选：

```text
自己
同盟
其他玩家
```

国家颜色：

```text
魏：蓝色
蜀：绿色
吴：红色
其它：灰色
```

推荐展示规则：

- 主体颜色表示国家。
- 边框或徽标表示关系。
- 自己使用高亮描边。
- 同盟使用友方描边。
- 其他玩家按国家颜色显示。

如果第一版联盟系统还不完整：

- 同盟筛选可以先保留 UI 和字段。
- 后端 `relation = ally` 暂时只在有明确联盟关系时返回。
- 没有联盟数据时，除自己外都归为其他玩家。

### <span style="color:#16a34a">3.6 目标信息</span>

点选玩家城池后显示：

```text
坐标
城池名称或玩家名称
国家
等级
状态
可执行操作
```

明确不显示：

```text
兵力
资源
武将
驻防
建筑详情
防守详情
```

兵力和详细防守信息必须通过侦查获取，不能直接暴露在世界地图。

第一版状态建议：

```text
self          自己
ally          同盟
normal        正常
protected     保护中
truce         免战中
attackable    可攻击
unavailable   不可操作
```

### <span style="color:#16a34a">3.7 操作按钮</span>

玩家城池可执行操作：

```text
侦查
攻击
掠夺
增援
```

按钮是否可用由后端返回，不由前端硬判断。

字段建议：

```json
{
  "canScout": true,
  "canAttack": true,
  "canPlunder": true,
  "canReinforce": true,
  "reason": "",
  "scoutReason": "",
  "attackReason": "",
  "plunderReason": "",
  "reinforceReason": ""
}
```

自己城池：

- 不允许攻击。
- 不允许掠夺。
- 不允许侦查。
- 不允许增援自己。

同盟玩家：

- 第一版如果还没有联盟权限，可以只禁用攻击和掠夺。
- 是否允许增援同盟由增援系统现有规则决定。

其他玩家：

- 侦查、攻击、掠夺、增援按现有 PVP/增援规则判断。

## <span style="color:#16a34a">4. 行军时间规则</span>

### <span style="color:#16a34a">4.1 每格耗时</span>

用户确认规则：

```text
速度 1：1 格 = 5 分钟
速度 5：1 格 = 1 分钟
速度 15：1 格 = 20 秒
```

统一公式：

```text
每格耗时秒数 = 300 / 速度
```

### <span style="color:#16a34a">4.2 地图距离</span>

前端地图必须使用真实坐标格渲染：草地不是背景图，也不是装饰纹理；每一块草地就是一个世界坐标格，大小必须和玩家城池占用格完全一致。城池只能覆盖自己所在的那一格，点击草地时选中的也是该坐标格。

第一版使用曼哈顿距离：

```text
distance = abs(fromX - toX) + abs(fromY - toY)
```

示例：

```text
自己坐标：(10, 10)
目标坐标：(13, 14)
距离 = 3 + 4 = 7 格
```

暂不使用斜线距离、欧氏距离或寻路系统。

### <span style="color:#16a34a">4.3 部队速度</span>

如果出征或增援包含多个兵种：

```text
部队速度 = 所有出征兵种中的最低速度
```

如果兵种缺少速度配置：

- 后端应使用默认速度 `1`。
- 配置校验应提示缺少速度字段。

### <span style="color:#16a34a">4.4 行军时间</span>

公式：

```text
marchSeconds = ceil(distance * 300 / troopSpeed)
finalSeconds = min(marchSeconds, 10800)
```

示例：

```text
距离 = 7 格
最慢兵种速度 = 5
行军时间 = 7 * 300 / 5 = 420 秒 = 7 分钟
```

第一版最终行军时间上限固定为三小时；地图仍使用真实格子距离，只有计算结果超过三小时时才封顶。

### <span style="color:#16a34a">4.5 建筑和武将加成</span>

第一版应继续接入已有 `marchSpeedBonus`。

推荐顺序：

```text
先按地图距离和部队速度计算基础时间
再通过 Modifier 管线应用 marchSpeedBonus
```

即：

```text
baseSeconds = ceil(distance * 300 / troopSpeed)
finalSeconds = applySpeedBonus(baseSeconds, StatMarchSpeedBonus, now, modifierSources)
```

### <span style="color:#16a34a">4.6 对 PVP 和增援的影响</span>

PVP：

- 侦查、攻击和掠夺都使用世界地图距离计算行军时间。
- 侦查发起时派出当前阵营的全部侦察兵，抵达目标后结算侦查并生成双视角战报。
- 侦查幸存者按实际去程耗时返程；全军覆没时直接结束行军。
- 侦查不计入每日攻击次数，也不触发攻击对应的免战和战斗状态变化。
- 返程仍按 PVP 现有返程规则，但应基于实际去程耗时。
- 加速规则继续沿用 PVP 当前加速规则。

增援：

- 增援使用世界地图距离计算行军时间。
- 增援加速按《增援系统修复开发方案》执行。
- 路上召回/遣返按已走时间返程。

## <span style="color:#16a34a">5. 老坐标迁移</span>

### <span style="color:#16a34a">5.1 当前旧坐标</span>

当前 PVP 目标坐标由 `playerId` 稳定伪随机生成，不是数据库中的真实坐标。

旧逻辑特点：

- 同一个玩家每次算出的坐标稳定。
- 不需要存库。
- 但无法迁城。
- 无法保证坐标唯一。
- 无法承载联盟领土、资源点、据点等后续地图玩法。

### <span style="color:#16a34a">5.2 迁移原则</span>

迁移到权威表时：

```text
优先保留旧伪随机坐标
```

目标：

- 老玩家地图位置尽量不突然变化。
- 冲突时就近找空格。
- 迁移后只读权威表。

### <span style="color:#16a34a">5.3 坐标转换</span>

当前旧坐标可能是：

```text
-100 到 100
```

第一版新坐标是：

```text
0 到 99
```

需要把旧坐标映射到新坐标。

推荐做法：

```text
newX = floor((oldX + oldWorldSize) * 100 / (oldWorldSize * 2 + 1))
newY = floor((oldY + oldWorldSize) * 100 / (oldWorldSize * 2 + 1))
```

并做边界保护：

```text
newX = clamp(newX, 0, 99)
newY = clamp(newY, 0, 99)
```

如果开发时决定继续使用 `-50 ~ 49` 或 `-100 ~ 100` 坐标制，也可以不转换。但本方案第一版推荐统一 `0 - 99`。

线上兼容补充：

- 如果旧伪随机坐标已经是 `0 - 99`，迁移时保持原值，不做二次压缩。
- 如果读到明显越界的历史坐标，例如负坐标或 `100` 以上坐标，再按上面的公式映射到 `0 - 99`。
- 没有历史坐标制元数据时，完全落在 `0 - 99` 内的值优先视为当前合法坐标，避免线上玩家被误迁。

### <span style="color:#16a34a">5.4 冲突处理</span>

当目标坐标已被占用：

```text
从旧坐标附近找最近空格
```

规则：

1. 计算旧坐标映射后的 `x, y`。
2. 如果 `(x, y)` 空闲，直接使用。
3. 如果被占用，从半径 1 开始找空格。
4. 半径 1 找不到，找半径 2。
5. 一直扩大到地图边界。
6. 仍找不到，说明地图容量不足，应停止迁移并提示扩容。

搜索顺序必须稳定，避免同一批数据重复执行得到不同结果。

建议顺序：

```text
上 -> 右 -> 下 -> 左 -> 外圈顺时针
```

### <span style="color:#16a34a">5.5 懒加载兜底</span>

除了迁移脚本，世界地图接口也必须做兜底：

```text
玩家打开世界地图
如果 player_world_positions 没有该玩家
后端自动分配坐标
```

这样即使迁移漏了，也不会导致地图打不开。

兜底分配来源：

```text
assigned_by = lazy_create
```

## <span style="color:#16a34a">6. 数据库设计</span>

### <span style="color:#16a34a">6.1 player_world_positions</span>

玩家世界坐标权威表。

```sql
CREATE TABLE player_world_positions (
  player_id VARCHAR(64) PRIMARY KEY,
  world_id VARCHAR(64) NOT NULL DEFAULT 'world_1',
  x INT NOT NULL,
  y INT NOT NULL,
  assigned_by VARCHAR(32) NOT NULL DEFAULT 'create',
  created_at DATETIME(6) NOT NULL,
  updated_at DATETIME(6) NOT NULL,
  UNIQUE KEY uk_world_xy (world_id, x, y),
  KEY idx_world_xy (world_id, x, y),
  KEY idx_world_player (world_id, player_id),
  CONSTRAINT fk_player_world_positions_player
    FOREIGN KEY (player_id) REFERENCES players(id)
    ON DELETE CASCADE
);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `player_id` | 玩家 ID |
| `world_id` | 世界 ID，第一版固定 `world_1` |
| `x` | 横坐标 |
| `y` | 纵坐标 |
| `assigned_by` | 坐标来源 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

`assigned_by` 枚举建议：

```text
create       新玩家创建
migration    老玩家迁移
lazy_create  接口兜底创建
admin         GM 调整
relocate     后续迁城
```

删除玩家存档时必须释放该玩家的世界坐标。新库可以依赖 `ON DELETE CASCADE`，但历史库可能缺少外键，后端 `DeletePlayer` 仍必须显式删除 `player_world_positions`，避免已删玩家继续占用地图格。

### <span style="color:#16a34a">6.2 world_maps</span>

第一版可以不建，也可以先建配置表。

如果建立：

```sql
CREATE TABLE world_maps (
  world_id VARCHAR(64) PRIMARY KEY,
  name VARCHAR(64) NOT NULL,
  width INT NOT NULL,
  height INT NOT NULL,
  status VARCHAR(32) NOT NULL DEFAULT 'active',
  created_at DATETIME(6) NOT NULL,
  updated_at DATETIME(6) NOT NULL
);
```

第一版默认：

```text
world_id = world_1
width = 100
height = 100
```

如果不建表，先写配置常量也可以，但接口和数据结构要保留 `worldId`。

### <span style="color:#16a34a">7.2 Repository 能力</span>

建议新增端口：

```go
type WorldMapRepository interface {
    GetWorldPosition(playerID string) (WorldPosition, error)
    EnsureWorldPosition(playerID string, assignedBy string, preferred *WorldCoordinate) (WorldPosition, error)
    ListWorldTargets(worldID string, minX int, maxX int, minY int, maxY int) ([]WorldPosition, error)
    AssignWorldPosition(playerID string, worldID string, x int, y int, assignedBy string) (WorldPosition, error)
}
```

要求：

- 分配坐标必须依赖数据库唯一键防并发冲突。
- 如果随机坐标冲突，要继续找空格。
- 同一玩家重复 `EnsureWorldPosition` 必须幂等。

### <span style="color:#16a34a">7.3 坐标分配算法</span>

新玩家随机分配：

```text
1. 在 0-99 内生成随机起点。
2. 尝试写入该坐标。
3. 如果唯一键冲突，从该点向外螺旋找空格。
4. 找到后写入。
5. 如果全图无空格，返回地图已满错误。
```

老玩家迁移：

```text
1. 用旧伪随机算法算出旧坐标。
2. 映射到 0-99。
3. 优先写入映射坐标。
4. 冲突则就近找空格。
```

- 查询范围裁剪到地图边界。
- 返回自己和范围内玩家。
- 只显示玩家基础信息，不显示兵力。

### <span style="color:#16a34a">7.5 目标详情接口</span>

新增：

```http
GET /api/v1/world-map/targets/player_city/{playerId}?viewerId=xxx
```

返回单个目标详情。

第一版也可以直接用 `view` 返回的数据展示详情，暂不单独加详情接口。但如果右侧面板需要刷新状态，建议保留该接口。

### <span style="color:#16a34a">7.6 坐标查找接口</span>

第一版不一定需要单独接口。

前端输入坐标后，可以直接调用：

```http
GET /api/v1/world-map/view?playerId=xxx&centerX=目标X&centerY=目标Y&radius=10
```

然后前端判断中心格是否有目标。

### <span style="color:#16a34a">7.7 行军时间函数</span>

新增公共函数：

```go
func CalculateWorldMarchSeconds(distance int, speed int, now time.Time, sources []ModifierSource) int
```

逻辑：

```text
if distance <= 0 return 0
if speed <= 0 speed = 1
baseSeconds = ceil(distance * 300 / speed)
return applySpeedBonus(baseSeconds, StatMarchSpeedBonus, now, sources)
```

PVP 和增援都应复用该函数。

### <span style="color:#16a34a">7.8 PVP 接入</span>

需要修改：

- PVP 目标列表从权威表读取坐标。
- `GetPvpTargets` 不再使用实时伪随机坐标。
- PVP 出征时间按坐标距离和部队最低速度计算。
- PVP 目标响应继续兼容现有前端字段。

保留：

- 侦查。
- 攻击。
- 掠夺。
- PVP 行军。
- PVP 加速。
- PVP 召回。
- PVP 战报。

### <span style="color:#16a34a">7.9 增援接入</span>

需要修改：

- 增援发起时读取双方权威坐标。
- 增援行军时间按坐标距离和部队最低速度计算。
- 增援的路上召回/遣返和加速按《增援系统修复开发方案》实现。

### <span style="color:#16a34a">7.10 权限与安全</span>

要求：

- 玩家只能以自己的 `playerId` 查询视野。
- 后端必须校验登录用户拥有该玩家。
- 地图视图不能返回兵力。
- 地图视图不能返回资源。
- 地图视图不能返回武将和驻防详情。
- 操作按钮可用性以后端为准。

## <span style="color:#16a34a">10. Admin 和迁移工具</span>

### <span style="color:#16a34a">10.1 迁移工具</span>

需要提供本地或后台迁移能力：

```text
为所有已有玩家回填 player_world_positions
```

要求：

- 可重复执行。
- 已有坐标的玩家跳过。
- 缺失坐标的玩家补齐。
- 输出迁移数量、冲突数量、失败数量。
- 地图容量不足时停止并报错。

线上大库执行规则：

- 迁移只写 `player_world_positions`，不迁移玩家大存档、战报、资源、背包、兵力等大表。
- dbtool 按 `players.id` 分页扫描缺少世界坐标的玩家，只读取玩家 ID，不读取 `state_json`。
- 推荐正式库命令为 `hero3-dbtool backfill-world-positions --allow-non-test --batch-size=500`。
- 首次线上试跑可以增加 `--max-batches=1`，确认输出和锁等待正常后再继续执行。
- 命令可重复执行；已经有世界坐标的玩家会跳过，失败或中断后再次执行只会处理剩余缺失玩家。

### <span style="color:#16a34a">10.2 Admin 能力</span>

第一版 Admin 可以暂缓，但建议预留：

- 查看玩家坐标。
- 按玩家 ID 查询坐标。
- 手动分配坐标。
- 检查坐标冲突。
- 统计地图占用率。

当前 GM 后台已提供玩家坐标查询、占用率查看、指定坐标占用检查和手动调整入口；保存调整前会先检查目标格是否已被其它玩家占用，后端保存时仍以唯一键和服务校验作为最终防线。

如果当前开发时间有限，第一版至少要有数据库查询和迁移工具。

## <span style="color:#16a34a">14. 验收标准</span>

后端验收：

- 所有玩家都有权威坐标。
- 坐标唯一。
- 老玩家迁移后不再依赖旧伪随机坐标。
- 地图接口能返回自己附近玩家。
- 地图接口不泄露兵力和资源。
- PVP 侦查、攻击、掠夺和增援使用地图距离计算行军时间。
- 侦查抵达前不生成战报，抵达后才结算并生成战报。
- 侦查幸存者返程后归队，召回时未结算侦查。
- 坐标缺失时能自动补齐。

- 地图只有世界地图一个主视图。
- 地图只显示玩家城池。
- 地图可拖拽。
- 格子和坐标一一对应。
- 默认以自己为中心。
- 可以输入坐标查找。
- 可以筛选自己、同盟、其他玩家。
- 不同国家颜色不同。
- 选中城池后显示等级和状态。
- 不显示兵力。
- 侦查、攻击、掠夺、增援可正常发起。
- 侦查行军和被侦查行军具有独立倒计时标识。

## <span style="color:#16a34a">16. 最终结论</span>

世界地图第一版的核心是：

```text
玩家城池坐标权威化 + 格子地图展示 + 地图距离行军时间
```

本次开发完成后，Hero3 的 PVP 和增援将从“列表选择目标”升级为“在世界地图上选择目标”，为后续据点、资源点、联盟领土和世界事件打基础。
