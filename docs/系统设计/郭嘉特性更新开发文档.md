# 郭嘉特性更新开发文档

最后更新：2026-07-23

## 1. 当前设计

| 特性 | 类型 | 当前规则 |
| --- | --- | --- |
| 神鬼之才 `shengui_zhicai` | 全天候永久被动 | 郭嘉固定增加 10 点内政和 10 点智谋。增加值进入 `effectiveStats`，并按每点属性 2% 转换为对应真实内政、征兵速度和行军速度等加成；不作为战斗触发项。数值可由 GM 配置。 |
| 鬼才遗策 `guicai_yice` | 战斗结束后复活 | 郭嘉主动进攻、守城或作为援军参战时，战斗结束后按其所率部队本场真实阵亡逐兵种复活 22%。默认必定触发，复活比例和触发概率可由 GM 配置，不限制胜负。 |

两项特性职责分离：神鬼之才在武将装配时进入最终属性；鬼才遗策只在所属部队产生真实阵亡后进行战后结算。拥有快照不能替代触发时间线。

## 2. 数值与战报

- 神鬼之才的基础默认值为 `politicsBonus=10`、`intelligenceBonus=10`。它会写入最终四维及对应 Modifier，但不得写入 `TraitTriggered` 或标准战报触发列表。
- 鬼才遗策以战斗核心已经结算出的逐兵种真实阵亡为基数，逐项执行 `floor(真实阵亡 × effectRate)`。
- 复活没有单场人数上限，但所有战后复活累计仍不得超过对应兵种本场真实阵亡。
- GM schema 只暴露复活比例和触发概率，不展示也不读取通用最大影响比例、最大影响数量，避免形成虚假的复活上限。
- 复活兵必须回到郭嘉实际所属的进攻返程部队、主城守军、援军记录或轮回权威军队，不能只改战报。
- 战报必须同时保存并展示 `effectRate`、`triggerChance`、`actualLostUnits`、`revivedUnits`、`totalRevived` 和最终兵力行。
- 没有实际复活时不得伪造正数结果；概率未命中时不得修改兵力或生成触发项。

## 3. GM 配置与迁移

| 特性 | 字段 | 默认值 |
| --- | --- | --- |
| 神鬼之才 | `politicsBonus` | `10` |
| 神鬼之才 | `intelligenceBonus` | `10` |
| 鬼才遗策 | `effectRate` | `0.22` |
| 鬼才遗策 | `triggerChance` | `1` |

存量配置归一化规则：

- 删除神鬼之才旧 `resourceCostReduction` 和无意义的战斗概率，迁移为默认内政、智谋各加 10。
- 删除鬼才遗策旧 `lossReductionRate`、`maxReturnCount` 和 `requiredOutcome=loss`，迁移为全方向战后复活 22%。
- 当前新格式中 GM 已明确配置的四维值、复活比例和触发概率必须保留，不被默认值覆盖。
- GM schema 不再暴露旧征兵减耗、最终减损、返还上限字段。

## 4. 实现边界

- 不修改稳定战斗核心公式；永久四维复用通用武将属性装配，战后复活复用统一 `AfterBattle` 事件。
- PVP、NPC、黄巾、轮回和增援继续使用各自既有事务与战报适配入口。
- 复活只消费后端权威真实阵亡，不从胜负、战力或前端展示值反推。
- `web` 与 `web-wlsg` 必须同步维护永久被动区、战后触发区、逐兵种真实阵亡、实际复活和最终存活。

## 5. 固定验收矩阵

- 永久属性：基础智谋 3、内政 4 时，最终智谋 13、内政 14；对应征兵/行军加成为 26%，生产/容量加成为 28%，神鬼之才不进入战斗时间线。
- PVP 战败：100 名魏步兵真实阵亡 100，默认复活 22，最终返程 22；双方战报结果一致。
- PVP 平局：1000 名魏步兵真实阵亡 500，复活 110，最终返程 610。
- PVP 获胜：只要郭嘉所属部队存在真实阵亡，仍按 GM 比例复活，不受旧战败条件限制。
- 援军平局：500 名援军真实阵亡 250，复活 55，最终剩余 305；三方战报和援军记录一致。
- 轮回平局：100 名部队真实阵亡 100，复活 22，副本记录最终存活 22，玩家权威军队从 500 变为 422。
- NPC、黄巾和扫荡：真实阵亡、逐兵种复活、经验、最终库存和标准战报全部对账。

## 6. 自动与页面验收

- 已覆盖默认配置、旧配置迁移、当前 GM 自定义值保留、永久最终属性、战败、获胜、平局、进攻、防守、增援、NPC、黄巾、轮回、扫荡、战报归属和权威库存。
- `web` 与 `web-wlsg` 均只格式化后端结果，不自行计算复活；神鬼之才显示在永久被动区域，鬼才遗策显示在战斗结束后时间线。
- Go 全量测试通过；郭嘉专项竞态测试使用 `-race -count=3` 通过；`web` 236 项、`web-wlsg` 287 项测试和两个生产构建通过。
- 本机 Chrome 已验证 GM 只展示四个当前有效参数，旧返兵字段和无效通用上限均不存在；`web`、`web-wlsg` 与 GM 页面没有横向溢出。

## 7. 后续修改验收清单

1. 同步修改后端、`web` 和 `web-wlsg`，不得只修单端。

3. 分别验证概率命中、概率未命中、进攻、守城、增援、不同胜负和多兵种取整。
4. 对账真实阵亡、实际复活、最终存活、返程或库存、经验及所有参战方战报。
5. 确认旧征兵减耗、战败条件、最终减损和返还上限只存在于迁移输入测试中。
6. 运行 Go 全量、双前端测试与构建，并使用本机 Chrome 验收两端。
