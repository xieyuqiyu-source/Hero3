# 诸葛亮特性更新开发文档

## 1. 当前规则

### 1.1 奇门遁甲

- 特性 ID：`qimen_dunjia`。
- 触发阶段：进攻、防守或增援战斗前。
- 默认效果：敌方各兵种合计 25% 兵力仅本场无法参战。
- 被困兵力不属于真实阵亡，不提供击杀经验，战后完整保留在原部队。
- 困敌比例和触发概率可由 GM 配置；正式默认值为 `effectRate=0.25`、`triggerChance=1`。
- 战报必须显示设计比例、触发概率和逐兵种本场压制兵力。

### 1.2 卧龙奇谋

- 特性 ID：`wolong_mouzhi`，旧名称“卧龙谋制”已废止。
- 触发阶段：任何战斗触发型特性执行前。
- 适用方向：进攻、防守或增援。
- 正式默认概率为 60%，由 GM 的 `triggerChance` 配置。
- 命中后封禁敌方所有参战将领的战斗触发型特性，包括主将和各支真实参战援军将领。
- 封禁覆盖战斗前、战斗结算后、战斗结束后和掠夺结算阶段。
- 永久属性、永久兵种加成、留城效果和已经完成的行军效果不属于战斗触发型特性，不受封禁影响。
- 战报必须显示封禁将领数、实际封禁的触发型特性数和触发概率。

## 2. 双方诸葛亮

- 只要进攻联盟和防守联盟都存在真实参战的诸葛亮，双方卧龙奇谋均不进行概率判定，也不封禁任何特性。
- 两位诸葛亮的战报分别显示“状态：特性已失效；失效原因：双方均有诸葛亮”。
- 奇门遁甲不受该特殊规则影响，仍由双方独立执行。
- 永久被动和其他将领特性也不因该特殊规则失效。

## 3. 旧逻辑清理

- 删除卧龙奇谋旧 `disableTraitCount` 参数和“战斗结算后拦截 1 项后续特性”逻辑。
- 删除奇门遁甲旧 `maxAffectedRate`、`maxAffectedCount` 参数。
- 旧配置载入时自动归一：奇门补齐默认概率 100%，卧龙补齐默认概率 60%。
- GM 参数面板中，奇门只显示“困敌比例、触发概率”，卧龙只显示“触发概率”。
- 保留黄盖苦肉计原有战斗结算后单项压制机制，两种封禁规则不得混用。

## 4. 实现边界

- 新增独立的 `battle_trait_control` 事件阶段，不修改稳定攻防公式。
- PVP 在构建战前触发结果前统一判断卧龙奇谋，再过滤被封禁方的战斗触发型特性。
- 被动 Modifier 继续进入真实战斗单位属性，保证“封触发、不封被动”。
- 封禁状态贯穿主将、援军、战斗结算后、战斗结束后和掠夺结算。
- NPC、黄巾和轮回中没有敌方参战将领时，卧龙奇谋没有封禁对象，不生成虚假触发结果。

## 5. 验收标准

- 奇门在进攻、防守和增援方向都按修改后的参战兵力进入核心攻防。
- 卧龙覆盖 0% 未命中、100% 命中、正式 60% 配置和 GM 旧字段迁移。
- 命中后敌方所有参战将领的触发型特性均不执行、不改状态、不进入战报。
- 被封禁方永久被动仍进入最终属性和战斗能力。
- 双方诸葛亮真实 PVP 必须出现两条失效提示，且双方奇门仍各自生效。
- 主战报、守方战报和援军独立战报的归属、阶段、数值和最终兵力一致。
- `web` 与 `web-wlsg` 同步显示当前名称、战前阶段、封禁结果和失效原因。
- Go 全量及定向 `-race`、双前端测试与构建、Chrome 页面检查和 `git diff --check` 全部通过。

## 6. 本轮验收结果

- Go 全仓测试通过；诸葛亮相关测试在竞态检测下连续运行 3 次通过，关键配置及 PVP 场景连续运行 5 次通过。
- `web` 236 项测试、`web-wlsg` 287 项测试全部通过，两个玩家端和 GM 后台生产构建通过。
- Chrome 确认 GM 只暴露当前有效参数：奇门 25% 困敌比例和 100% 默认概率，卧龙 60% 概率。
- Chrome 确认两个玩家端可登录并加载同一真实存档；战报名称、阶段、封禁结果和失效提示由双端全量展示测试覆盖。
- 双方诸葛亮的真实 PVP 自动验收确认：卧龙均显示“特性已失效”，双方均不封禁，奇门仍分别生效。
- `git diff --check` 通过。
