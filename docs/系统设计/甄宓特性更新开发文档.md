# 甄宓特性更新开发文档

## 1. 当前正式规则

### 1.1 美人心计 `meiren`

- 类型：特殊特性。
- 阶段：主动进攻战斗前。
- 默认触发概率：50%，由 GM 参数 `triggerChance` 配置。
- 默认效果：甄宓所率全军攻击提升 25%，由 GM 参数 `attackBonusRate` 配置。
- 防守和增援无效。
- 命中后直接修改本场参战军团的单位攻击，核心使用修改后的攻击重新计算战力与兵损。

### 1.2 魅惑扰阵 `meihuo_raozhen`

- 类型：加成特性。
- 阶段：主动进攻战斗前。
- 默认触发概率：50%，由 GM 参数 `triggerChance` 配置。
- 默认效果：敌方全军步兵防御、骑兵防御降低 25%，由 GM 参数 `enemyDefenseReductionRate` 配置。
- 防守和增援无效。
- 命中后直接修改本场敌军单位防御，核心使用修改后的防御重新计算战力与兵损。

## 2. 概率与组合规则

两项特性各自独立判定，不共享一次随机结果：

| 美人心计 | 魅惑扰阵 | 结果 |
| --- | --- | --- |
| 命中 | 命中 | 同时加攻和破防 |
| 命中 | 未命中 | 只增加我方攻击 |
| 未命中 | 命中 | 只降低敌方防御 |
| 未命中 | 未命中 | 使用基础攻防 |

按默认 50% 概率计算，四种组合各占 25%。GM 可以分别修改两项概率，前端不得自行随机或推算命中结果。

## 3. 战斗与战报约束

- 特性必须先于核心战斗公式执行，不能先算兵损再补写百分比。
- 只有实际命中的特性进入 `traitTriggered`、`traitOutcomes` 和标准战报时间线。
- 美人心计战报记录 `attackBonusRate`、`attackModifiedUnits` 和 `triggerChance`。
- 魅惑扰阵战报记录 `enemyDefenseReductionRate`、`infantryDefenseModifiedUnits`、`cavalryDefenseModifiedUnits` 和 `triggerChance`。
- 逐兵种实际变化使用后端最终整数，两个前端不得根据百分比二次计算。
- 两项同时命中时必须各自显示，不能覆盖、合并或只保留其中一项。
- 防守和增援战报不得出现这两项触发结果；将领拥有快照不等于本场触发。

## 4. 旧特性清理

- `meiren` ID 为兼容现有存档继续保留，但正式名称改为“美人心计”。
- 已删除旧“美人计”俘虏实现、俘虏比例、单兵种俘虏上限及专用测试。
- 旧配置中的 `captureRate`、`captureMax`、`maxCapturePerUnit` 会被归一化迁移，不再参与战斗。
- 新战斗不得生成俘虏兵、获得驻防或俘虏类特性明细。
- 战报通用俘虏字段暂时保留，只用于读取历史战报和兼容其他未来玩法。

## 5. 验收标准

1. 正式配置为两项 50% 独立概率、攻击 +25%、敌方防御 -25%。
2. GM 参数 schema 提供两项效果比例和各自触发概率，不再提供旧俘虏参数。
3. 核心单元测试覆盖同时命中、零概率和防守/增援方向隔离。
4. 真实 PVP 覆盖四种命中组合，核对修改后战力、真实兵损、双方战报和权威兵力。
5. NPC 与轮回战斗核对修改后的攻防进入核心公式，且不再产生俘虏结果。
6. `web` 与 `web-wlsg` 同步显示正式名称、阶段、概率、设计比例和实际逐兵种变化。
7. 后端全量测试、两个前端测试与生产构建通过，并使用 Chrome 检查玩家可见文案。
