# 刘备特性更新开发文档

最后更新：2026-07-23

## 1. 当前设计

| 特性 | 类型 | 当前规则 |
| --- | --- | --- |
| 仁德天下 `rende` | 全天候永久被动 | 刘备固定增加 10 点内政和 12 点统率。数值进入最终四维与对应 Modifier，不进行概率判定，不进入战斗触发时间线。 |
| 仁主守护 `renzhu_shouhu` | 战斗结束后概率复活 | 刘备主动进攻、守城或作为援军参战时，战斗结束后有 60% 概率按其所率部队本场真实阵亡逐兵种复活 35%。 |

两项特性职责严格分离。仁德天下负责武将最终属性；仁主守护只消费战斗已经产生的真实阵亡。拥有特性快照不等于本场触发。

## 2. 属性与战斗口径

- 系统稳定字段中，“统率”使用 `command`，“内政”使用 `politics`。
- 每 1 点四维属性按 `GeneralStatPercentPerPoint=0.02` 转换为 2% 对应加成。
- `politics +10` 对应生产与容量加成 20%；`command +12` 对应防御加成 24%。
- 仁德天下的增加值写入 `effectiveStats`、`attributes` 和 `buffs`，但不得写入 `TraitTriggered`、`TraitOutcomes` 或标准战报触发列表。
- 仁主守护按每个兵种执行 `floor(本场真实阵亡 × effectRate)`，默认 `effectRate=0.35`。
- 复活没有单场人数上限。35% 的计算结果天然不会超过本场真实阵亡；统一战后结算仍保证累计复活不超过对应兵种的真实阵亡。
- 概率未命中时不改变兵力，不生成触发结果，不由前端补造“未触发”时间线。
- 复活只改变最终净损失和存活，不回减已经发生的真实阵亡及敌方击杀经验。

## 3. GM 配置

| 特性 | 字段 | 默认值 |
| --- | --- | --- |
| 仁德天下 | `politicsBonus` | `10` |
| 仁德天下 | `commandBonus` | `12` |
| 仁主守护 | `effectRate` | `0.35` |
| 仁主守护 | `triggerChance` | `0.60` |

GM schema 只能暴露以上四个当前有效字段。仁德天下没有触发概率；仁主守护没有人数上限、胜负条件或最终减损字段。

## 4. 旧逻辑清理与迁移

- 删除仁德天下旧战后复活执行器；旧 `effectRate`、`reviveRate`、`maxReviveCount`、`triggerChance` 迁移为当前内政 +10、统率 +12。
- 删除仁主守护旧固定返兵语义；旧 `lossReductionRate`、`maxReturnCount` 迁移为复活比例 35%、概率 60%。
- 清除 `maxAffectedRate`、`maxAffectedCount` 等通用人数上限字段，避免 GM 形成虚假限制。
- 当前新格式中 GM 已配置的属性、复活比例和概率必须保留，不被默认值覆盖。
- 历史战报可以继续按其已经保存的明细只读展示，但任何新战斗不得再生成旧仁德复活或仁主返还结果。

## 5. 实现边界

- 不修改稳定战斗核心公式；永久属性复用武将装配，战后复活复用统一 `AfterBattle` 事件。
- PVP、NPC、黄巾、轮回、扫荡和援军继续使用既有玩法适配与事务入口。
- 进攻返程、主城守军、援军记录和轮回权威军队都必须真实增加复活兵力，不能只改战报。
- `web` 与 `web-wlsg` 必须同步展示仁德天下的永久属性快照，以及仁主守护的真实阵亡、实际复活和最终存活。

## 6. 固定验收矩阵

1. 永久属性：基础内政 4、统率 3 时，最终内政 14、统率 15；对应生产/容量 28%、防御 30%，仁德天下不进入触发时间线。
2. 概率命中：100 名真实阵亡时复活 35 名，最终兵力、`revivedUnits` 和 `totalRevived` 一致。
3. 概率未命中：同一战斗强制概率 0 时复活 0，不产生仁主守护结果。
4. 多兵种与无上限：骑兵、步兵各真实阵亡 30000 时，各复活 10500，总复活 21000。
5. 方向：主动进攻、主城防守、正式援军和轮回攻防均可在战后判定，不限制胜负。
6. 资产与战报：真实阵亡、敌方经验、实际复活、最终存活、返程或库存和所有参战方战报逐项对账。
7. 幂等：重复解析同一战斗不得再次判定概率或重复发放复活兵力。

## 7. 持续修改清单

1. 每次同步修改后端、`web` 和 `web-wlsg`。
2. 检查默认配置、GM schema、旧配置迁移和当前自定义值保留。
3. 覆盖概率命中、未命中、攻防援军、多兵种、取整、无上限和重复结算。
4. 对账真实状态与新旧战报，前端只展示后端权威整数。
5. 运行 Go 全量与竞态测试、双前端测试和生产构建，再使用本机 Chrome 验收 GM 与两个玩家端。

## 8. 本轮验收结果

- Go 全量 `go test ./... -count=1` 通过。
- 刘备专项应用层与核心竞态测试 `-race -count=3` 通过。
- `web` 236 项测试与生产构建通过；`web-wlsg` 287 项测试与生产构建通过。
- Chrome 确认 GM 中仁德天下只显示内政 10、统率 12，仁主守护只显示复活比例 0.35、触发概率 0.6；旧返还和人数上限字段不存在。
- Chrome 确认 React 端准确展示永久被动与 60%/35% 战后复活说明，Vue 端可登录并进入刘备存档；GM、React、Vue 三端均无控制台告警或横向溢出。
