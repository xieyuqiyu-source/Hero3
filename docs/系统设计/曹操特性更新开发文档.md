# 曹操特性更新开发文档

最后更新：2026-07-21

## 1. 当前规则

### 1.1 魏武号令

- 曹操作为当前主将且留在本城时，每分钟自动获得 `300` 虎卫，即每秒平均 `5` 个。
- 不设每日、单次或累计产兵上限。
- 曹操出征或增援离城后立即停止产兵，离城时段不得在归城后追补。
- 后端依据 `resourceSettledAt`、服务端当前时间和 `generalTraitProgress` 进行权威经过时间结算；玩家离线期间不需要浏览器在线，重新登录或请求状态时一次补齐真实留城时段产量。
- `web` 与 `web-wlsg` 只根据后端权威基线进行每秒显示投影，不写回或修改玩家兵力；每 60 秒、窗口重新获得焦点和页面刷新时重新请求军事视图校准。
- 魏武号令不是战斗触发特性，不得出现在战报触发时间线。

### 1.2 魏武统御

- 曹操作为主城防守将领或援军将领时，在战斗前使其所率全军步兵防御和骑兵防御提升 `15%`。
- 加成按战斗引擎现有整数规则逐兵种计算，真实修改战斗输入并影响最终防御战力、兵损和存活。
- 主动进攻时完全无效：不修改攻击或防御，不产生特性结果，不进入标准战报时间线。
- 防守与增援生效时，战报必须记录触发武将、归属角色、设计防御比例，以及每个兵种实际增加的步防和骑防数值。

## 2. 权威边界

| 内容 | 权威来源 | 前端职责 |
| --- | --- | --- |
| 当前虎卫兵力 | 后端存档与军事视图 | 展示权威基线并做只读投影 |
| 产兵经过时间 | 后端 `serverTime`、`resourceSettledAt` | 使用响应到达后的经过时长推进显示 |
| 小数产兵进度 | 后端 `generalTraitProgress` | 只参与显示投影，不单独发兵 |
| 曹操是否离城 | 后端 `generalAssignments` | 离城时立即停止显示增长 |
| 战斗是否触发 | 后端特性分发和战斗结果 | 只展示 `detail.traits` 的真实时间线 |
| 实际防御变化 | 后端 `TraitOutcome.detail` | 按兵种展示，不重新计算 |

## 3. 自动化验收

- 后端：24 小时留城离线结算必须增加 `432000` 虎卫；高频结算与一次结算结果一致；无上限；离城期间为零增长。
- 主动进攻：基础战力保持不变，双方新旧战报均不存在魏武统御结果；拥有特性只能留在将领快照。
- 主城防守：多种兵力全部获得 `15%` 防御整数修正，最终防御战力和双方战报逐项一致。
- 援军防守：只强化曹操实际携带的援军，全军防御变化、真实兵损、驻防记录和攻守援三份战报一致。
- 双前端：24 小时投影无上限、离城停止、投影不修改权威对象；测试、类型检查和生产构建全部通过。

## 4. 发布要求

- 曹操规则修改必须同步后端、`web`、`web-wlsg` 和当前文档。
- 提交名称使用“曹操特性更新”。
- 推送 `main-core` 后确认 GitHub Actions 部署成功，再进行生产账号的留城、出征、防守、增援和战报实测。
