# <span style="color:#8b5cf6">物品系统开发备忘</span>

最后更新：2026-06-24
## <span style="color:#8b5cf6">当前定位</span>

物品系统已经作为独立模块接入，但目前只做最基础、最稳的第一版。

它和将领系统不是强绑定关系。现在玩家端只是暂时把背包显示在“军事 -> 将领”页右侧，因为第一批物品里包含将领经验包，而且将领页原本已有背包区域。

## <span style="color:#8b5cf6">已完成内容</span>

### 后端

- 新增物品配置文件：`go/config/items.json`
- 新增配置加载：`HERO3_ITEMS_PATH`，默认 `config/items.json`
- 新增物品配置结构：`ItemsConfig`、`ItemDefinition`、`ItemEffect`
- 玩家存档新增独立背包字段：`GameState.Inventory`
- 老存档读取时会自动补空背包，避免空字段问题
- 新增物品服务：`service_item.go`
- 新增物品配置校验：`items_config.go`
- 新增玩家使用接口：`POST /api/v1/items/use`
- 新增 GM 发放接口：`POST /api/v1/admin/items/grant`
- 邮件附件支持 `type: "item"`
- 领取邮件附件时会返回 `inventory`，前端背包可即时刷新
- 部署 workflow 已经会同步 `go/config/`，新增 `items.json` 会随部署上传

### 前端玩家端

- `GameState` 类型新增 `inventory`
- 启动配置 `bootstrap` 返回 `items`
- 玩家端 API 新增 `useItem`
- 信函领取附件后同步更新资源、城金、背包
- “军事 -> 将领”页右侧背包从占位格子改为真实物品列表
- 修复过一次 Hook 顺序问题：`GeneralPanel` 里的 `useMemo` 必须在提前返回之前调用

### GM 后台

- 运营工具里新增“发放物品”
- 信函附件下拉支持选择物品
- 信函收件人改成选择玩家，避免手填 playerId 出错
- 后台请求错误会显示后端返回的具体原因

## <span style="color:#8b5cf6">初始物品</span>

目前配置了 7 个基础物品：

- `general_exp_small`：将领小经验包，当前将领 +500 经验
- `general_exp_medium`：将领中经验包，当前将领 +2500 经验
- `general_exp_large`：将领大经验包，当前将领 +10000 经验
- `resource_pack_small`：小资源包，四资源各 +1000
- `resource_pack_medium`：中资源包，四资源各 +5000
- `resource_pack_large`：大资源包，四资源各 +20000
- `recruit_ticket_small`：小征募券，按阵营发基础步兵 50

资源包受仓库上限限制。

## <span style="color:#8b5cf6">当前获得途径</span>

目前还没有玩法自然掉落。

可通过两种 GM 方式获得：

1. 后台“运营工具 -> 玩家操作 -> 发放物品”
2. 后台“信函管理 -> 附件 -> 选择物品”，玩家领取附件后进入背包

## <span style="color:#8b5cf6">邮件领取规则</span>

现在信函附件不做过期限制。即使旧邮件里有 `expiresAt`，领取附件时也不会因为过期被拦。

不可领取的情况包括：

- 已领取
- 没有附件
- 玩家私信类型不能领取附件
- 附件数据异常
- 物品配置不存在

前端已做中文提示。

## <span style="color:#8b5cf6">重要提醒</span>

物品系统是独立模块，页面入口只是暂时借用将领页。

如果后续物品越来越多，建议再单独开“背包/物品”页面；如果仍以将领经验包、征募券、资源包为主，继续放在军事页也可以。
