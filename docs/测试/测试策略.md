# <span style="color:#14b8a6">Hero3 测试策略</span>

最后更新：2026-06-25
## <span style="color:#14b8a6">1. 测试目标</span>

测试不是只验证“能跑”，而是验证：

- 规则正确
- 数据不丢
- 权限不穿透
- 发版不破坏存档
- 回归不影响已有玩法

## <span style="color:#14b8a6">2. 测试分层</span>

### 单元测试

适合验证：

- 战斗计算
- 将领特性
- 资源结算
- 配置解析
- 权限判断

### 集成测试

适合验证：

- repository 与 MySQL 的一致性
- 事务回滚
- 信函领取
- 金币/城金互转
- 玩家状态读改写链路

### 接口测试

适合验证：

- 登录、注册、创建存档
- 主页面状态拉取
- 城建、征兵、战斗、信函、小游戏
- GM 配置修改

### 回归测试

适合验证：

- 资源结算不回退
- 战报不丢
- 已有接口响应结构不变
- 前端页面不因接口变动报错

## <span style="color:#14b8a6">3. 必测清单</span>

每次大改建议至少覆盖：

- 注册 / 登录 / 退出
- 创建 / 切换 / 删除存档
- 资源结算
- 建筑升级
- 征兵完成
- NPC 攻击 / 侦查
- 信函领取 / 删除 / 发送
- 金币 / 城金兑换
- GM 配置修改

## <span style="color:#14b8a6">4. 上线前门槛</span>

上线前至少满足：

- 后端单测通过
- 前端构建通过
- OpenAPI 打包通过
- 关键路径人工走查通过
- 数据库变更可回滚

## <span style="color:#14b8a6">5. 需要补的测试重点</span>

当前最值得优先补的测试：

- 并发下的城金和金币变更
- 玩家状态保存与局部更新的一致性
- 战斗结算结果的稳定性
- 管理后台配置变更后的前端读取一致性
