# <span style="color:#ea580c">Hero3 发布回滚规范</span>

最后更新：2026-06-25
文档状态：active

## <span style="color:#ea580c">1. 发布目标</span>

发布流程要保证：

- 业务可用
- 数据可恢复
- 新旧版本尽量兼容
- 事故发生时能快速回退

## <span style="color:#ea580c">2. 发布前检查</span>

- 后端测试通过。
- 前端构建通过。
- OpenAPI 已同步。
- 数据库迁移脚本已确认。
- 新增配置项已有默认值。
- 高危功能有回滚方案。

## <span style="color:#ea580c">3. 推荐发布顺序</span>

1. 先发布数据库兼容变更。
2. 再发布后端服务。
3. 再发布玩家端和 GM 后台。
4. 最后切换流量或环境配置。

## <span style="color:#ea580c">4. 回滚原则</span>

- 回滚优先恢复服务可用。
- 数据库变更必须可逆或兼容。
- 不能在同一发布里同时引入不可逆表结构和逻辑破坏。
- 回滚时先停新逻辑，再恢复旧版本。

## <span style="color:#ea580c">5. 兼容性要求</span>

- 接口新增字段必须允许旧客户端忽略。
- 接口删除字段前要有过渡期。
- 配置新增项必须有默认值。
- 存档结构升级要保证旧数据可读。

## <span style="color:#ea580c">6. 事故处理顺序</span>

1. 确认影响面。
2. 暂停继续发布。
3. 回滚最近变更。
4. 恢复数据。
5. 补修后再发布。
