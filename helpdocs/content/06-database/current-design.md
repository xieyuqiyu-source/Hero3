# 当前数据库设计

数据库方向是逐步从大 JSON 存档转向权威表。

## 当前原则

- `players.state_json` 是轻量兼容快照，不应该继续作为唯一权威来源。
- 新写入的 `state_json` 不再保存资源、建筑、资源田、兵力、征兵队列、武将、背包、Buff 等已有权威表承载的大字段。
- 玩家资源应读写资源权威表。
- 玩家建筑应读写建筑权威表。
- 玩家兵力应读写兵力权威表。
- 玩家武将应读写武将权威表。
- 玩家道具应读写背包权威表。
- Buff 和事件应有独立记录。

## 为什么会慢

如果每次操作都读写整个 `state_json`，会出现：

- JSON 大字段读写重。
- 每次都要序列化和反序列化。
- 局部更新也要写整包。
- 并发时冲突范围过大。

当前已经完成快照瘦身：资源变化、建筑升级、兵力变化等操作仍会维护权威表，但不会再把这些资产整包塞回 `players.state_json`。

## 当前性能改善

- 减少 `players.state_json` 写入体积。
- 避免每次升级建筑、征兵、发道具时刷新完整资产 JSON。
- 读取状态仍会从权威表组装完整 `GameState` 返回前端。
- 下一阶段可以继续把常见操作改成更细的局部事务，减少主表锁和 JSON 读取。

## 查询帮助

如果你想知道某个字段存在哪里，优先查：

- 数据库设计文档。
- Go storage 文件。
- 具体业务 service。
