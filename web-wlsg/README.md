# Hero3 武林三国风格玩家前端

`web-wlsg` 是与现有 `web/` 并存的新玩家前端，使用 Vue 3、TypeScript 和 Vite 开发。当前仅面向桌面浏览器，并适配 Hero3 现有后端接口。

生产环境固定发布到 `https://wlsg.ccoos.cn/`，构建产物安装在服务器 `/var/www/hero3/web-wlsg/`；它与 `https://hero3.ccoos.cn/` 的 React `web` 并行部署并共用 Hero3 API。

## 本地运行

```bash
pnpm install
pnpm dev
```

默认访问地址为 `http://localhost:5173`。生产构建使用：

```bash
pnpm build
```

自动测试使用：

```bash
pnpm test
```

## API 配置

复制 `.env.example` 为 `.env.local` 后，可以通过 `VITE_API_BASE_URL` 配置 Hero3 API 基础地址；默认值为同源 `/api/v1`。本地开发服务器会将 `/api` 代理到 `http://localhost:8080`，因此先启动现有 Hero3 后端即可联调。部署时建议保持同源反向代理，也可以填写完整的 API 地址。

新前端的账号、JWT 和当前玩家只保存在 `hero3_wlsg_*` 本地键中，不会读取、覆盖或删除现有 `web` 前端使用的 `hero3_token` 等会话键。密码只参与当次登录请求，不会写入本地存储。

## 当前功能范围

登录选档后调用 `GET /api/v1/game/state?playerId={playerId}`，展示当前存档的真实资源、容量、每小时产量、资源地块、建筑等级与状态、账号金币、城金、服务端时间、武将、直属军队、建造队列和未读数量。建筑悬浮详情使用 `GET /api/v1/game/bootstrap` 返回的 `balance.buildings`。

当前已接入 `POST /api/v1/city/buildings/upgrade` 执行单建筑建造/升级，成功后会即时更新资源、产量、建筑状态和倒计时。资源类型、兵种与建筑名称通过集中适配层转换；重复地块、额外地块和未知类型都保留真实数据并稳定展示。拆除、批量升级及尚无现有后端接口的操作仍不在当前范围内。

本城资源条右侧提供黄色高亮的“一键爆仓”，接入现有 `POST /api/v1/city/resources/fill-paid`。页面按“每补充 3000 资源消耗 1 城金”显示预计消耗，资源已满或城金不足时直接禁用；成功后以后端响应更新全部资源、城金和服务端时间，并阻止重复提交。

右侧“城池生产力”标题右边增加 Hero3 特色黄色“扩容”入口，用于仓库容量扩容，与顶部“一键爆仓”补满资源是两个独立能力。点击后使用原站深色铜边风格弹窗展示后端开放的 ×2、×4、×8、×16 四档容量倍率和 1、6、12、24 小时四档时长；组合价格实时读取 `GET /api/v1/city/boost/prices`，确认后调用 `POST /api/v1/city/capacity-boost`。成功响应会立即同步资源容量、当前倍率、到期时间、城金和服务端时间；同倍率续时，不同倍率重新计算。

军事“战争”页按官网当前“调兵遣将”页面复刻并接入现有真实接口：守城兵力、当前武将和武将任务占用来自 `GET /api/v1/military/view`；本城派出和他城来援逐批读取 `GET /api/v1/reinforcements/sent`、`GET /api/v1/reinforcements/received`，显示真实目标、将领、剩余兵力、状态及服务端倒计时。他城来援严格按增援记录逐批生成独立军队模块，不按来源或兵种聚合；每个模块与“本城所属的守城军队”使用相同的将领、阵营兵种图标、数量和总耗粮四行结构。攻击、掠夺、侦察、增援四个官方大按钮复用战争命令弹窗和世界地图返回的真实目标能力，分别调用现有 PVP/增援接口。武将存在非 `main` 的 PVP 或增援占用时，不再显示于守城将领和右侧“本城直属军队”；兵力使用后端已扣除出征数量的当前余额。现有后端未提供据点派遣、小队竞技派遣和被俘军队列表，这三块保留官方结构并明确标记差异；“战争动态”“战争保险”“将领”“科技”不在本次单页范围。

军事“战争”页视觉验收图：[`1280 × 800`](./docs/screenshots/war/1280x800.png)、[`1440 × 900`](./docs/screenshots/war/1440x900.png)。

右侧“城池建造”标题提供无边框黄色“一键完成”，每条建造队列右侧使用官方锤子图标。两种操作均不弹窗，悬浮时显示预计城金；单条直接调用 `POST /api/v1/city/buildings/instant`，一键完成按当前队列顺序依次调用同一现有接口，并逐次以后端结果更新建筑、资源和城金。

右侧当前城池栏可展开账号的真实存档列表，黑底金字并高亮当前存档。选择其他可用存档时复用现有会话 `selectPlayer` 流程，保存当前玩家 ID、清理旧玩家页面状态并加载新存档；后端未提供坐标字段，因此列表不会伪造官方坐标。

军事征兵页已按官方当前可见页面完成视觉复刻，包含步兵营、骑兵营、攻城武器、特殊兵种和机关阵分类。页面从启动配置读取当前阵营的真实兵种名称、属性、基础消耗与训练时间，并映射官方立绘：魏 `101–110`、蜀 `112–121`、吴 `123–132`；未知新增兵种不会被丢弃，会以安全占位图继续显示。

征兵功能已接入现有 `GET /api/v1/military/view`、`POST /api/v1/military/recruit` 和 `POST /api/v1/military/recruit/instant`。兵力、资源、城金和最多二十条征兵队列均以后端响应为唯一事实；队列倒计时基于服务端时间，结束后自动刷新军事视图完成结算。提交前显示的是启动配置中的基础估算，英雄、建筑等后端修正后的最终消耗和时间以后端结算为准。写操作具有数量校验、重复点击保护、错误保留输入和旧玩家响应隔离。

征兵页视觉验收图：[`1280 × 800`](./docs/screenshots/recruitment/1280x800.jpg)、[`1440 × 900`](./docs/screenshots/recruitment/1440x900.jpg)。

世界地图页已按官网当前地图完成复刻，并接入现有只读 `GET /api/v1/world-map/view`。页面以该响应为唯一事实来源，在官方二十行错位地块中展示真实玩家城池和黄巾营地；地图中心、世界边界、自身权威坐标、阵营、关系色、同账号存档归属、城池等级、目标状态以及攻击、掠夺、侦查、增援可用性均来自后端。同账号的其他存档使用自己的官方城池资源和专用“同号”标记，在小地图中使用独立青色点，悬浮与右侧详情会明确显示“我的其他存档”。八方向罗盘、坐标查询和返回本城会重新读取目标中心附近的真实视野，旧请求在切换存档或快速移动后不能覆盖新结果。

在官方默认 `100%` 比例之上增加了 `75% / 100% / 125% / 150%` 四档地图缩放，支持原版风格的 `− / ＋` 控件和地图内鼠标滚轮；缩放会重新计算可见行列并补足整个 `518 × 399` 视窗，不会只放大截图或在缩小时留下空白。右上角可折叠世界小地图使用同一只读接口的 `radius=100` 全图响应，绘制真实玩家、自己和三十个黄巾营地色点、当前视野框；点击色点或小地图坐标会读取并居中对应真实主地图视野。

地图二级导航已拆分为“地图、NPC、据点、副本、万象幻境”五项。NPC 页沿用官网排行列表框架，通过 `GET /api/v1/map/npc-cities` 读取当前已验证存档的真实城池，把小型、中型、大型、超大（后端 `golden`）四档 NPC 用不同颜色统一展示在一页，不按规模分页。页面保留后端返回数量、阵营、恢复特性、城池词条、生成时间和未知扩展值，不再混入演示数据。

NPC 手动刷新调用 `POST /api/v1/map/npc-cities/refresh`：后端在同一资产事务中扣除当前配置的账户金币（正式默认价格为 100）、重新生成 NPC 状态，余额不足时两者均不改变；响应返回实际 `cost` 和 `accountGold`，页面据此同步页头金币。点击任意 NPC 城池会打开与玩家地图一致的官方战争命令弹窗；攻击和掠夺调用 `POST /api/v1/map/npc-cities/attack`，侦查调用 `POST /api/v1/map/npc-cities/scout`。三种操作都即时结算，不创建行军队列或倒计时，并以后端局部响应更新兵力、资源、城金、武将和 NPC 状态，详细结果进入军情战报。据点页独立展示当前世界地图视野中的黄巾据点。

副本页接入现有“轮回绝境”模块，真实读取副本配置和当前挑战实例，展示七档难度、十八波进度、敌我随机加成、波次奖励、累计经验与最终奖励。每波默认选择当前可用主将随军，主将不可用时回退第一名空闲武将，并展示后端返回的真实攻击、防御属性与激活特性；玩家仍可改选其他空闲武将或主动选择不出动。携带将领参与进攻或防守后，后端按本波实际击杀计算并写入将领经验，页面显示该将领本波获得的真实经验及升级前后等级。玩家可按兵种调配任意数量的本城真实可用兵力并选择进攻或防守打法，副本不再设置出战总兵力上限；开始挑战、逐波结算、金币重置加成、最终领取和结束后退出分别调用 `/api/v1/dungeons/reincarnation` 下的现有接口。退出接口只接受已经结束的实例，幂等记录退出时间并保留历史实例、战报和已发放奖励；成功后页面回到层级选择。每次结算都以后端返回的兵力、武将经验、账户金币、服务端时间和挑战状态更新页面，不在前端推演战斗结果。

万象幻境页首期开放“六合博戏”和“天机轮转”。六合博戏支持大小、单双、豹子和指定点数，天机轮转使用三乘三服务端权威图案矩阵；两种玩法均从本城真实兵力中下注，最低投入和赔率以后端配置与结算为准。胜出奖励先进入 `minigame_records` 库存，页面可逐条兑换或按玩法一键兑换，并将兑换后的真实兵力回写公共城池状态。记录、豪赌、轮转、单条兑换和一键兑换全部调用现有 `/api/v1/minigame` 接口，切换存档时会隔离旧请求，所有写操作都有防重复提交与中文错误提示。

地图玩家城池的攻击、掠夺、侦查和增援已接入现有后端：攻击与掠夺调用 `POST /api/v1/pvp/attacks` 并分别提交 `attack`、`plunder` 模式；侦查调用 `POST /api/v1/pvp/scout`，由后端自动派出当前阵营全部侦察兵；增援调用 `POST /api/v1/reinforcements`。官方风格战争命令弹窗动态展示当前阵营全部兵种、真实可用数量、可用武将、目标名称和坐标，禁止运输与零口粮非战斗单位出征。提交具有整数与兵力范围校验、目标能力校验、重复点击保护、切换存档过期响应隔离；成功后以后端响应更新本城兵力、武将占用和服务端时间。

右侧菜单会通过 `GET /api/v1/pvp/marches`、`GET /api/v1/reinforcements/sent` 与 `GET /api/v1/reinforcements/received` 读取当前存档的活动行军。每支行军都使用单独一行展示，不再按类型合并计数；行内显示“攻击中 / 掠夺中 / 侦查中 / 增援中 / 被增援 / 返回中”、目标简称和该队列自己的服务器倒计时，并可逐条展开目标和兵力详情。本人仍在去程的 PVP 队伍和派出增援会显示加速与召回图标：PVP 分别调用 `POST /api/v1/pvp/marches/{marchId}/accelerate`、`POST /api/v1/pvp/marches/{marchId}/recall`，增援分别调用 `POST /api/v1/reinforcements/{reinforcementId}/accelerate`、`POST /api/v1/reinforcements/{reinforcementId}/recall`。加速使用官方锤子图标，每次消耗 10 城金、把剩余时间减半且每队最多两次；召回后以接口返回的返程时间刷新队列。请求期间统一防重复提交，成功后回写城金和服务端时间并重新读取三套权威列表；失败直接展示后端错误。“被增援”和“返回中”只读，不显示这两个操作。本人派出的增援和其他玩家仍在赶往本城的增援继续使用绿色高亮；已经驻防、已经完成或正在从本城返程的外部增援不显示为“被增援”。

右侧“军情”入口已按官网当前列表页完成复刻并接入 Hero3 现有战报接口，包含最新、攻击、防守、军事增援、侦查五个标签，不提供“饿死兵”。“最新”会按后端可见总数分批读取并只展示未读军情；打开并成功标记已读后立即移出“最新”，随后只在攻击、防守、军事增援或侦查对应分类中显示。各分类同样按后端总数分批读取、筛选已读记录后执行前端分页，避免后端没有读状态筛选参数时漏掉后续页数据。列表通过 `GET /api/v1/reports` 读取当前已校验存档的真实数据；攻击、防守和军事增援使用 `viewType` 筛选，侦查使用 `battleType=scout`。点击主题调用 `GET /api/v1/reports/{reportId}` 读取真实详情，未读记录再调用 `POST /api/v1/reports/{reportId}/read`；勾选删除经确认后串行调用现有单条 `POST /api/v1/reports/{reportId}/delete`，完成后重新读取权威列表。加载、空数据、失败重试、未知类型兜底、重复提交保护及切档过期响应隔离均已覆盖，不再混入演示数据。

军情页视觉验收图：[`1280 × 800`](./docs/screenshots/intelligence/1280x800.jpg)、[`1440 × 900`](./docs/screenshots/intelligence/1440x900.jpg)。

战报详情已按官网攻击战报和多份官方战报样本重构：使用 `detail.primarySide / secondarySide`、武将、十兵种出动与阵亡、资源收益、掉落、情报可见性、PVP 援军损耗和城墙快照组成完整动态战报。官职和军衔在正式字段接入前统一以 `-` 占位，身份区不展示后端快照战力；有出战武将时，左侧阵营图和右侧胜败图跨越中间两行，中间第一行分列显示将领名称、官职、军衔，第二行合并显示该将领本场获得经验，未携带将领或没有经验快照时显示 `-`。攻防双方和增援方分别读取将领自身的经验与等级变化快照，防守或增援视角不会再把进攻方经验显示为 `-`；后端还会按同一 `eventId` 为历史战报补齐其他视角已保存的经验。带图身份区下方另起整行显示武将自身的中文特性；真实触发结果读取 `detail.traits` 与兼容字段 `traitOutcomes`，按归属武将展示特性名称、触发阶段、效果/触发比例和逐兵种的攻防修正、追加损失、压制、俘虏、复活等详细数据。普通参战方没有武将时保留固定身份栏，并以 `-` 占位将领名称、官职、军衔和经验。NPC 战损达到 `25%` 时，防守兵种分别读取结算快照中的战前数量与实际阵亡；低于阈值继续隐藏守军情报，并把 `enemy_remaining_hidden` 等内部状态码转换为包含实际阈值的中文提示。后端当前没有战报生命值字段，页面不生成生命值占位。战损反馈暂以 `-` 占位；宝物掉落按物品 ID 优先、名称兜底合并同类数量，并以金黄色高亮逐项展示；其下增加 Hero3 特色“获得城金”行，读取 `rewards.cityGold`，缺失时显示 `0`。热门推荐整行已移除。参战一方、双方、多支增援和“未打穿不公开防守方”都使用同一组可扩展组件；历史旧战报没有 `detail` 时由兼容适配层生成最小官方结构。后端尚未返回的具体建筑降级结果不会在前端伪造。
