# web-wlsg Agent Rules

1. 本目录是 Hero3 的武林三国风格新玩家前端，使用 Vue 3、TypeScript 和 Vite 开发。
2. 本目录继承仓库根目录 `AGENTS.md` 和 `PROJECT_RULES.md`；发生冲突时，以根目录规则为准。
3. 当前长期开发只允许修改 `web-wlsg/`。未经用户明确授权，不修改 `go/`、`web/`、`admin/`、数据库、OpenAPI 或部署配置。
4. `go/` 现有后端视为固定接口提供方。新前端必须适配现有 API，不得以复刻 UI 为理由要求后端配合修改。
5. `web-wlsg/` 与现有 `web/` 并存；当前不替换、不删除现有玩家前端。
6. 第一阶段只面向桌面浏览器，采用固定宽度布局，高度还原用户打开的官方《武林三国》页面；移动端暂不纳入范围。
7. 后续开发只使用两份通用标准文档，不再为每个页面建立 V0.1、V0.2 等版本开发文档：
   - `docs/开发标准/官方页面复刻标准.md`
   - `docs/开发标准/现有后端API接入标准.md`
8. 用户要求“按页面复刻标准完成当前页面”时，读取并执行 `官方页面复刻标准.md`；浏览器当前实际可见页面是本次唯一页面范围。
9. 用户要求“按 API 接入标准接入当前页面”时，读取并执行 `现有后端API接入标准.md`；不得顺带开发其他页面。
10. 页面复刻和 API 接入分两次验收。页面复刻完成后必须停止，用户确认视觉通过后才能接入该页面 API；API 接入完成后再次停止并等待功能验收。
11. 官方站点、用户截图和用户确认结论属于视觉与交互参考，不代表 Hero3 必须实现官方站点全部业务能力。
12. 可以采集当前页面需要的官方公开图片、背景和界面资源；资源必须保存到 `web-wlsg/` 内并记录来源，不得直接热链。
13. 不得采集账号凭据、Cookie、聊天内容或其他玩家隐私数据。
14. Hero3 与官方《武林三国》存在差异时，视觉布局、信息组织、交互形式和前端扩展结构优先采用《武林三国》风格；真实数据、权限、结算和业务能力仍以 Hero3 现有后端接口为准。
15. 官方页面存在、但现有 Hero3 API 不支持的功能，不得伪造真实能力或绕过后端；记录差异并立即交由用户决定。
16. 列表型数据必须按接口动态渲染。不得假设资源、建筑、兵种、队列或其他同类数据只有固定数量；接口返回更多实例时使用通用组件和《武林三国》风格自然扩展。
17. 可以在 `web-wlsg/` 内建立 API 适配层、视图模型和前端路由，把现有后端数据转换为复刻界面所需结构。
18. 每次任务完成后必须执行生产构建、必要测试、浏览器控制台检查和目标桌面视口截图检查，然后停止并等待用户验收。
19. 用户未明确确认当前阶段通过前，不得自行开始下一页面或下一阶段。
20. 项目级对话记忆继续维护在仓库根目录 `memory/`，不在 `web-wlsg/` 内建立第二套聊天记忆。
