# 现有后端 API 接入标准

最后更新：2026-07-12

## 1. 使用方式

当前页面已经按照《官方页面复刻标准》完成并通过用户视觉验收后，用户发出类似指令：

> 按照现有后端 API 接入标准，为当前页面接入真实数据和操作。

AI 读取本文档，只为浏览器当前对应的已验收页面接入 Hero3 现有后端能力。一次不接入多个页面，也不顺带开发下一模块。

## 2. 核心边界

- 现有 `go/` 后端、数据库和 OpenAPI 保持不变。
- 只能使用已经存在的 Hero3 API、字段、权限和业务规则。
- 允许在 `web-wlsg/` 内新增 API 方法、TypeScript 类型、状态服务、适配层和视图模型。
- Hero3 与官方《武林三国》存在差异时，页面布局、信息组织、交互形式和扩展结构优先采用《武林三国》风格。
- 真实数据、权限、消耗、结算和操作结果始终以后端为准。
- 官方页面拥有但现有后端不支持的数据或操作不得伪造；必须记录差异并交由用户决定。

## 3. 接入前检查

开始编码前必须：

1. 确认当前页面已经通过视觉验收。
2. 列出当前页面展示的数据、查询动作和写操作。
3. 检查现有 API 客户端、OpenAPI、后端路由和原 `web` 前端的实际调用方式。
4. 建立“官方页面字段 → Hero3 接口字段 → 页面视图模型”映射。
5. 标记完全支持、需要前端适配和后端不支持的项目。
6. 如果完成核心操作必须修改后端，停止开发并向用户说明缺失能力。

不得凭接口名称猜测请求和响应结构，也不得复制原前端代码后跳过类型和边界审查。

## 4. 数据读取标准

- 复用现有登录、JWT、账号和当前玩家选择机制。
- `playerId` 必须来自当前账号已经校验的存档列表，不能由用户手填越权访问。
- 页面组件不直接散落网络请求；请求集中在 API 层和状态服务中。
- 使用 TypeScript 明确定义请求、响应和视图模型，不使用无约束 `any`。
- 加载真实数据后必须移除或隔离对应演示数据，不能真假数据混合展示。
- 数值 `0`、空数组、可选字段缺失和旧存档兼容数据必须正常处理。
- 页面至少具备加载、正常、空数据、失败、重试和未授权状态。
- 401 统一清除 `web-wlsg` 会话并返回登录流程。
- 退出、切换玩家或请求过期后，旧请求结果不得覆盖当前页面。

## 5. 动态扩展标准

- 不假设一种资源、建筑、兵种、武将、队列或记录只有固定数量。
- 同类型存在多个实例时逐条展示，不按类型错误去重。
- 接口返回数量超过官方参考页面默认容量时，按照《武林三国》风格自然扩展行列、分页或内容高度。
- 类型名称、图标、排序和页面文案使用集中映射。
- 接口未来返回新类型时使用通用组件和明确兜底，保留真实名称、数量和状态，不报错、不丢弃。
- 页面固定排序规则和项目根目录 `PROJECT_RULES.md` 中的稳定规则必须继续生效。

## 6. 写操作标准

当前页面存在建造、征兵、升级、购买、领取、发送等写操作时：

- 请求前验证必填输入、整数范围、数量和当前页面状态。
- 防止重复点击和并发提交；请求期间按钮进入明确加载或禁用状态。
- 不只依赖前端校验，最终错误和权限以后端响应为准。
- 成功后使用后端返回的局部状态更新页面；后端未返回足够状态时重新读取当前页面数据。
- 不在前端自行推断资源扣除、奖励或战斗结算结果。
- 失败时保留用户可修正的输入，并显示可读错误。
- 高风险或不可逆操作沿用官方风格确认交互，但不得改变后端实际规则。
- 后端暂未安全接入的开发或 GM 能力，不包装成普通玩家正式功能。

## 7. 时间与刷新标准

- 服务端时间是倒计时、队列和状态到期的基准。
- 前端可以根据服务端时间和本地经过时间连续展示倒计时，但不能改变真实结算结果。
- 自动刷新、轮询或实时更新只在当前页面确有需要时加入，并设置合理停止条件。
- 页面隐藏、退出登录、切换玩家或组件卸载后应停止无用定时器和请求。
- 手动刷新不能产生重复并发请求。

## 8. 安全与隔离标准

- 密码不得写入本地存储、日志、截图或错误信息。
- JWT 不得输出到控制台、页面、截图或文档。
- `web-wlsg` 本地存储继续使用 `hero3_wlsg_` 前缀，不删除原 `web` 的会话键。
- 不读取或提交与当前页面无关的隐私信息。
- 不通过修改请求参数访问其他账号的玩家数据。
- 不修改 `go/`、`web/`、`admin/`、OpenAPI、数据库或部署配置。

## 9. 测试标准

至少根据当前页面覆盖：

- 正常响应和真实字段映射。
- 零值、空数组和可选字段缺失。
- 同类型多个实例和超过默认数量的扩展数据。
- 未知类型的通用兜底。
- 网络失败、业务错误和 401。
- 重复提交保护和成功后的状态更新。
- 退出或切换玩家后的过期请求保护。
- 倒计时或轮询存在时的启动、更新和清理。

## 10. 验收标准

### 10.1 数据验收

- 页面展示的真实数据与接口响应一致。
- 所有字段转换有明确来源，不混入演示值或手工伪造值。
- 列表数量、同类多实例、排序和未知类型展示正确。
- 刷新页面后能够恢复会话、当前玩家和当前页面真实状态。

### 10.2 操作验收

- 当前页面范围内后端已经支持的操作可以完整执行。
- 请求中、成功、失败、资源不足、无权限和会话失效反馈清楚。
- 写操作结果以后端响应为准，资源和队列等关联状态同步正确。
- 重复点击不会产生非预期的重复请求或重复业务操作。

### 10.3 视觉验收

- 接入真实数据后不破坏已经通过的官方页面布局和视觉结构。
- 较长名称、大数值、多条记录和错误提示不会造成非预期溢出或遮挡。
- 在 `1280 × 800` 和 `1440 × 900` 下，`997px` 画布保持稳定。
- AI 提供两档视口的真实数据页面截图，截图不得暴露 JWT、密码或隐私数据。

### 10.4 工程验收

- `pnpm build` 通过，包含 TypeScript 类型检查。
- 当前页面必要自动测试全部通过。
- 浏览器控制台不存在由本次接入引入的警告和错误。
- 新增文件顶部和功能方法具有符合仓库规则的中文说明注释。
- 中文 README 按实际接口和当前功能更新。
- 不存在 `web-wlsg/` 作用域外的代码修改。

### 10.5 用户验收

- AI 完成开发、自检、自动测试和截图后必须停止。
- 用户使用真实账号完成当前页面的数据核对和主要操作流程。
- 用户未明确确认 API 接入通过前，不得开始下一个页面。
- 验收未通过时只修正当前页面 API 接入，不扩大任务范围。

## 11. 完成报告

AI 最终只需向用户报告：

- 当前页面实际接入的接口和操作。
- 页面字段与后端字段的关键映射。
- Hero3 与官方页面之间仍存在的差异。
- 构建、测试、控制台和两档视口检查结果。
- 需要用户使用真实账号验证的步骤。
- 当前已经停止并等待用户功能验收。
